## Research and owner boundaries

- [Unity Economy player balances](https://docs.unity.com/en-us/economy/sdk/player-balances)
  exposes asynchronous authenticated player balance operations and optional write locks
  for optimistic concurrency. That is service/backend authority, not this L2 snapshot API.
- [Unreal Data Assets](https://dev.epicgames.com/documentation/unreal-engine/data-assets-in-unreal-engine)
  store system data in asset instances; configuration can remain distinct from state.
- [Godot Resource](https://docs.godotengine.org/en/stable/classes/class_resource.html)
  describes serializable data containers, nesting and resource caching. Its engine/global
  resource lifecycle is not copied into this function-only library.

Inference for this architecture: L3 supplies currency IDs/display units/prices/caps;
L4 owns authorization, authoritative state, persistence/freshness/concurrency/atomic commit.
L2 owns only approved immutable wallet contracts here. L1 retains existing numerical
stat/resource/combat ownership; Currency Foundation calls no math Kernel. Registry adds
one optional currency->[] entry, zero imports and no runtime edges to siblings.
