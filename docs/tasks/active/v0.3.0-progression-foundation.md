# 6. PG01 — Progression Identity

## 6.1. Objective

Progression State phải liên kết trực tiếp với existing Entity ID.

Ví dụ:

```ts
const actor = createEntity({
  id: "player-1",
  kind: "player"
});

const progression = createProgressionState(actor, {
  level: 1,
  experience: 0
});
```

Expected:

```ts
{
  entityId: "player-1",
  level: 1,
  experience: 0
}
```

Tên public function là định hướng; agent có thể chọn naming phù hợp với Entity conventions.

## 6.2. Identity Rules

Bắt buộc:

- Progression dùng chính xác Entity ID.
- Không tạo Progression ID độc lập.
- Không tạo global progression counter.
- Không tạo UUID.
- Không sinh ID từ Clock/RNG.
- Không normalize Entity ID.
- Không đổi Entity ID trong Progression State.
- Không suy ra identity từ Entity kind hoặc Character name.

Một Progression State không được tự đại diện cho Entity khác khi có state transition sau này.

## 6.3. Entity Validation

Input Entity phải đáp ứng accepted EC01–EC03.

Reject:

- Missing ID.
- Blank ID.
- Invalid kind.
- Malformed Entity input.
- Inherited/accessor-based input bị EC03 từ chối.
- Invalid extra fields.

Không tạo một phiên bản Entity validator thứ hai.

Không silently chấp nhận malformed Entity chỉ vì TypeScript type đúng ở compile time.

## 6.4. Identity Association

Progression State gắn với Entity ID nhưng không sở hữu Entity Collection.

Không tự:

- Add Entity vào Collection.
- Kiểm tra global Entity Registry.
- Tạo Player hoặc Monster.
- Tạo Runtime Context.
- Đăng ký Character Controller.
- Sync Life/Resource State.

Một Entity có thể được tạo hợp lệ mà không có Progression State.

Một Progression State có thể tồn tại dưới dạng immutable snapshot dù Entity đã bị remove khỏi một independent collection.

Membership/lifecycle synchronization thuộc caller hoặc integration layer tương lai.

## 6.5. Uniqueness Scope

Hai independent Progression snapshots có thể cùng Entity ID nếu caller tạo chúng ở những thời điểm khác nhau.

Không tạo global rule ngăn việc này.

Ví dụ:

```text
Progression Snapshot A:
  entityId = player-1

Progression Snapshot B:
  entityId = player-1
```

Điều này không có nghĩa có hai Player identities.

Đó có thể là hai phiên bản dữ liệu độc lập.

Collection/authority để chọn snapshot mới nhất chưa thuộc v0.3.0.

# 7. PG02 — Progression Contract

## 7.1. Objective

Định nghĩa Progression State tối thiểu, typed, immutable và không phụ thuộc game-specific formulas.

Public type định hướng:

```ts
interface ProgressionState {
  readonly entityId: string;
  readonly level: number;
  readonly experience: number;
}
```

Không bắt buộc tên cuối cùng đúng như ví dụ, nhưng cần giữ các concepts:

- Entity association.
- Current recorded level.
- Current recorded experience value.

Không nhét toàn bộ Progression vào `Record<string, unknown>`.

## 7.2. State Input

Đề xuất:

```ts
interface ProgressionInitialState {
  readonly level: number;
  readonly experience: number;
}
```

Caller phải cung cấp explicit values.

Không tự chọn:

- Starting level.
- Starting EXP.
- Max level.
- EXP threshold.
- Character class.
- Skill points.
- Attribute points.

Không mặc định Player luôn bắt đầu level 1 nếu caller không yêu cầu.

## 7.3. Level Validation

Level phải là:

- JavaScript number.
- Positive safe integer.
- `level >= 1`.
- `level <= Number.MAX_SAFE_INTEGER`.

Reject:

- 0.
- Negative levels.
- Fractional levels.
- `NaN`.
- `Infinity`.
- `-Infinity`.
- Non-number values.
- Unsafe integers.

Không tự clamp level.

Không áp đặt game-specific maximum level.

**Level 1 là minimum structural contract, không có nghĩa mọi game phải bắt đầu ở Level 1.**

Một caller có thể tạo Level 30 nếu muốn.

Max-level policy thuộc PG07–PG10.

## 7.4. Experience Validation

Experience phải là:

- JavaScript number.
- Finite.
- Nonnegative.
- Được bảo toàn chính xác theo JavaScript number representation.

Reject:

- Negative EXP.
- `NaN`.
- `Infinity`.
- `-Infinity`.
- String EXP.
- Undefined hoặc malformed values.

Không tự:

- Làm tròn EXP.
- Ép EXP thành integer.
- Clamp theo level.
- Trừ EXP threshold.
- Tự tăng level.
- Tự reset EXP.

**Không bắt buộc EXP phải là integer tại Foundation.**

Một game có thể dùng fractional EXP; nếu cần quy tắc precision/integer-specific thì policy phải được thiết kế rõ trong các milestone sau.

## 7.5. EXP Semantics Boundary

Đây là boundary quan trọng để tránh khóa sớm architecture.

Tại v0.3.0, `experience` chỉ là **giá trị EXP đang được ghi nhận trong snapshot**.

Không được tự khẳng định nó là:

- Lifetime/cumulative EXP.
- EXP còn lại trong level hiện tại.
- EXP đã tiêu.
- EXP cần thiết cho level tiếp theo.

v0.3.1–v0.3.2 sẽ chốt contract tính EXP và advancement dựa trên actual game requirements.

Tại v0.3.0:

- Không so sánh EXP với threshold.
- Không validate quan hệ giữa EXP và level.
- Không tự chuyển đổi EXP representation.
- Không tạo EXP Curve interface chưa cần thiết.
- Không thêm hidden EXP mode.
- Không tự tính EXP progress percentage.

**Nếu các milestone sau cần phân biệt cumulative EXP và level-local EXP, phải đưa ra explicit contract/decision trong task tương ứng; không được âm thầm thay đổi cách diễn giải `experience` đã lưu.**

## 7.6. No Points/Ranks Yet

Không thêm sớm:

```ts
attributePoints
skillPoints
skillRanks
talents
prestige
ascension
```

Các fields đó có state/ownership semantics riêng.

PG11–PG18 sẽ thiết kế sau.

Không tạo placeholder fields với giá trị 0.

Không tạo optional generic bags cho những dữ liệu này.

## 7.7. Shared Actor Model

Cùng contract hỗ trợ:

- Player Level/EXP.
- Monster Level/EXP.
- NPC Progression khi game cần.
- Companion/Summon Progression.
- Các actor kinds khác.

Không hardcode actor kind.

Không ép mọi Monster/NPC phải có Progression.

Không dùng `kind` để suy ra starting level.

# 8. PG03 — Creation & Validation

## 8.1. Required Public Function

Cung cấp function tương đương:

```ts
createProgressionState(entity, initialState)
```

Ví dụ:

```ts
const actor = createEntity({
  id: "monster-1",
  kind: "monster"
});

const progression = createProgressionState(actor, {
  level: 12,
  experience: 450
});
```

Expected:

```ts
{
  entityId: "monster-1",
  level: 12,
  experience: 450
}
```

## 8.2. Creation Behavior

Bắt buộc:

1. Validate Entity bằng canonical Entity contract.
2. Validate initial Progression input.
3. Capture exact Entity ID.
4. Capture exact level/experience values.
5. Create immutable snapshot.
6. Không mutate Entity.
7. Không mutate input.
8. Không tự đọc Clock/RNG.
9. Không tự gọi Kernel.
10. Không tạo Progression Collection.
11. Không tự phát Event.
12. Không tự chạy Lifecycle hook.

Creation phải deterministic với cùng inputs.

## 8.3. Closed Input Shape

Initial Progression input chỉ chứa:

```text
level
experience
```

Không chấp nhận arbitrary fields.

Reject:

- Null/undefined.
- Arrays.
- Wrong input types.
- Missing level.
- Missing experience.
- Unknown extra fields.
- Symbol keys.
- Inherited fields thay cho own required data.
- Accessor-based required fields.
- Invalid numerical values.

Không tự gọi getters để đọc malformed inputs.

Không silently convert:

```text
"10" → 10
"100" → 100
```

Không tự thêm missing values bằng defaults.

## 8.4. Immutable Snapshot

Output phải:

- Là immutable object.
- Có readonly public contract.
- Detached khỏi caller-owned mutable inputs.
- Không expose writable internal references.
- Không chứa functions/callbacks.
- Không chứa Runtime/Messaging capability.
- Không chứa global state.

Ví dụ:

```ts
const input = {
  level: 5,
  experience: 200
};

const saved = createProgressionState(actor, input);

input.level = 99;
input.experience = 9999;
```

Expected:

```text
saved.level = 5
saved.experience = 200
```

Caller không thể sửa `saved` để làm thay đổi dữ liệu đã tạo.

## 8.5. Snapshot Independence

Tạo nhiều Progression snapshots độc lập.

Ví dụ:

```text
Player:
  level = 10
  experience = 1000

Monster:
  level = 5
  experience = 0
```

Expected:

- Player và Monster không chia sẻ state.
- Snapshot A không thay đổi khi caller tạo Snapshot B.
- Cùng Entity ID có thể có multiple independently created snapshots.
- Không global singleton.
- Không implicit version authority.

Không triển khai updates tại PG03.

## 8.6. Failure Atomicity

Khi input invalid:

- Không trả partial successful snapshot.
- Không mutate Entity.
- Không mutate input.
- Không sinh Entity/Progression ID.
- Không thay đổi Runtime.
- Không phát Event.
- Không cập nhật Entity Collection.
- Không ghi global state.

Không tạo transaction manager chỉ để bảo đảm điều này.

# 9. Foundation & Entity Integration

## 9.1. Module Registration

Progression phải tích hợp GF01–GF05 bằng actual module contracts.

Conceptual registration:

```ts
let registry = createModuleRegistry();

registry = registerModule(registry, {
  id: "entity",
  optional: true,
  dependencies: []
});

registry = registerModule(registry, {
  id: "progression",
  optional: true,
  dependencies: ["entity"]
});

const configuration = configureModules(registry, {
  enable: ["entity", "progression"]
});

const composition = composeModules(
  registry,
  configuration
);
```

Expected resolution order:

```text
entity
progression
```

Không tự thêm Entity vào configuration nếu caller chỉ enable Progression.

Không thay đổi GF04–GF05 dependency semantics.

## 9.2. Dependency Failure

Nếu caller enable Progression nhưng không enable Entity:

Expected:

- Existing Foundation resolver reject theo accepted contract.
- Không auto-enable Entity.
- Không tạo partial module composition.
- Không có alternate dependency resolver.

Nếu chỉ enable Entity:

- Progression không được selected.
- Entity hoạt động độc lập.
- Không tạo Progression State ngầm.

## 9.3. Entity Integration

Consumer có thể:

1. Tạo Entity.
2. Thêm Entity vào Entity Collection.
3. Tạo Progression State bằng Entity snapshot.
4. Đọc Progression State.
5. Tiếp tục dùng Entity functions như trước.

Expected:

- Entity Identity giữ nguyên.
- Entity Collection không tự lưu Progression.
- Entity kind không thay đổi.
- Không ảnh hưởng Attribute/Resource/Life State.
- Không có Progression-to-Entity synchronization tự động.

Không sửa EC01–EC18 APIs.

## 9.4. Runtime Integration Boundary

PG01–PG03 chưa cần:

- Progression lifecycle hooks.
- Command handlers.

- Execution Context.

Có thể dùng Foundation composition làm functional integration evidence.

# 12. Minimum Meaningful Scenarios

## Scenario A — Shared Progression Model

Tạo:

```ts
const player = createEntity({
  id: "player-1",
  kind: "player"
});

const monster = createEntity({
  id: "monster-1",
  kind: "monster"
});

const npc = createEntity({
  id: "npc-1",
  kind: "npc"
});
```

Tạo Progression:

```ts
const playerProgression = createProgressionState(player, {
  level: 10,
  experience: 1500
});

const monsterProgression = createProgressionState(monster, {
  level: 5,
  experience: 0
});

const npcProgression = createProgressionState(npc, {
  level: 1,
  experience: 0
});
```

Expected:

- Exact Entity IDs.
- Exact level/experience values.
- Một common public API.
- Không Player/Monster-specific logic.
- Không game-specific level formulas.

## Scenario B — Validation

Thử:

```text
level = 0
level = -1
level = 1.5
level = NaN
level = Infinity
level > MAX_SAFE_INTEGER

experience = -1
experience = NaN
experience = Infinity
experience = "100"
```

Expected:

- Invalid inputs reject TypeError.
- Không silently normalize.
- Không tạo partial snapshots.

Thêm malformed input shapes để bảo vệ closed contract.

## Scenario C — Immutability

```ts
const input = {
  level: 7,
  experience: 300
};

const progression = createProgressionState(player, input);

input.level = 100;
input.experience = 10000;
```

Expected:

```text
progression.level = 7
progression.experience = 300
```

Object.freeze/snapshot behavior phải đúng.

Không mutate Entity.

## Scenario D — Entity Integration

1. Create Entity Collection.
2. Add Player/Monster.
3. Get Player qua Entity Collection.
4. Create Progression State từ retrieved Entity.
5. Remove Player khỏi một new Collection snapshot.

Expected:

- Progression State giữ đúng Entity ID.
- Original collection không đổi.
- Detached Progression State không tự bị xóa.
- Entity/Progression responsibilities rõ ràng.

## Scenario E — Module Dependency

Register `entity` và `progression`.

Enable cả hai.

Expected:

```text
composition.moduleIds = ["entity", "progression"]
```

Enable Progression nhưng không enable Entity.

Expected: dependency resolution failure theo existing GF04 behavior.

Không có auto-enable.

## Scenario F — No Hidden Behavior

Tạo Progression State trong môi trường có instrumented Clock/RNG.

Expected:

- Clock không được gọi.
- RNG không được gọi.
- ID provider không được gọi.
- Không có Event Publication.
- Không có Level Transition.
- Không có EXP calculation.

Không nhất thiết phải tạo một test riêng cho từng absent behavior nếu source audit và một targeted fixture đã chứng minh đủ.
