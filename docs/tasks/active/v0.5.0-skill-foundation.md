# 1. Approved Architecture Decisions

Các quyết định kiến trúc dưới đây đã được Developer thống nhất. Coding Agent không được tự thay đổi.

## Decision A — Strict Layer Ownership

Hệ thống gồm bốn layers:

| Layer | Canonical Responsibility |
|---|---|
| L1 — RPG Core | Numerical calculations, numerical rules và calculation contracts |
| L2 — RPG Gameplay | Reusable gameplay state, validation, transitions, lifecycle và module orchestration contracts |
| L3 — Game Rules & Content | Skill definitions data, game-specific configuration, requirements, formulas selection và gameplay policies |
| L4 — Game Application | Runtime coordination, UI, controllers, scene, networking, persistence và actual execution orchestration |

**L2 không được tự tạo numerical implementation thay thế L1.**

**L2 không được hardcode game-specific configuration thuộc L3.**

**L2 không được triển khai application runtime thuộc L4.**

## Decision B — Skill Definition vs Skill Instance

Phải tách hai khái niệm:

**Skill Definition**

- Mô tả identity và contract của một loại kỹ năng.
- L2 sở hữu schema và structural validation.
- L3 sở hữu dữ liệu và cấu hình kỹ năng cụ thể.
- Có thể được nhiều actors sử dụng.
- Không mang trạng thái của một actor.
- Không chứa runtime lifecycle state.

**Skill Instance**

- Đại diện một instance của kỹ năng gắn với một Entity cụ thể.
- L2 Skill sở hữu instance identity và state contract.
- Tham chiếu Skill Definition bằng `skillId`.
- Không sao chép toàn bộ Skill Definition.
- Không sở hữu lại Entity State hoặc Skill Rank State.

Hai loại dữ liệu phải độc lập và immutable.

## Decision C — Skill Rank Belongs to Progression

Existing Progression owns:

- Skill Rank State.
- Skill Point State.
- Skill Rank Upgrades.
- Skill Upgrade Requirements.
- Skill Point Rewards.

Skill System không được:

- Tạo second Skill Rank State.
- Lưu rank trong Skill Instance.
- Tạo Rank Upgrade API.
- Tạo Skill Point Manager.
- Đồng bộ rank ngầm với Progression.

**Skill không phụ thuộc bắt buộc vào Progression.**

Các milestone cần rank về sau nhận thông tin thông qua canonical public contract hoặc explicit caller input.

Một Skill Instance có thể tồn tại mà không cần Progression module.

## Decision D — Skill Is Independent From Combat

Combat System đã được accepted và merge qua PR #9.

Skill không được:

- Thay thế Combat Action Admission.
- Thay thế Combat Target Validation.
- Tạo Damage Calculator.
- Tự thực hiện Attack Resolution.
- Tự cập nhật HP hoặc Death.
- Tạo Combat-specific state trùng lặp.

Skill chỉ tạo những gameplay contracts thực sự thuộc Skill.

Các milestone sau mới được bổ sung Skill Activation và Execution Request.

L4 sẽ điều phối việc gọi Combat khi cần.

## Decision E — No Premature Generic Engine

Không tạo:

- Universal Ability Engine.
- Generic Action Engine.
- Skill/Combat Unified Engine.
- Universal Requirement Engine.
- Shared Gameplay State Manager.
- Skill Catalog Runtime.
- Runtime Skill Registry.
- Skill Execution Pipeline.

Chỉ mở rộng khi có actual requirements và Developer approval.

1. Cung cấp Skill Definition identity.

```ts
const skill = createSkillDefinition({
  skillId: "fireball"

const entity = createEntity({
  id: "player-1",

  skill,
  entity,
```

```ts
{
  instanceId: "skill-instance-001",
  skillId: "fireball",
  entityId: "player-1"
}
```

Kết quả chỉ là immutable state snapshot.

Không ngụ ý:

- Skill được phép activation.

| Responsibility | Owner | Rule |
|---|---|---|
| Skill Definition Schema | L2 — Skill | Structural contract và validation |
| Skill Content/Data | L3 | Skill catalog, names, descriptions, classification, tuning |
| Skill Instance | L2 — Skill | Instance identity và immutable snapshot |
| Entity Identity | L2 — Entity | Canonical actor identity |
| Skill Rank | L2 — Progression | Single rank authority |

v0.5.0 chỉ triển khai các dòng thực sự liên quan Skill Definition và Skill Instance Foundation.

## 5.2. Allowed Dependencies

Static module registry:

```text

  dependencies: []

  dependencies: [entity]

  dependencies: [entity]

  dependencies: [entity]
```

Skill:

- Depends on Entity.
- Does not depend on Progression.
- Does not depend on Combat.
- Does not depend on Effect.
- Does not depend on Encounter.

Rationale:

Skill Instance gắn với canonical Entity, do đó dùng Entity identity contract.

Skill Rank là một optional integration concern, không phải structural prerequisite cho Skill Instance.

Combat là execution capability độc lập, không phải foundation dependency.

Không tạo circular dependencies.

## 5.3. Module Boundary

# 7. SK02 — Skill Definition Contract

## 7.1. Objective

Chuẩn hóa reusable identity contract của Skill Definition mà không đưa game-specific data vào L2.

## 7.2. Public Contract

Conceptual public type:

```ts
export interface SkillDefinition {
  readonly skillId: string;
}
```

Đây là minimum identity contract cho v0.5.0.

Không biến nó thành toàn bộ schema của dữ liệu Skill ở L3.

## 7.3. Skill Definition Identity

`skillId` phải:

- Là nonblank string.
- Giữ nguyên exact caller input.
- Case-sensitive.
- Không auto-trim.
- Không auto-normalize.
- Không ép UUID.
- Không ép numeric ID.
- Không generate.

Ví dụ hợp lệ:

```text
fireball
heal
basic-sword
skill_001
```

Không hardcode skill IDs.

## 7.4. Public Factory

```ts
createSkillDefinition(
  definition: SkillDefinition
): SkillDefinition
```

Factory:

1. Validate schema.
2. Validate identity.
3. Capture dữ liệu.
4. Trả immutable snapshot.

Không query catalog.

Không resolve Skill Rank.

Không kiểm tra actor sở hữu skill.

Không đọc bất kỳ gameplay state nào.

## 7.5. L3 Boundary

L3 có thể sở hữu rich configuration:

```ts
const gameSkillConfig = {
  skillId: "fireball",
  name: "Fireball",
  description: "Launch a fire projectile",
  // Additional L3-specific content and tuning
};
```

L3 chủ động chuyển identity cần thiết sang L2:

```ts
const definition = createSkillDefinition({
  skillId: gameSkillConfig.skillId
});
```

Không đưa `name`, `description` hoặc arbitrary content vào L2 Definition chỉ để phục vụ một game cụ thể.

Các milestone sau có thể định nghĩa những operation-specific policy contracts riêng, khi đã xác định rõ canonical owner và actual requirements.

Không tự mở rộng definition schema trong v0.5.0.

## 7.6. Closed Validation

Reject:

- Null.
- Array.
- Missing `skillId`.
- Empty/whitespace-only `skillId`.
- Non-string `skillId`.
- Unknown fields.
- Symbol keys.
- Accessor/getter fields.
- Inherited required fields.

Không invoke getters.

Không silently drop extra fields.

Malformed input phải throw `TypeError`.

Không trả partial definition.

## 7.7. Immutability

Returned definition:

- Detached from caller object.
- Frozen.
- Does not mutate original input.
- Deterministic.
- Does not contain hidden state.

Không tạo shared mutable definition registry.

# 8. SK03 — Skill Instance Identity

## 8.1. Objective

Phân biệt chính xác ba identity domains:

```text
Skill Definition:
  skillId

Skill Instance:
  instanceId

Entity:
  entityId
```

Không sử dụng một identity để thay thế identity khác.

## 8.2. Skill ID

`skillId` tham chiếu một validated Skill Definition.

Hai instances có thể cùng `skillId`.

Ví dụ:

```text
Player A:
  skillId = fireball

Player B:
  skillId = fireball
```

Không tạo hai Skill Definitions chỉ vì có hai actors.

## 8.3. Instance ID

`instanceId` là opaque identifier do caller cung cấp.

Requirements:

- Nonblank string.
- Exact value.
- No generated ID.
- No UUID requirement.
- No clock dependency.
- No random dependency.

Instance ID cho phép phân biệt các instance riêng biệt, kể cả khi cùng `skillId` và `entityId`.

Tuy nhiên:

**Global uniqueness và duplicate instance policy không được bảo đảm trong v0.5.0.**

Không tạo instance registry để enforce uniqueness.

Caller/runtime authority chịu trách nhiệm nếu cần uniqueness hoặc idempotency.

## 8.4. Entity ID

`entityId` lấy từ canonical Entity Snapshot.

Không để caller đồng thời truyền một `entityId` độc lập có thể mâu thuẫn với Entity Snapshot.

Không infer actor identity từ Skill ID.

Không infer Player/Monster từ Skill ID.

Không hardcode:

```text
player
monster
npc
pet
summon
```

thành những loại skill instance riêng.

Entity validation phải reuse canonical public Entity contract.

Không viết second Entity validator.

## 8.5. Structural Identity Is Not Ownership Authorization

Một structurally valid Skill Instance không chứng minh:

- Actor hiện nằm trong Entity Collection.
- Actor có quyền sử dụng skill.
- Actor đã học skill.
- Actor có rank phù hợp.
- Actor còn sống.
- Actor đang equipped skill.
- Skill đã được unlocked.

Những vấn đề này thuộc các bước availability/admission sau.

Không gọi kết quả tạo instance là `activated`, `admitted` hoặc `ready`.

# 9. SK04 — Skill Instance State

## 9.1. Objective

Tạo reusable immutable snapshot cho một Skill Instance gắn với Entity.

## 9.2. Public Contracts

Conceptual types:

```ts
export interface SkillInstanceInitialState {
  readonly instanceId: string;
}

export interface SkillInstanceState {
  readonly instanceId: string;
  readonly skillId: string;
  readonly entityId: string;
}
```

Không có rank, resource, cooldown hoặc execution data.

## 9.3. Public Factory

```ts
createSkillInstance(
  definition: SkillDefinition,
  entity: EntitySnapshot,
  initial: SkillInstanceInitialState
): SkillInstanceState
```

Factory phải:

1. Validate Definition contract.
2. Validate Entity bằng canonical public Entity contract.
3. Validate Instance ID.
4. Capture exact identities.
5. Trả detached frozen Skill Instance State.

Không lookup Entity Collection.

Không query Progression.

Không tạo resource state.

Không tạo cooldown state.

## 9.4. State Shape

Expected:

```ts
{
  instanceId: "skill-instance-001",
  skillId: "fireball",
  entityId: "player-1"
}
```

Chỉ chứa approved fields.

Không thêm:

```text
rank
skillPoints
learned
unlocked
enabled
equipped
charges
mana
health
resourceCost
cooldown
remainingCooldown
lastUsedAt
castTime
executionStatus
damage
target
effects
slots
```

Những thuộc tính này hoặc thuộc canonical owner khác, hoặc chưa có approved lifecycle semantics.

Không tạo placeholder state với default values.

## 9.5. State Ownership

Skill Instance State thuộc L2 Skill.

Nó chỉ giữ Skill-specific instance identity.

Entity attributes, resources và life vẫn thuộc Entity.

Skill ranks vẫn thuộc Progression.

Không copy Entity Snapshot hoặc Progression State vào instance.

Không giữ reference tới mutable game configuration.

## 9.6. Immutability & Isolation

Factory phải bảo đảm:

- Frozen returned state.
- Detached input ownership.
- No mutation of original arguments.
- No mutable aliases.
- Independent snapshots.
- Deterministic creation.
- No implicit providers.
- No shared global state.

Hai calls với equivalent inputs phải có equivalent semantic outputs.

Không yêu cầu cùng object identity.

## 9.7. Invalid Input Behavior

Malformed Definition, Entity hoặc Initial State:

- Throw `TypeError`.
- No partial state.
- No side effects.
- No stored instance.
- No event.
- No Core calculation.

Structurally valid nhưng chưa được actor học skill vẫn có thể tạo instance.

Availability semantics chưa triển khai.

## 9.8. No Lifecycle Transitions Yet

Không bổ sung:

```ts
activateSkill()
executeSkill()
learnSkill()
upgradeSkill()
spendSkillResource()
startSkillCooldown()
equipSkill()
```

Không tạo placeholder implementations cho tương lai.

# 10. SK05 — Foundation Verification

## 10.1. Objective

## 10.2. Required Acceptance Scenarios

### Scenario S01 — Definition Creation

```ts

  skillId: "fireball"
}
```

- Exact `skillId`.
- Frozen definition.
- No additional fields.
- No side effects.

```text
  fireball

  player-1

  monster-1

  skill-instance-001

  skill-instance-002
```

```text
  fireball
```

- Same `entityId`.

Reject:

```text

instanceId = null
missing instanceId
unknown definition fields
unknown instance initial fields
accessor-based identity
inherited identity
symbol keys
```

# 14. Stop Conditions

Nếu gặp một trong các tình huống sau, agent phải dừng phần việc liên quan và báo:

## 14.1. Canonical Ownership Conflict

Ví dụ:

- Cần Skill Rank nhưng Progression chưa cung cấp contract phù hợp.
- Cần sửa Entity validator ngoài scope.
- Muốn thêm gameplay state thuộc Combat.
- Muốn chuyển numerical responsibility từ Core sang Skill.

Không viết parallel implementation.

## 14.2. Breaking Public Contract

Nếu cần:

- Thay đổi existing Entity types.
- Thay đổi Progression types.
- Thay đổi Combat contracts.
- Thay đổi Foundation behavior.
- Thay đổi package export structure.
- Thay đổi module dependency architecture ngoài approved scope.

Phải yêu cầu Developer approval.

## 14.3. Missing Core Capability

Không tự:

- Sửa RPG Core.
- Import Core Legacy để bypass Kernel.
- Copy numerical formulas.
- Viết workaround calculator.

v0.5.0 hiện không yêu cầu numerical calculations.

## 14.4. Unexpected Repository State

Nếu:

- `main` khác expected accepted baseline với thay đổi không tương thích.
- Working tree chứa conflicting uncommitted modifications.
- Existing phase branch/PR chứa implementation không được phê duyệt.

Không overwrite hoặc bỏ qua.
