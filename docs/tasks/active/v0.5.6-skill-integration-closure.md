# 5. SK31 — End-to-End Skill Integration

## 5.1. Objective

Chứng minh Skill System hoạt động đầy đủ qua những canonical public modules đã triển khai.

Không tạo new production orchestration engine.

Integration được thực hiện trong **external consumer/test harness**, mô phỏng trách nhiệm L3/L4 bằng explicit inputs và local authoritative snapshots.

## 5.2. Required Integration Flow

```text
L3 — Skill Configuration
         ↓
L2 — Entity Creation
         ↓
L2 — Skill Definition
         ↓
L2 — Skill Instance
         ↓
L2 — Progression Rank (when required)
         ↓

         ↓

         ↓
```

# 6. SK32 — Deterministic Replay

## 6.1. Objective

Chứng minh cùng explicit inputs, clock và RNG sẽ tạo cùng semantic execution trace.

Không sử dụng real-time timing hoặc random source mặc định.

## 6.2. Controlled Dependencies

Sử dụng actual Foundation:

```ts
createExecutionContext()
readExecutionTime()
nextExecutionRandom()
```

Caller cung cấp:

```text
Clock sequence
RNG sequence
Explicit IDs
L3 configuration
Canonical state snapshots
```

Không dùng:

```text
Date.now()
Math.random()
setTimeout()
sleep()
```

để làm test deterministic.

## 6.3. Independent Replay Sessions

Tạo hai sessions độc lập:

```text
Session A:
  Fresh initial state
  Explicit clock
  Explicit RNG
  Explicit IDs

Session B:
  Fresh equivalent initial state
  Same clock values
  Same RNG values
  Same IDs
```

Expected:

- Same admission outcomes.
- Same resource candidates.
- Same cooldown timestamps.
- Same accepted execution requests.
- Same Combat numerical outcomes.
- Same loadout states.
- Same execution outcome reports.
- Same rejection reasons.

Không reuse mutable state từ Session A trong Session B.

## 6.4. Replay Timeline

Example Skill:

```text
Base cooldown:
  1000 ms

Effective CDR:
  0.25

Duration:
  750 ms

Initial mana:
  100

Mana cost:
  25
```

| Time | Action | Expected |
|---|---|---|
| 1000 | First activation | Accepted, mana 75, cooldown readyAt 1750 |
| 1250 | Reuse attempt | Rejected `cooldown_active`, mana remains 75 |
| 1750 | Reuse at exact boundary | Accepted, mana 50, new readyAt 2500 |
| 2000 | Early reuse | Rejected `cooldown_active`, mana remains 50 |
| 2500 | Ready evaluation | Ready, remaining 0 |

For this test, caller explicitly commits only accepted candidate states and carries them to the next step.

Use actual canonical Resource/Clock APIs.

No hidden time advance.

No double spending.

## 6.5. RNG Replay

Combat actual resolution phải dùng explicit RNG provider.

Expected:

- Same RNG inputs produce same hit/dodge/critical decisions.
- Same numerical inputs produce same Core outputs.
- Skill itself does not generate RNG.
- No additional RNG draw from Skill Activation.
- Combat RNG consumption follows canonical Combat behavior.

Không hardcode random results trong Skill.

Không tạo mock Combat calculator.

## 6.6. Rejection Determinism

Test các rejection paths:

```text
actor_dead
skill_not_owned
skill_rank_too_low
execution_preflight_rejected
resource_cost_rejected
cooldown_active
slot_occupied
instance_already_assigned
```

Expected:

- Exact stable reason.
- Correct stage precedence.
- No candidate leakage.
- No earlier snapshot mutation.

Không tự sửa previously approved priority.

## 6.7. Snapshot Isolation

Trong independent replay, xác minh:

- Skill Instance immutable.
- Loadout State immutable.
- Resource State immutable.
- Cooldown State immutable.
- Execution Request immutable.
- Execution Outcome immutable.

Không có shared mutable aliases giữa previous/next states.

## 6.8. Malformed Input Behavior

Không biến malformed contracts thành normal gameplay rejection.

Verify representative:

- Unknown fields.
- Accessor properties.
- Symbol keys.
- Inherited properties.
- Invalid IDs.
- Identity mismatch.
- Invalid numerical config.
- Invalid timestamps.
- Malformed nested loadout slots.

Expected:

```text

```

Không invoke malicious getters.

Không tạo partial results.

## 6.9. Replay Evidence

Report phải chứa literal expected trace và actual observed trace.

So sánh semantic values.

Không yêu cầu same object reference.

Không tạo expected trace bằng cách serializing implementation output rồi dùng nó làm oracle.
