```text

```

Bắt buộc chứng minh:

- Resource transition không tự đổi Life State.
- Defeat dùng đúng configured life resource.
- Resource State không bị mutate bởi Defeat Resolver.
- Transition result thể hiện chính xác before/after/outcome.
- Old Life State vẫn alive.

## 8.2. Explicit Recovery

```text

```

Expected:

- Resource State mới health = 10.
- Life State vẫn dead.
- Không có automatic revival.
- Không có implicit event publication.

## 8.3. Revival

Consumer gọi EC16 với recovered Resource State.

Expected:

```text
before = dead
after = alive
outcome = revived
```

Kiểm chứng:

- Same Entity ID.
- Valid life policy.
- Resource current > minimum.
- Old dead Life State không đổi.
- Không có automatic refill.
- Không tự thay đổi Entity kind hoặc Collection membership.

## 8.4. Invalid & Repeated Transitions

Minimal negative evidence:

- Defeat khi actor đã dead không tạo outcome `defeated` lần thứ hai.
- Revival khi actor đã alive không tạo outcome `revived` giả.
- Revival tại resource minimum bị reject theo accepted contract.
- Mismatched Life/Resource Entity IDs bị reject.
- Missing configured life resource bị reject.
- Invalid operations không thay đổi các snapshots cũ.

# 10. Entity Isolation & Snapshot Consistency

## 10.1. Cross-Entity Isolation

Tạo ít nhất hai actors có attributes/resources/life states khác nhau.

Ví dụ:

```text
player-1:
  strength = 10
  health = 20
  life = alive

monster-1:
  strength = 5
  health = 8
  life = alive
```

Thực hiện resource transition và defeat chỉ cho Player.

Expected:

- Monster Attributes không đổi.
- Monster Resource State không đổi.
- Monster Life State vẫn alive.
- Monster Entity Snapshot không đổi.
- Entity Collection membership không đổi.

Không có global state leakage.

## 10.2. Snapshot Independence

Bắt buộc kiểm chứng những state versions sau:

```text
Entity Collection A
Entity Collection B

Attribute State A
Attribute State B

Stat Snapshot A
Stat Snapshot B

Resource State A
Resource State B

Life State A
Life State B
```

Expected:

- Old snapshots không đổi.
- New snapshots thể hiện đúng operation.
- Không expose writable backing maps.
- Không mutate caller input objects.
- Không freeze caller-owned configuration/modifier objects ngoài contract.

Không yêu cầu tất cả snapshots nằm trong một combined Entity State object.

## 10.3. Identity Consistency

Các liên kết state phải dựa trên exact Entity ID.

Kiểm chứng:

- Attribute/Resource/Life State đúng owner.
- Mismatched IDs reject ở các operation yêu cầu consistency.
- Collection membership không tự ràng buộc lifecycle của detached states.
- Remove Entity khỏi collection không âm thầm xóa các independent snapshots.
- Không sử dụng object-reference identity thay cho logical ID.

Không thêm global relationship registry.

## 10.4. No Implicit State Synchronization

Chứng minh absence of automatic coupling:

- Attribute change không tự tính Stats.
- Stat change không tự normalize Resources.
- Resource current chạm minimum không tự đổi Life State.
- Resource recovery không tự revive.
- Life transition không tự publish event.
- Entity removal không tự xóa những independent state snapshots.

Đây là các architectural invariants bắt buộc.

# 11. Deterministic End-to-End Execution

## 11.1. Reproducibility Contract

Chạy hai independent sessions:

```text
Session A:
  Entity inputs = X
  Collection operations = C
  Attribute/Stat rules = S
  Resource policies = R
  Life policies = L
  Explicit calls = O

Session B:
  Same X, C, S, R, L, O
```

Expected:

```text
Semantic Trace A == Semantic Trace B
```

Mỗi session phải tạo state/context/probes riêng.

Không dùng chung mutable provider/callback state rồi tuyên bố isolation.

## 11.2. Required Trace Fields

Trace nên chứa đủ những observations có ý nghĩa:

```text
module-selected: entity
entity-created: player-1
entity-created: monster-1
collection-order: player-1, monster-1
attribute: strength=10
stat: maximum-life=25
resource: health=20
resource-decrease: 20→0
life-before-defeat: alive
life-defeat: alive→dead
event: entity-defeated/listener-A
event: entity-defeated/listener-B
resource-recovery: 0→10
life-before-revival: dead
life-revival: dead→alive
event: entity-revived
```

Đây là conceptual trace.

Nếu dùng numerical input khác hợp lệ, phải có literal expected oracle tương ứng.

Không sinh expected trace bằng chính function đang test rồi so sánh với bản copy.

## 11.3. Explicit Expected Oracle

Test phải:

1. Định nghĩa expected values độc lập.
2. Chạy Session A.
3. So sánh A với expected.
4. Chạy Session B.
5. So sánh B với expected.
6. So sánh A và B.

Không chỉ so sánh A với B.

Không dùng object identity hoặc volatile CI timestamps để kiểm tra determinism.

## 11.4. Failure Boundaries

Kiểm chứng một meaningful failure path:

- Invalid entity/resource association.
- Invalid resource transition/revival.
- Hoặc GF12 listener failure.

Expected:

- Không có partial successful state.
- Error/result diagnostics đúng contract.
- Completed callbacks được ghi nhận đúng nếu thuộc Messaging.
- Immutable previous snapshots không thay đổi.
- Không có retry/rollback ngầm.

Không cần thêm failure matrix lớn vì các checkpoint EC01–EC17 đã có targeted tests.
