# 5. PG11 — Attribute Point Pool

## 5.1. Objective

Cung cấp typed immutable Attribute Point State cho mỗi Entity.

State cần phản ánh:

- Entity ID.
- Điểm chưa sử dụng.
- Điểm đã sử dụng.
- Mốc level cuối cùng đã xử lý reward.

Public contract định hướng:

```ts id="uwumqq"
interface EntityAttributePointState {
  readonly entityId: string;
  readonly unspentPoints: number;
  readonly spentPoints: number;
  readonly rewardedThroughLevel: number;
}
```

Không bắt buộc exact naming, nhưng phải giữ rõ semantic ownership.

## 5.2. Point State Semantics

`unspentPoints`:

Số điểm hiện còn có thể phân bổ.

`spentPoints`:

Tổng số điểm đã sử dụng và được ghi nhận trong Point State.

`rewardedThroughLevel`:

Mốc level cuối cùng đã được xử lý bởi level-reward workflow, bao gồm những level có reward bằng 0.

**Không hiểu `rewardedThroughLevel` là current character level trong mọi trường hợp.**

Một actor có thể đã lên cấp nhưng chưa nhận point rewards tương ứng.

## 5.3. Canonical Point State

Không tạo:

```text id="9qlg2c"
AttributePointsStore
CharacterPointBalance
LevelRewardPoints
```

thành những authoritative stores song song.

PG11 State là nguồn duy nhất của Attribute Point Pool trong scope này.

Không nhét points vào `ProgressionState` bằng breaking change.

Giữ PG02:

```ts id="6pmpnu"
{
  entityId,
  level,
  experience
}
```

Không thay đổi accepted EXP/Level APIs.

## 5.4. Initialization

Cung cấp function tương đương:

```ts id="hxja05"
createAttributePointState(
  progressionState,
  {
    unspentPoints: 0,
    spentPoints: 0,
    rewardedThroughLevel: 1
  }
);
```

Expected:

```ts id="x7bp9o"
{
  entityId: "player-1",
  unspentPoints: 0,
  spentPoints: 0,
  rewardedThroughLevel: 1
}
```

Tất cả initial values phải được caller cung cấp tường minh.

Không tự:

- Cấp starting points.
- Suy diễn reward từ current level.
- Gán spent = 0 khi caller không cung cấp.
- Reset điểm thuộc tính.
- Phân bổ điểm mặc định.

## 5.5. Point Validation

`unspentPoints` và `spentPoints` phải là:

- Nonnegative safe integers.
- Finite numbers.
- Không phải strings.
- Không phải fractional numbers.

Tổng `unspentPoints + spentPoints` phải nằm trong safe-integer range.

`rewardedThroughLevel` phải:

- Positive safe integer.
- Không lớn hơn current Progression level khi tạo Point State.
- Không tự mặc định current level.
- Không được silently normalize.

Điều này cho phép caller khởi tạo trạng thái đang chờ xử lý level rewards một cách tường minh.

Không tự giả định đã nhận reward của mọi level trước current.

## 5.6. Closed State Contract

Reject:

- Missing fields.
- Extra fields.
- Invalid Entity ID.
- Negative points.
- Fractional points.
- Unsafe integers.
- Invalid rewardedThroughLevel.
- Inherited/accessor-based required values.
- Malformed structural inputs.

Không gọi getters ngầm.

Không silent coercion.

## 5.7. Immutable State

Point State phải:

- Frozen/immutable.
- Detached khỏi caller inputs.
- Không chứa mutable backing maps.
- Không chứa callbacks.
- Không chứa live Progression State references.
- Không có global store.
- Không có hidden Level-up listener.

Tạo nhiều snapshots cho cùng Entity ID là hợp lệ.

Không có global latest-state authority.

## 5.8. Point Balance Inspection

Có thể đọc trực tiếp:

```ts id="4bfe9j"
pointState.unspentPoints
pointState.spentPoints
```

Không cần thêm redundant getters.

Nếu cần total recorded points:

```text id="b6cz5d"
total = unspentPoints + spentPoints
```

Đây là derived bookkeeping value; không tạo một mutable total field riêng gây nguy cơ mất đồng bộ.

# 6. PG12 — Attribute Point Rewards

## 6.1. Objective

Cấp điểm thuộc tính dựa trên actual successful Level Advancement.

Không cấp điểm từ một yêu cầu level-up chưa thực hiện.

Không tự tạo điểm khi EXP tăng.

## 6.2. Reward Input

Sử dụng actual Level Advancement Result từ PG09.

Expected required evidence:

- Entity ID.
- Before Level.
- After Level.
- `advancedLevels`.
- `levelsGained`.

Ví dụ:

```text id="jlleje"
Level Advancement:

beforeLevel = 1
afterLevel = 3
advancedLevels = [2, 3]
levelsGained = 2
```

Reward calculation chỉ xét những levels đã tăng thành công.

Không xét target level chưa đạt.

Không suy diễn reward từ EXP delta.

## 6.3. Reward Configuration

Caller cung cấp điểm thưởng theo level.

Conceptual policy:

```ts id="teez0z"
interface AttributePointRewardPolicy {
  readonly pointsByLevel: Readonly<Record<number, number>>;
}
```

Ví dụ:

```ts id="qx13df"
{
  pointsByLevel: {
    2: 5,
    3: 5
  }
}
```

Expected:

```text id="ai11kr"
Level 2 reward = 5
Level 3 reward = 5

Total Granted = 10
```

Đây là data configuration, không phải game-specific formula.

Không hardcode:

- +5 điểm mỗi cấp.
- +1 điểm mỗi cấp.
- Điểm thưởng tăng theo cấp.
- Reward multiplier theo class.
- Reward dựa trên monster/player kind.

## 6.4. Reward Policy Validation

Bắt buộc:

- Mỗi completed level phải có explicit reward entry.
- Reward amount là nonnegative safe integer.
- Reward bằng 0 hợp lệ.
- Không âm.
- Không fractional.
- Không nonfinite.
- Không có duplicate/malformed level keys.
- Không accessor-based entries.
- Không inherited entries.
- Không unknown fields ngoài contract.

Với một advancement result có completed levels `[2,3]`, policy phải cung cấp đúng rewards cho những levels này.

Không âm thầm coi missing reward là 0.

Không tự gọi reward callback để lấy số điểm.

Không tạo EXP/Level reward formula engine.

## 6.5. Required Public Function

Cung cấp function tương đương:

```ts id="2j47xi"
grantAttributePointRewards(
  pointState,
  levelAdvancementResult,
  rewardPolicy
);
```

Expected result:

```ts id="5sa87b"
{
  state: nextPointState,
  transition: {
    entityId: "player-1",
    rewardedLevels: [2, 3],
    pointsGranted: 10,
    beforeUnspent: 0,
    afterUnspent: 10
  }
}
```

Có thể mở rộng transition diagnostics khi cần, nhưng không tạo generic reward transaction system.

## 6.6. Reward Eligibility

Bắt buộc xác nhận:

1. Level Advancement Result hợp lệ.
2. Point State hợp lệ.
3. Entity IDs khớp.
4. Completed levels là contiguous sequence.
5. `levelsGained` nhất quán với `advancedLevels`.
6. Before/after Level đúng actual result.
7. `rewardedThroughLevel` bằng `beforeLevel` của advancement receipt đang được áp dụng.
8. Reward policy đủ entries.
9. Point totals không overflow.

Nếu bất kỳ điều kiện nào sai, reject trước khi tạo successful reward result.

Không tự dựng một Level Advancement Result giả từ `ProgressionState.level`.

## 6.7. Partial Advancement

Ví dụ:

```text id="pq5obg"
Requested:
  Level 1 → 4

Actual:
  Level 1 → 2 → 3

Level 4 blocked.
```

PG12 chỉ cấp điểm cho:

```text id="2gjqwm"
[2, 3]
```

Không cấp điểm cho Level 4.

Không cần caller phải đạt requested target mới được nhận rewards cho successful prefix.

## 6.8. Duplicate Reward Protection

Đây là critical invariant.

Khi Point State đã xử lý reward tới Level 3:

```text id="6a5nqe"
rewardedThroughLevel = 3
```

Không được nhận lại reward receipt:

```text id="qdlxdf"
beforeLevel = 1
advancedLevels = [2, 3]
```

Expected:

- Reject stale/replayed reward application.
- Không tăng unspentPoints.
- Không tạo successful grant result.
- Không mutate Point State.

Bảo vệ dựa trên **reward cursor của updated immutable Point State**.

Không tạo global reward ledger hoặc event sourcing.

## 6.9. Replay Protection Limit

Vì L2 sử dụng immutable snapshots:

- Caller phải truyền updated Point State cho operation kế tiếp.
- Nếu caller cố ý sử dụng lại một stale snapshot từ trước khi grant, L2 không thể bảo đảm global exactly-once delivery.

**Không claim global idempotency hoặc transactional exactly-once guarantees.**

Không tạo database/lock/singleton để giả lập.

Chống replay trong phạm vi một correctly threaded state history là đủ cho v0.3.3.

## 6.10. Zero Reward

Ví dụ:

```text id="thmkxq"
advancedLevels = [2]
pointsByLevel[2] = 0
```

Expected:

- Không thêm điểm.
- `rewardedThroughLevel` vẫn được cập nhật tới 2.
- Không cấp lại reward Level 2 sau này.
- Result ghi pointsGranted = 0.

Không xem zero reward là missing policy.

## 6.11. No-Level Advancement

Nếu PG09 result có:

```text id="w8uiqt"
levelsGained = 0
advancedLevels = []
```

Expected:

- Không cấp điểm.
- Point State không đổi về mặt semantic.
- Không tự cập nhật reward cursor tới requested target.
- Không tạo reward event.

Không thưởng điểm khi level-up bị chặn.

## 6.12. Failure Atomicity

Nếu reward input invalid:

- Không cấp partial points.
- Không tăng reward cursor.
- Không mutate Point State.
- Không mutate Progression State.
- Không phát event.
- Không ghi global ledger.

Validation của toàn reward input phải hoàn tất trước khi công bố snapshot mới.

# 7. PG13 — Attribute Point Allocation

## 7.1. Objective

Cho phép consumer tiêu Attribute Points để thay đổi Base Attribute của Entity.

Progression sở hữu point spending.

Entity sở hữu Attribute State.

**Không tạo Attribute State Calculator trong Progression.**

## 7.2. Required Public Function

Cung cấp function tương đương:

```ts id="fku9zi"
allocateAttributePoints(
  pointState,
  attributeState,
  {
    attributeId: "strength",
    pointCost: 3,
    newBaseValue: 23
  }
);
```

Trong đó:

- `attributeId`: thuộc tính muốn nâng.
- `pointCost`: số điểm cần tiêu.
- `newBaseValue`: Base Attribute value sau nâng cấp, do caller xác định theo game rules.

Không mặc định 1 point = 1 attribute unit.

## 7.3. Why Caller Supplies New Base Value?

Các trò chơi có thể có:

```text id="qa23u2"
Game A:
  1 point → +1 Strength

Game B:
  1 point → +2 Strength

Game C:
  3 points → +1 Strength

Game D:
  Cost increases at higher attributes
```

Progression không nên hardcode bất kỳ conversion formula nào.

Caller/L3 chịu trách nhiệm tính và validate economic policy của game.

L2 kiểm tra:

- Point Cost hợp lệ.
- Đủ điểm.
- Attribute tồn tại.
- Target Base Value hợp lệ.
- Entity IDs khớp.
- Result nhất quán với accepted public state contracts.

Không tự suy ra newBaseValue từ pointCost.

## 7.4. Allocation Input

Conceptual type:

```ts id="dkpsf3"
interface AttributePointAllocation {
  readonly attributeId: string;
  readonly pointCost: number;
  readonly newBaseValue: number;
}
```

Input phải là closed own-data record.

Không chấp nhận hidden callbacks hoặc arbitrary metadata.

## 7.5. Point Spending Rules

`pointCost` phải là:

- Positive safe integer.
- Không bằng 0.
- Không âm.
- Không fractional.
- Không nonfinite.
- Không vượt unspentPoints.

Nếu thiếu điểm, reject bằng `TypeError` hoặc repository-consistent explicit rejected result; **không trừ một phần rồi vẫn nâng thuộc tính**.

Một allocation operation phải apply toàn bộ approved cost hoặc không apply.

Không tự vay điểm.

Không cho negative point balance.

## 7.6. Entity Identity Consistency

Bắt buộc:

```text id="yeojc9"
PointState.entityId
==
AttributeState.entityId
```

Nếu mismatch:

- Reject.
- Không tiêu điểm.
- Không thay đổi Attribute State.
- Không tìm actor khác qua global collection.

Không tự tạo Entity mới.

Không tự thay đổi Entity kind.

## 7.7. Attribute Existence

`attributeId` phải tồn tại trong Entity Attribute State.

Không tự thêm attribute key mới.

Không tự chuyển attribute ID thành lowercase.

Không tự map:

```text id="bbl5dw"
strength → str
vitality → hp
```

Caller cung cấp chính xác attribute key.

Dùng canonical Entity APIs:

- `getEntityBaseAttributes()`
- `setEntityBaseAttribute()`

Không copy một implementation `setBaseAttribute()` riêng trong Progression.

## 7.8. Target Base Value Validation

`newBaseValue` phải:

- Finite number.
- Lớn hơn current Base Attribute value.
- Không phải NaN/Infinity.
- Không silent coercion.
- Không tự round.

Không tự đặt maximum attribute value.

Nếu game có cap hoặc class-specific restrictions, caller phải validate trước khi yêu cầu allocation.

Không tự clamp newBaseValue.

Không tính Effective Stats trong allocation.

## 7.9. Allocation Result

Public result tương đương:

```ts id="bma7kn"
{
  points: nextPointState,
  attributes: nextAttributeState,
  transition: {
    entityId: "player-1",
    attributeId: "strength",
    beforeValue: 20,
    afterValue: 23,
    pointsSpent: 3,
    beforeUnspent: 5,
    afterUnspent: 2
  }
}
```

Bắt buộc:

- Point State mới immutable.
- Attribute State mới immutable.
- Old Point State không đổi.
- Old Attribute State không đổi.
- Entity ID không đổi.
- `spentPoints` tăng đúng pointCost.
- `unspentPoints` giảm đúng pointCost.
- `rewardedThroughLevel` không đổi.

Không tự tạo second Attribute State authority.

## 7.10. Atomic Result Construction

Allocation thay đổi hai independent snapshots.

Operation phải:

1. Validate Point State.
2. Validate Attribute State.
3. Validate matching Entity IDs.
4. Validate pointCost.
5. Validate available balance.
6. Validate attribute existence.
7. Validate newBaseValue.
8. Sử dụng canonical Entity `setEntityBaseAttribute()`.
9. Tạo immutable next Point State.
10. Trả combined result.

Nếu một bước fail, không trả partial successful result.

Không mutate original states.

**Đây là một atomic immutable result construction, không phải database transaction.**

Caller chịu trách nhiệm lưu/apply cả hai resulting snapshots cùng nhau ở tầng sở hữu state thực tế.

Không claim distributed hoặc persistent transaction guarantees.

## 7.11. No Automatic Stats Recalculation

Sau allocation:

```text id="bwfvtf"
Strength 20 → 23
```

Progression không tự gọi `calculateEntityStats()`.

Consumer có thể:

```text id="4x7bmb"
Attribute Allocation Result
        │
        ▼
New Attribute State
        │
        ▼
Explicit EC08/EC09 Stats Calculation
        │
        ▼
New Effective Stat Snapshot
```

Không tự update:

- Maximum Health.
- Current HP/MP.
- Combat Damage.
- Skill Damage.
- Equipment Modifier.
- Life State.

Không tạo hidden stat recalculation pipeline.
