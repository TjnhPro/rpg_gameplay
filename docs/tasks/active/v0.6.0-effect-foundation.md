# 1. Objective

Triển khai **Effect Foundation**, tạo nền tảng Effect độc lập với Skill để các hệ thống gameplay về sau có thể sử dụng chung.

Effect có thể bắt nguồn từ:

- Skill.
- Item.
- Equipment.
- Consumable.
- Environment.
- System-generated gameplay events.
- Các hệ thống khác trong tương lai.

v0.6.0 chỉ thiết lập **identity, structural contracts, immutable snapshots và module boundary**.

| ID | Feature | Responsibility |
|---|---|---|
| EF01 | Effect Identity | Effect ID, Effect Instance ID, source/target identity |
| EF02 | Effect Definition | Reusable Effect Definition, independent of Skill |
| EF03 | Effect Instance | Structural instance identity, source/target association |
| EF04 | Immutable Effect State | Per-Entity structural state, validation, isolation |
| EF05 | Effect Module Integration | Optional module registry, public exports, installed verification |

## Expected Outcome

Consumer có thể:

1. Tạo Effect Definition.
2. Tạo Effect Instance identity liên kết với một Entity.
3. Phân biệt Effect Instance với Effect Definition.
4. Phân biệt các nguồn gây Effect khác nhau.
5. Tạo immutable Effect State cho Entity.
6. Validate Effect State.
7. Sử dụng Effect module độc lập với Skill/Progression/Combat.
8. Sử dụng các contracts qua installed package.

Ví dụ:

```text
Effect:
  poison

Source:
  kind = entity
  sourceId = player-1
  sourceKey = player-1/skill-instance-001

Target:
  monster-1

Effect Instance:
  effect-instance-001
```

Effect Instance này là **structural identity**, chưa phải Effect đã được apply hoặc đang active.

v0.6.0 không xử lý application, duration, stacking, expiration, stat modification, DoT hoặc HoT.

# 6. EF01 — Effect Identity

## 6.1. Objective

Thiết kế identity conventions độc lập với Skill và cho phép nhiều nguồn phát sinh Effect.

Bắt buộc phân biệt:

```text
effectId
effectInstanceId
sourceId
sourceKey
targetEntityId
```

Không sử dụng Skill ID làm Effect ID.

## 6.2. Effect ID

`effectId`:

- Opaque nonblank string.
- Caller-supplied.
- Case-sensitive.
- Không generate.
- Không normalize.
- Không ép UUID.
- Không hardcode danh sách effect.

Examples:

```text
poison
burning
frost-shield
regeneration
__proto__
```

`effectId` chỉ định loại Effect.

Không phải một active instance.

## 6.3. Effect Instance ID

`effectInstanceId`:

- Opaque nonblank string.
- Caller-supplied.
- Exact identity.
- Không generate.
- Không ép UUID.
- Không cần chứa Effect ID.
- Không cần chứa Skill ID.
- Không tạo global ID authority.

Một Effect Definition có thể có nhiều Effect Instance references.

Global uniqueness và replayable ID allocation do L4 chịu trách nhiệm.

Within a supplied per-Entity Effect State, duplicate `effectInstanceId` phải bị reject.

## 6.4. Effect Source Reference

Proposed contract:

```ts
export type EffectSourceReference =
  | {
      readonly kind: "entity";
      readonly sourceId: string;
      readonly sourceKey: string;
    }
  | {
      readonly kind: "system";
      readonly sourceId: string;
      readonly sourceKey: string;
    };
```

**Entity source**

```ts
{
  kind: "entity",
  sourceId: "player-1",
  sourceKey: "player-1/skill-instance-001"
}
```

**Equipment source**

```ts
{
  kind: "entity",
  sourceId: "player-1",
  sourceKey: "equipment/sword-instance-001"
}
```

**Environment source**

```ts
{
  kind: "system",
  sourceId: "swamp-zone",
  sourceKey: "swamp-zone/poison-area-001"
}
```

Equipment ở đây chỉ là example source identity.

Không triển khai Equipment module.

## 6.5. Source Key Requirements

`sourceKey`:

- Explicit stable nonblank string.
- Provided by L4.
- Exact/case-sensitive.
- Không tự derive từ Skill ID.
- Không random generate.
- Không implicit combine với target ID.
- Không mutate sau khi instance được tạo.

L4 phải bảo đảm sourceKey phân biệt các nguồn vật lý/logical cần hoạt động độc lập.

D06 đã chốt future grouping:

```text
targetEntityId + effectId + sourceKey
```

**EF01 chỉ bảo tồn identity fields.**

Không implement grouping ở v0.6.0.

## 6.6. Entity Source Validation Boundary

Với:

```text
kind = entity
```

Foundation kiểm tra structural source ID.

Không tự kiểm tra:

- Source Entity đã tồn tại trong collection chưa.
- Source alive/dead.
- Skill ownership.
- Equipment ownership.
- Target relation.
- Application permission.

Những điều kiện đó thuộc EF06–EF10 và caller-owned policies.

Không tạo source lookup registry.

Proposed:

```ts
export interface EffectInstanceState {
  readonly effectInstanceId: string;
  readonly effectId: string;
  readonly source: EffectSourceReference;
```

**Đây là structural instance identity.**

Không chứng minh:

## 8.4. Public Factory

```ts

  definition: EffectDefinition,
  target: EntitySnapshot,
```

Implementation sequence:

1. Validate Effect Definition qua canonical Effect factory.
2. Validate Target Entity qua `createEntity()`.
3. Validate Effect Instance Initial State.
4. Validate Source Reference.
5. Capture exact identities.
6. Return immutable detached snapshot.

Không đọc Foundation Clock.

Không gọi `nextExecutionId()`.

Không tự thêm vào Effect State.

Không invoke Effect Application.

# 9. EF04 — Immutable Effect State

## 9.1. Objective

Cung cấp immutable structural state envelope theo Entity.

Foundation chỉ tạo và validate snapshots.

**Chưa có lifecycle transitions hoặc active-effect authority.**

## 9.2. Proposed Contract

```ts
export interface EffectState {
  readonly entityId: string;
  readonly instances: readonly EffectInstanceState[];
}
```

`entityId` là target Entity sở hữu state association.

`instances` chứa Effect Instance structural records.

State không chứa:

```text
HP
Mana
Attributes
Stats
Skill Rank
Cooldown
Combat Context
```

Không duplicate other module state.

## 9.3. Public State Factory

```ts
export function createEffectState(
  target: EntitySnapshot
): EffectState;
```

Expected:

```ts
{
  entityId: "monster-1",
  instances: []
}
```

Requirements:

- Validate target bằng `createEntity()`.
- Empty immutable array.
- Frozen state.
- No default Effect Instances.
- No implicit apply.
- No registry lookup.

## 9.4. Public Structural Validator

```ts
export function validateEffectState(
  state: EffectState
): EffectState;
```

Required:

- Validate exact top-level fields.
- Validate Entity ID shape.
- Validate dense instance array.
- Validate every nested Effect Instance record.
- Validate every nested Source Reference.
- Reject duplicate effectInstanceId within same state.
- Require every instance.targetEntityId matches state.entityId.
- Preserve original order.
- Return detached frozen snapshot.

Không mutate input.

## 9.5. Structural Validity Is Not Active Validity

Ví dụ:

```text
EffectState:
  monster-1

Instance:
  effect-instance-001
  effectId = poison
  target = monster-1
```

Nếu externally supplied state chứa record trên, validator chỉ xác nhận structural correctness.

Nó không chứng minh effect đã được apply.

Không tạo giả lifetime/active flag.

Không tạo hidden authorization token.

Ở v0.6.1, canonical Effect Application sẽ trở thành đường tạo accepted candidate states. Ở v0.6.2, approved duration/lifecycle contracts sẽ bổ sung runtime lifecycle representation trong cùng Effect owner.

Không triển khai các transitions đó trong Foundation.

## 9.6. Instance Identity Uniqueness

Within state:

```text
effect-instance-001
effect-instance-002
```

Valid.

Within state:

```text
effect-instance-001
effect-instance-001
```

Expected:

```text
TypeError
```

Không silently deduplicate.

Across independent states, caller chịu trách nhiệm global uniqueness nếu ứng dụng yêu cầu.

Không tạo global instance registry.

## 9.7. Multiple Same-Effect References

Valid structurally:

```text
effectId = poison
effectInstanceId = instance-a

effectId = poison
effectInstanceId = instance-b
```

Không reject chỉ vì trùng effectId.

Stack grouping/admission thuộc EF16–EF20.

## 9.8. Ordering

Preserve caller-supplied instance order.

Không tự sort theo:

```text
effectId
sourceKey
instanceId
```

Không xác định expiry order tại Foundation.

Lifecycle/expiration ordering được áp dụng khi EF11–EF15 được triển khai.

## 9.9. No Active State Store

Không tạo:

```text
Map<EntityId, ActiveEffects>
global EffectStore
EffectStateManager
EffectSession
```

EffectState là immutable value object.

L4 giữ authoritative current snapshot.

Không có hidden mutation.

# 11. Contract Validation Rules

## 11.1. Closed Records

All public Effect records phải fail-closed.

Reject:

- Missing fields.
- Unknown fields.
- Symbol fields.
- Accessor/getter fields.
- Inherited required fields.
- Invalid nested records.
- Invalid discriminants.
- Invalid array structures.

Không silently normalize.

Không ignore unknown fields.

## 11.2. Identity Validation

IDs phải là nonblank strings.

Preserve exactly:

```text
"poison"
"Poison"
" poison "
"__proto__"
"constructor"
```

Nếu string chỉ chứa whitespace:

```text
TypeError
```

Không trim ID và lưu giá trị mới.

Không lowercase.

Không ép enum.

## 11.3. Source Reference Validation

Required exact fields:

```text
kind
sourceId
sourceKey
```

Allowed kinds:

```text
entity
system
```

Reject:

```text
skill
item
equipment
environment
unknown
```

ở trường `kind`.

Các nguồn như Item/Equipment được biểu diễn qua approved `entity` hoặc `system` source reference cùng stable sourceKey, không cần mở thêm type variants.

## 11.4. No Getter Invocation

Validation phải sử dụng safe own-data inspection.

Không access untrusted getters.

Ví dụ:

```ts
const invalid = {
  get effectId() {
    throw new Error("getter invoked");
  }
};
```

Expected:

```text
TypeError
Getter invocation count = 0
```

Không chỉ dựa trên TypeScript readonly types.

## 11.5. No Prototype Pollution

IDs như:

```text
__proto__
constructor
toString
```

phải được bảo toàn và không gây mutation của object prototypes.

Không dùng unsafe plain-object map writes làm registry.

## 11.6. No Hidden Runtime

Effect Foundation không gọi:

```text
Date.now()
performance.now()
Math.random()
setTimeout()
setInterval()
```

Không gọi Foundation Clock/ID provider vì mọi IDs đều do caller cung cấp.

Không tạo hidden mutable state.
