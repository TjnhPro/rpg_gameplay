## 3. Public API delta — exactly three functions and three types

Preserve all `ItemDefinitionReference`, `ItemDefinition`, `ItemInstanceState`, `ItemPropertyValue`, metadata, `createItemInstance`, `validateItemInstance`, etc. exactly as accepted. **Do not add fields** to them.

```ts
export type ItemPropertyReadResult =
  | { readonly found: false }
  | { readonly found: true; readonly value: ItemPropertyValue };

export interface ItemPropertyOperationAdmission {
  readonly eligible: boolean;
}

export type ItemPropertyOperationResult =
  | {
      readonly status: 'accepted';
      readonly reason: 'none';
      readonly candidate: ItemInstanceState;
    }
  | {
      readonly status: 'rejected';
      readonly reason: 'ineligible';
      readonly candidate: null;
    };

export function getItemInstanceProperty(
  definition: ItemDefinition,
  instance: ItemInstanceState,
  key: string,
): ItemPropertyReadResult;

export function setItemInstanceProperty(
  definition: ItemDefinition,
  instance: ItemInstanceState,
  key: string,
  value: ItemPropertyValue,
  admission: ItemPropertyOperationAdmission,
): ItemPropertyOperationResult;

export function replaceItemInstanceProperties(
  definition: ItemDefinition,
  instance: ItemInstanceState,
  properties: Readonly<Record<string, ItemPropertyValue>>,
  admission: ItemPropertyOperationAdmission,
): ItemPropertyOperationResult;
```

**Exact proposed additive API:** 3 runtime functions, 3 exported types. No generic `mutateItem`, `patch`, `delete`, callback interpreter, public schema validator, catalogue accessor or `ItemStateV2`.

### 3.1. Shared validation and determinism

- Validate entire complete **Definition**, then entire **Instance** against that Definition before every operation. Reuse exact canonical v0.9.0 validators; no alternative private validation code that weakens type/closed-record/prototype rules.
- Property **keys** are exact **any strings**, unlike nonblank **identity IDs**; valid even if `''`, Unicode, `constructor`, `__proto__`, numeric-looking keys or whitespace. No normalization/trim/reserved words; wrong-type key is `TypeError` and never coerced.
- Validate a supplied `value` or **complete replacement map** with exactly v0.9.0's recursive safe-value rules (finite numbers; dense arrays; own plain-data records; no cycles/accessors/symbols/prototype pollution). Malformed inputs fail with `TypeError`, not ordinary rejection.
- Admission must be a **closed own-data** `{eligible:boolean}` record, no missing field, extra/symbol field, accessor, custom prototype, default true, coercion or callback. L2 does **not** check L3 item rules itself.
- **Validate all structural inputs before evaluating admission**: `{eligible:false}` must NOT mask an invalid nested object or mismatched `definitionId`.
- Every successful read/result/candidate is detached and deeply frozen; neither caller inputs nor current item state are modified/frozen. No hidden time, RNG, ID provider, state cache, event emission, persistence, numerical game calculation or asynchronous executor.
- Candidate always has **exactly** the accepted three instance fields `instanceId`, `definitionId`, `properties`, with IDs unchanged.

### 3.2. IT06: exact own-instance property inspection

1. Query **instance.properties only**, never merge/inherit `definition.properties`.
2. Use **own property presence**, not truthiness or prototype lookup.
3. Missing key → exact `{found:false}` with **no value own key**; present key (including `null`, `0`, `false`, `''`) → `{found:true,value:<exact copied value>}`.
4. For nested data, deep capture/freeze output: no writable value alias to caller or source snapshot. Preserve original property key spelling, nested ordering and safe dangerous keys.
5. Read is not calculated/effective stats, inventory lookup, catalog lookup or Item usage.

### 3.3. IT07: single-key set candidate

1. Closed structurally valid admission `eligible:false` → exact `{status:'rejected',reason:'ineligible',candidate:null}`; *no change*.
2. `eligible:true` → new full candidate: same instance/definition IDs; all existing properties preserved except the exact named key replaced; if absent, create a safe own-data key. `__proto__` must not mutate prototype.
3. Set-to-null creates a **present null key** rather than delete. An unchanged value may still return a fresh accepted candidate; no hidden equality/revision event.
4. Revalidate final candidate with canonical `validateItemInstance` and return deeply frozen detached new value, fresh outcome; no partial output on error.
5. Insertion of a new key preserves deterministic ECMAScript own-key enumeration rules (do not invent lexicographic sort); changing existing key must not reorder unrelated keys.

### 3.4. IT07: whole-map replace candidate

1. `properties` is an **entire replacement dictionary**, not a patch; validate deeply before admission.
2. `eligible:true` → candidate has exactly the supplied own property keys and deep values; old omitted keys are **removed**, not set to `undefined` and not inherited back from definition.
3. Empty `{}` is valid and clears all **instance** properties, not definition metadata.
4. `eligible:false` → same rejection, no candidate and no state changes.
5. IDs and definition remain exactly unchanged; outputs are safe from dangerous keys and caller post-call mutation.

### 3.5. IT08: outcome and semantic boundary

- **Structural error:** `TypeError`, no accepted/rejected result; definition/instance/value/admission is malformed.
- **Policy rejection:** only valid structure + `eligible:false` → `rejected/ineligible/candidate:null`.
- **Accepted:** `accepted/none/candidate:<full ItemInstanceState>`; outcome/candidate are closed detached deeply frozen records; strict NodeNext `status` discriminant narrows `candidate`.
- `eligible:true` is **caller assertion**, not proof of ownership, property schema, item eligibility, transaction authority or current state. The L4 consumer must re-evaluate against authoritative state before commit.
- L3 owns permitted keys, type/range semantics, durability formulas, allowed rarity/affix transitions. An opaque number is **data**, not L2 arithmetic.

## 4. Literal examples and acceptance requirements

  createItemDefinitionReference({definitionId:'fixture-item'}),
  {categoryId:null, tagIds:[], rarityId:null, properties:{shared:'definition-only'}},

const before = createItemInstance(def, {
  instanceId:'fixture-instance', properties:{charge:1, note:null},

// literal expected: {found:true,value:null}

// candidate properties exactly {charge:2,note:null}; before still {charge:1,note:null}
const afterReplace = replaceItemInstanceProperties(def,before,{fresh:[true,0]},{eligible:true});
// candidate properties exactly {fresh:[true,0]}
const denied = setItemInstanceProperty(def,before,'charge',4,{eligible:false});
// literal expected: {status:'rejected',reason:'ineligible',candidate:null}
