# 1. Objective

Mở rộng Progression module để hỗ trợ quản lý cấp kỹ năng (Skill Rank), điểm kỹ năng (Skill Points) và điều kiện nâng cấp kỹ năng.

Triển khai:

| ID | Feature | Responsibility |
|---|---|---|
| PG14 | Skill Rank State | Quản lý rank theo Entity ID và Skill ID |
| PG15 | Skill Point Pool | Quản lý điểm kỹ năng chưa sử dụng, đã sử dụng và level reward cursor |
| PG16 | Skill Upgrade Requirements | Đánh giá level, prerequisites, max rank, point cost và caller eligibility |
| PG17 | Skill Rank Upgrade | Nâng một rank và tiêu điểm bằng explicit immutable operation |
| PG18 | Skill Progression Result | Trả kết quả, diagnostics, outcome và rejection reason |

**Kết quả mong muốn:**

Consumer có thể:

1. Tạo Skill Rank State cho một Entity.
2. Tạo Skill Point State.
3. Nhận Skill Points từ Level Advancement theo reward configuration.
4. Kiểm tra một kỹ năng có đủ điều kiện nâng rank không.
5. Nâng kỹ năng từ Rank 0 lên Rank 1, hoặc từ Rank N lên Rank N+1.
6. Tiêu Skill Points tương ứng.
7. Nhận immutable next states và transition result.
8. Không tự thực thi kỹ năng hoặc tạo gameplay effects.

**Skill Progression chỉ quản lý ownership và advancement của skill ranks.**

Không triển khai Skill Engine.

# 5. PG14 — Skill Rank State

## 5.1. Objective

Cung cấp typed immutable Skill Rank State cho mỗi Entity.

Conceptual contract:

```ts
interface EntitySkillRankState {
  readonly entityId: string;
  readonly ranks: Readonly<Record<string, number>>;
}
```

Trong đó:

- `entityId` là Entity ID hiện có.
- Key trong `ranks` là Skill ID.
- Value là current rank của skill đó.

## 5.2. Rank Semantics

Quy ước:

```text
Rank 0 = Registered but not learned
Rank 1 = Learned at rank 1
Rank N = Learned at rank N
```

Rank phải là:

- Nonnegative safe integer.
- Không fractional.
- Không nonfinite.
- Không negative.

Không tự chọn max rank trong Skill Rank State.

Max rank thuộc caller-supplied Skill Upgrade Requirements.

Không tự suy ra rank từ:

- Character Level.
- Skill EXP.
- Skill Definition.
- Equipment.
- Character Class.

## 5.3. Skill IDs

Skill ID:

- Nonblank string.
- Caller-defined.
- Exact string identity.
- Không normalize/trim.
- Không bắt buộc numeric ID.
- Không bắt buộc kebab-case.
- Không tự thêm prefix.

Hỗ trợ các ID như:

```text
sword_basic
fireball
skill-1001
123
```

`123` ở đây là string key.

Không ép Skill ID thành number.

Không hardcode JX1/D4-specific IDs.

## 5.4. Initial Rank State

Public function tương đương:

```ts
createSkillRankState(entity, {
  sword_basic: 0,
  fireball: 2
});
```

Expected:

```ts
{
  entityId: "player-1",
  ranks: {
    sword_basic: 0,
    fireball: 2
  }
}
```

Empty rank map hợp lệ.

Không tự cấp kỹ năng mặc định.

Không tự unlock skill khi tạo Entity.

Không tự tạo Skill Definition.

## 5.5. Registered Skill Key Set

Ở v0.3.4, Skill Rank State chứa danh sách Skill IDs do caller cung cấp tại initialization.

Đối với upgrade:

- Skill ID phải tồn tại trong rank map.
- Không auto-create missing skill.
- Không auto-register skill vào rank map.
- Không tự xóa skill.
- Không tự rename skill.

Rank 0 khác với skill chưa có trong state.

Ví dụ:

```text
fireball: 0
```

là skill được register nhưng chưa học.

Trong khi:

```text
fireball: missing
```

là unknown skill trong snapshot đó.

Upgrade unknown skill phải reject.

Không coi missing skill là rank 0 ngầm.

Việc thay đổi catalog/schema sau này cần explicit migration/rebind contract riêng nếu có nhu cầu.

## 5.6. Special Keys

Skill IDs như:

```text
__proto__
constructor
toString
```

không được gây prototype pollution hoặc sai lookup.

Không dùng inherited properties để xác định skill tồn tại.

Dùng own-key semantics.

Không mutate prototypes.

## 5.7. Rank Inspection

Cung cấp public function tương đương:

```ts
getSkillRank(rankState, skillId)
```

Expected:

- Existing skill → current rank.
- Unknown valid skill ID → `undefined`.
- Malformed skill ID → reject.
- Không tạo skill.
- Không mutate state.
- Không gọi Skill Engine.

Nếu readonly snapshot đã đủ, helper vẫn có thể được cung cấp để bảo vệ canonical validation boundary.

Không tạo generic skill catalog lookup.

## 5.8. Immutability

Bắt buộc:

- Skill Rank State immutable.
- Nested rank map immutable.
- Caller input không bị freeze/mutate.
- Mutation của caller input sau creation không ảnh hưởng saved snapshot.
- Không chia sẻ writable backing maps.
- Không có module-global skill rank store.
- Multiple actors độc lập.

Không sử dụng `ProgressionState` làm mutable container cho skill ranks.

# 6. PG15 — Skill Point Pool

## 6.1. Objective

Quản lý điểm kỹ năng chưa sử dụng, đã tiêu và reward cursor.

Conceptual contract:

```ts
interface EntitySkillPointState {
  readonly entityId: string;
  readonly unspentPoints: number;
  readonly spentPoints: number;
  readonly rewardedThroughLevel: number;
}
```

Giữ Skill Points độc lập với Attribute Points.

Không thêm Skill Points vào `ProgressionState` bằng breaking change.

## 6.2. Skill Point Semantics

`unspentPoints`:

Số điểm kỹ năng hiện có thể sử dụng.

`spentPoints`:

Số điểm đã được sử dụng để nâng skill ranks.

`rewardedThroughLevel`:

Mốc level cuối cùng đã xử lý Skill Point Rewards.

Đây là cursor **riêng với Attribute Point Rewards**.

Một level có thể đã cấp Attribute Points nhưng chưa cấp Skill Points.

Không sử dụng chung một reward cursor giữa hai pools.

## 6.3. Initialization

Function tương đương:

```ts
createSkillPointState(progressionState, {
  unspentPoints: 3,
  spentPoints: 0,
  rewardedThroughLevel: 10
});
```

Bắt buộc:

- Canonical Progression State hợp lệ.
- Exact Entity ID.
- Points là nonnegative safe integers.
- Tổng points nằm trong safe-integer range.
- Cursor là positive safe integer.
- Cursor không vượt current Progression level.
- Initial values được caller cung cấp explicit.
- Không auto-grant points.

Không tự suy diễn số Skill Points từ Character Level.

## 6.4. No Generic Points Engine

PG11 Attribute Points có bookkeeping tương tự.

Có thể reuse small private validation/bookkeeping helpers nếu thực sự cần.

Nhưng không tạo:

- Generic Points Engine.
- Universal Wallet System.
- Gameplay Currency Manager.
- Shared mutable Point Store.

Không làm breaking change các PG11–PG13 APIs để hợp nhất Attribute Points và Skill Points.

Ưu tiên hai typed states với ownership rõ ràng.

## 6.5. Skill Point Rewards

Bổ sung operation tương đương:

```ts
grantSkillPointRewards(
  skillPointState,
  levelAdvancementResult,
  rewardPolicy
);
```

Caller cung cấp per-level Skill Point rewards.

Ví dụ:

```ts
{
  pointsByLevel: {
    11: 1,
    12: 2
  }
}
```

Nếu Level Advancement thực sự đạt:

```text
Level 10 → 12
Advanced Levels = [11, 12]
```

Expected:

```text
Skill Points Granted = 3
Rewarded Through Level = 12
```

Không tự cấp theo công thức mỗi level +1.

Không dùng Attribute Point reward policy làm Skill Point reward policy ngầm.

## 6.6. Reward Source Validation

Phải dùng actual PG09 Level Advancement Result.

Kiểm tra:

- Matching Entity ID.
- Successful contiguous advanced levels.
- Consistent before/after/levelsGained.
- Cursor phù hợp với `beforeLevel` của receipt.
- Complete reward policy.
- Point integer safety.
- No stale reward replay.

Không tự reconstruct level-up receipt từ current level.

Không cấp điểm từ target levels chưa đạt.

Không thưởng khi chỉ có EXP Gain.

## 6.7. Replay Protection

Ví dụ:

```text
Skill Point Cursor = 10

Apply Level 10→12:
  Skill Points +3
  Cursor = 12
```

Apply lại cùng result lên updated state.

Expected:

- Reject replay.
- Không cộng thêm 3 điểm.
- Cursor không đổi.

Không tạo global reward ledger.

Không claim exactly-once across stale immutable branches hoặc databases.

Caller phải sử dụng updated Skill Point State.

## 6.8. Zero Rewards

Zero-point reward hợp lệ nếu explicit.

Ví dụ:

```text
Level 11 reward = 0
```

Expected:

- `pointsGranted = 0`.
- Cursor vẫn tiến tới Level 11.
- Replay bị reject.

Missing reward entry không được ngầm xem là zero.

## 6.9. Other Point Sources

v0.3.4 chỉ yêu cầu level rewards và explicit initial balances.

Không tự hỗ trợ:

- Quest Skill Point rewards.
- Item-based Skill Points.
- Premium currency.
- Skill EXP.
- Point purchase.
- Point transfer.
- Refund/respec.

Nếu sau này các nguồn này cần thiết, thiết kế explicit grant authorization/source contract riêng.

Không tạo generic reward pipeline trước.

# 7. PG16 — Skill Upgrade Requirements

## 7.1. Objective

Đánh giá khả năng nâng một skill lên rank tiếp theo.

Required inputs:

- Current Progression State.
- Current Skill Rank State.
- Current Skill Point State.
- Caller-defined upgrade requirements.

## 7.2. Upgrade Policy

Conceptual contract:

```ts
interface SkillRankPrerequisite {
  readonly skillId: string;
  readonly minimumRank: number;
}

interface SkillUpgradeRequirement {
  readonly skillId: string;
  readonly expectedRank: number;
  readonly maxRank: number;
  readonly pointCost: number;
  readonly requiredCharacterLevel: number;
  readonly prerequisites: readonly SkillRankPrerequisite[];
  readonly eligible: boolean;
}
```

Policy là dữ liệu cho **một lần nâng rank**.

Không phải full Skill Definition.

Không chứa skill damage/cooldown/effect configuration.

## 7.3. Expected Rank

`expectedRank` là required field.

Ví dụ:

```text
Current Rank = 2
Expected Rank = 2
Requested Upgrade = Rank 3
```

Nếu actual current rank khác expectedRank:

**Reject stale request.**

Không tự nâng theo actual rank hiện tại khi caller đã yêu cầu một rank cụ thể.

Điều này tránh việc cùng một upgrade request bị xử lý lại trên updated state và vô tình nâng tiếp rank.

Ví dụ:

```text
Request:
  expectedRank = 2

First application:
  2 → 3

Replay on updated state:
  actualRank = 3
  expectedRank = 2

Result:
  reject stale upgrade
```

Đây là optimistic state precondition.

Không cần global lock hoặc transaction store.

Không claim prevention of replay khi caller cố tình sử dụng lại stale pre-upgrade snapshot.

## 7.4. Rank Cap

Caller cung cấp:

```ts
maxRank: 10
```

Requirements:

- Positive safe integer.
- Current rank không được lớn hơn maxRank.
- Không auto-clamp current rank.
- Khi current rank = maxRank, trả blocked reason `max_rank`.
- Không cho rank vượt safe-integer range.

Không hardcode max rank.

Không giả định tất cả skills đều có 10 hoặc 20 ranks.

## 7.5. Point Cost

Caller cung cấp:

```ts
pointCost: 2
```

Point Cost là nonnegative safe integer.

**Zero-cost upgrade được phép nếu caller explicit cấu hình**, ví dụ một free starter skill.

Không có default cost.

Không tự tính cost theo current rank.

Không dùng Level EXP làm Skill Point Cost.

Nếu cost lớn hơn unspentPoints:

`insufficient_points`

Không tạo negative balance.

## 7.6. Required Character Level

Caller cung cấp:

```ts
requiredCharacterLevel: 20
```

Bắt buộc:

- Positive safe integer.
- So sánh với `ProgressionState.level`.
- Không tự evaluate Level Advancement.
- Không tự gain EXP.
- Không auto level-up.

Nếu current level thấp hơn requirement:

`character_level_too_low`

Không đọc Entity kind để tạo class-specific level requirement.

## 7.7. Skill Rank Prerequisites

Ví dụ:

```ts
prerequisites: [
  {
    skillId: "sword_basic",
    minimumRank: 3
  }
]
```

Ý nghĩa:

Target skill chỉ được nâng khi `sword_basic` đạt ít nhất Rank 3.

Bắt buộc:

- Prerequisite Skill ID hợp lệ.
- Referenced skill tồn tại trong Skill Rank State.
- Required rank là positive safe integer.
- Không có duplicate prerequisites.
- Không self-reference target skill.
- Không dùng inherited keys.
- Không auto-learn prerequisite skill.

Nếu prerequisite tồn tại nhưng rank chưa đủ:

`prerequisite_not_met`

Nếu prerequisite reference malformed/unknown:

Reject invalid policy.

Không tự đăng ký skill còn thiếu.

## 7.8. No Generic Talent Tree

Không xây:

- Full skill graph engine.
- Recursive unlock resolver.
- Talent Tree.
- Dependency graph persistence.
- Skill Class Tree.
- Automatic prerequisite traversal.

PG16 chỉ kiểm tra một explicit list của các prerequisite Skill IDs trong current rank state.

Không dùng generic Condition DSL.

Caller chịu trách nhiệm tính các yêu cầu phức tạp hơn.

## 7.9. External Eligibility

Caller cung cấp:

```ts
eligible: true
```

Có thể đại diện cho kết quả đánh giá:

- Class restriction.
- Quest restriction.
- Item requirement.
- Character specialization.
- Game-specific unlock condition.

L2 chỉ nhận boolean.

Không tự query các modules chưa tồn tại.

Nếu false:

`condition_not_met`

Không cho phép callbacks có hidden side effects trong upgrade policy ở v0.3.4.

## 7.10. Requirement Validation

Reject:

- Missing/unknown fields.
- Invalid skill ID.
- Unknown target skill.
- Invalid expectedRank.
- Inconsistent expectedRank.
- Invalid maxRank.
- Invalid pointCost.
- Invalid requiredCharacterLevel.
- Invalid prerequisite list.
- Duplicate prerequisites.
- Self-prerequisite.
- Unknown prerequisite ID.
- Invalid eligible type.
- Getter-based/inherited required fields.
- Sparse arrays.
- Nonfinite/unsafe numerical fields.

Malformed inputs phải reject trước khi tạo successful upgrade result.

Không dùng blocked reason để che invalid policy.

## 7.11. Deterministic Evaluation Priority

Sau khi validate input hoàn chỉnh, áp dụng thứ tự:

1. Max rank.
2. Required character level.
3. Skill prerequisites.
4. External eligibility.
5. Available Skill Points.

Trả reason của điều kiện đầu tiên chưa đạt.

Không thử những điều kiện sau để đổi reason nếu một bước trước đã blocked.

Không mutate state trong quá trình evaluate.

# 8. PG17 — Skill Rank Upgrade

## 8.1. Objective

Cho phép nâng chính xác một rank bằng explicit operation.

Public function tương đương:

```ts
upgradeSkillRank(
  progressionState,
  skillRankState,
  skillPointState,
  requirement
);
```

Không tự nâng nhiều ranks trong một call.

Nếu muốn tăng nhiều ranks, caller phải tạo nhiều explicit requests với expectedRank mới và point-cost policy tương ứng.

## 8.2. Dry-Run Evaluation

Bổ sung function tương đương:

```ts
evaluateSkillUpgrade(
  progressionState,
  skillRankState,
  skillPointState,
  requirement
);
```

Expected:

- Validate state/policy.
- Evaluate requirements.
- Project next rank và point balance.
- Không mutate inputs.
- Không phát event.
- Không gọi Skill Engine.

Dry-run và actual upgrade phải sử dụng **một canonical internal resolution path**.

Không viết hai calculators với semantics khác nhau.

## 8.3. Successful Upgrade

Ví dụ:

```text
Player Level = 20

Skill:
  sword_basic Rank 2

Skill Points:
  Unspent = 3
  Spent = 5

Requirements:
  expectedRank = 2
  maxRank = 10
  pointCost = 2
  requiredCharacterLevel = 15
  prerequisites = []
  eligible = true
```

Expected:

```text
Skill Rank:
  2 → 3

Skill Points:
  Unspent 3 → 1
  Spent 5 → 7
```

Progression Level/EXP không đổi.

Không thực thi kỹ năng.

Không phát event.

## 8.4. Rank 0 → Rank 1

Rank 0 có thể được nâng lên Rank 1 nếu policy hợp lệ.

Ví dụ:

```text
fireball Rank 0
Skill Points = 1

Cost = 1
MaxRank = 5
```

Expected:

```text
fireball Rank 1
Skill Points = 0
```

Đây là explicit learning/upgrade operation.

Không tạo một Skill Instance hoặc Skill Definition runtime.

Không tự cấp cooldown/effects.

## 8.5. Blocked Upgrade

Nếu một valid requirement chưa đạt:

- Không đổi Skill Rank State.
- Không đổi Skill Point State.
- Trả structured blocked outcome/reason.
- Không tự giảm cost.
- Không nâng rank một phần.
- Không phát event.

Không coi blocked upgrade là malformed input.

Phân biệt rõ blocked result và invalid request exception.

## 8.6. No Implicit Unlocks

Sau successful upgrade:

- Chỉ target skill được tăng một rank.
- Không tự nâng prerequisite skills.
- Không tự tạo unlocked skill list thứ hai.
- Không tự unlock các skills khác.
- Không tự cập nhật Player Class.
- Không tự apply Skill Effects.

Caller/Skill module tương lai có thể dùng current rank để đánh giá unlock/activation.

## 8.7. Two-State Result Construction

Successful upgrade thay đổi:

- Skill Rank State.
- Skill Point State.

Bắt buộc:

1. Validate Progression State.
2. Validate Skill Rank State.
3. Validate Skill Point State.
4. Validate matching Entity IDs.
5. Validate policy.
6. Evaluate requirements.
7. Calculate projected rank/points.
8. Create immutable next Skill Rank State.
9. Create immutable next Skill Point State.
10. Return combined result.

Nếu bất kỳ validation nào fail:

- Không mutate old states.
- Không trả partial successful result.
- Không consume points.

**Đây là immutable combined result construction, không phải persistent transaction engine.**

Caller chịu trách nhiệm lưu hoặc áp dụng đồng bộ các snapshots mới.

## 8.8. No Automatic Level Interaction

Skill upgrade không tự:

- Gain EXP.
- Level-up character.
- Grant Skill Points.
- Allocate Attribute Points.
- Recalculate Attributes/Stats.
- Normalize Resources.
- Revive Entity.

Những state domains tiếp tục tách biệt.

# 9. PG18 — Skill Progression Result

## 9.1. Objective

Chuẩn hóa kết quả Skill Upgrade để consumer quan sát chính xác:

- Upgrade thành công.
- Upgrade bị chặn.
- Lý do bị chặn.
- Rank trước/sau.
- Skill Points trước/sau.

## 9.2. Assessment Contract

Conceptual types:

```ts
type SkillUpgradeOutcome =
  | "upgraded"
  | "blocked";

type SkillUpgradeBlockReason =
  | "none"
  | "max_rank"
  | "character_level_too_low"
  | "prerequisite_not_met"
  | "condition_not_met"
  | "insufficient_points";

interface SkillUpgradeAssessment {
  readonly entityId: string;
  readonly skillId: string;
  readonly beforeRank: number;
  readonly projectedRank: number;
  readonly beforeUnspent: number;
  readonly projectedUnspent: number;
  readonly pointsSpent: number;
  readonly outcome: SkillUpgradeOutcome;
  readonly reason: SkillUpgradeBlockReason;
}
```

Có thể bổ sung `afterSpent` hoặc prerequisite diagnostic cần thiết, nhưng không tạo large generic result framework.

## 9.3. Upgrade Result

Conceptual shape:

```ts
interface SkillUpgradeResult {
  readonly ranks: EntitySkillRankState;
  readonly points: EntitySkillPointState;
  readonly transition: SkillUpgradeAssessment;
}
```

Tên public fields có thể điều chỉnh theo accepted conventions.

## 9.4. Successful Result

Ví dụ:

```ts
{
  transition: {
    entityId: "player-1",
    skillId: "sword_basic",
    beforeRank: 2,
    projectedRank: 3,
    beforeUnspent: 3,
    projectedUnspent: 1,
    pointsSpent: 2,
    outcome: "upgraded",
    reason: "none"
  }
}
```

Combined result phải chứa next Rank/Point States.

Không chỉ trả `true`.

Không dùng `success: true` nếu không cung cấp actual transition evidence.

## 9.5. Blocked Result

Ví dụ:

```ts
{
  transition: {
    entityId: "player-1",
    skillId: "fireball",
    beforeRank: 0,
    projectedRank: 0,
    beforeUnspent: 1,
    projectedUnspent: 1,
    pointsSpent: 0,
    outcome: "blocked",
    reason: "character_level_too_low"
  }
}
```

Không mutate state.

Không tiêu points.

Không tăng rank.

## 9.6. Dry-Run Consistency

Bắt buộc:

```text
evaluateSkillUpgrade(...inputs)
==
upgradeSkillRank(...inputs).transition
```

Theo semantic deep equality.

Không tạo duplicate upgrade implementation.

Không gọi Clock/RNG.

Không tạo Event ID.

Không tự phát event.

## 9.7. Result Immutability

Bắt buộc:

- Result immutable.
- Nested Skill Rank State immutable.
- Nested Skill Point State immutable.
- Nested rank maps immutable.
- Transition immutable.
- Caller policy không bị mutate.
- Old snapshots không thay đổi.

Không expose writable backing references.

# 11. Identity & Validation Boundaries

## 11.1. Entity ID Consistency

Bắt buộc:

```text
ProgressionState.entityId
==
SkillRankState.entityId
==
SkillPointState.entityId
```

Nếu mismatch:

- Reject.
- Không upgrade.
- Không spend points.
- Không search global Entity Collection.

Không tạo cross-actor rank mutation.

## 11.2. Structural Input Validation

Không tin hoàn toàn vào readonly TypeScript types.

Bảo vệ:

- Closed own-data records.
- Valid Entity IDs.
- Valid skill IDs.
- Valid point balances.
- Valid rank values.
- Valid prerequisite arrays.
- Valid policy numbers.
- No unknown fields.
- No accessor invocation.
- No prototype pollution.

Tái sử dụng existing Progression private validation conventions.

Không duplicate canonical Entity validator.

## 11.3. Invalid vs Blocked

**Invalid input:**

```text
expectedRank = -1
```

Reject TypeError.

**Valid but blocked:**

```text
expectedRank = 2
actualRank = 2
unspentPoints = 1
pointCost = 3
```

Return blocked:

`insufficient_points`

**Stale request:**

```text
expectedRank = 2
actualRank = 3
```

Reject as inconsistent/stale request.

Không âm thầm upgrade Rank 3→4.

## 11.4. Safe Integer Invariants

Bắt buộc:

- Rank là nonnegative safe integer.
- Point balances là nonnegative safe integers.
- Point totals trong safe-integer range.
- Character level là positive safe integer.
- Max rank là positive safe integer.
- Prerequisite required rank là positive safe integer.
- Rank increment không vượt safe-integer bounds.
- Spending không làm âm balance.

Không tự ép fractional values thành integer.

Không silent overflow.
