# 5. EC07 — Base Attributes

## 5.1. Objective

Cho phép một Entity có tập Base Attributes độc lập và được quản lý thông qua immutable state transitions.

Attributes là các numeric values được định danh bằng caller-defined keys.

Ví dụ:

```ts
{
  strength: 10,
  dexterity: 8,
  vitality: 12,
  intelligence: 5
}
```

Các tên trên chỉ là ví dụ dữ liệu L3.

L2 không được hardcode bốn thuộc tính này.

Một game khác có thể sử dụng:

```ts
{
  power: 15,
  agility: 20,
  focus: 10
}
```

Cùng public contract phải hỗ trợ được cả hai.

## 5.2. Entity Attribute State

Thiết kế public contract tương đương:

```ts
interface EntityAttributeState {
  readonly entityId: string;
  readonly baseAttributes: Readonly<Record<string, number>>;
}
```

Yêu cầu:

- Gắn với Entity identity hiện có.
- Không thay thế `EntitySnapshot`.
- Không thêm `baseAttributes` vào closed `createEntity()` input.
- Không yêu cầu Entity Collection thay đổi schema.
- Không chứa effective stats hoặc derived stats đang được cache ngầm.
- Không chứa calculation rules hoặc modifiers dưới dạng hidden global state.
- Không chứa runtime/engine references.

**Attribute State là dữ liệu gameplay riêng, không phải Entity Collection thứ hai.**

Nếu v0.2.1 đã có một canonical typed state extension mechanism thực sự phù hợp, agent phải audit và sử dụng nó thay vì tạo implementation cạnh tranh.

Không được ép state vào một unvalidated `Record<string, unknown>`.

## 5.3. Required Public Functions

Cung cấp public functions tương đương:

```ts
createEntityAttributeState(entity, baseAttributes)

getEntityBaseAttributes(attributeState)

setEntityBaseAttribute(attributeState, attributeId, value)
```

Có thể điều chỉnh tên cho phù hợp conventions hiện có.

Không cần thêm hàng loạt CRUD functions.

### Creation

```ts
const entity = createEntity({
  id: "actor-1",
  kind: "player"
});

const attributes = createEntityAttributeState(entity, {
  strength: 10,
  vitality: 12
});
```

Expected:

- Attribute State lưu đúng Entity ID.
- Base values giữ nguyên.
- Entity snapshot không đổi.
- Không tự tính derived stats.
- Không gọi Kernel.
- Không tạo global store.
- Không tạo implicit Entity ID.

### Read

`getEntityBaseAttributes()` trả readonly detached hoặc safely shared immutable snapshot.

Không trả mutable backing map.

### Update

```ts
const updated = setEntityBaseAttribute(
  attributes,
  "strength",
  15
);
```

Expected:

- `attributes.strength` vẫn bằng 10.
- `updated.strength` bằng 15.
- Các base attributes khác không đổi.
- Entity ID không đổi.
- Không tự chạy stat calculation.

Chỉ cho phép cập nhật một attribute key đã tồn tại.

Việc thay đổi toàn bộ attribute schema, thêm/xóa keys hoặc thay đổi actor profile không thuộc keyed-update API này.

Không tự thêm một attribute mới khi key không tồn tại.

## 5.4. Attribute Validation

Bắt buộc:

- Attribute identifier là nonblank string.
- Không tự normalize key.
- Values phải là finite numbers.
- Không chấp nhận `NaN`, `Infinity`, `-Infinity`.
- Negative values được phép ở base-state layer; bounds thuộc calculation rules.
- Không ép values thành integer.
- Không mặc định minimum là 0.
- Không tự clamp base values.
- Không chấp nhận inherited hoặc accessor-based data fields làm attribute input.
- Không chấp nhận callable values.

Empty attribute map được phép để hỗ trợ actor không sử dụng attributes.

Không ép NPC phải có Strength/HP.

Cần xử lý chính xác những property names đặc biệt như `constructor` hoặc `__proto__`, tránh làm thay đổi object prototype hay ghi nhầm giá trị.

Không tự áp đặt whitelist thuộc tính.

## 5.5. Immutability

- Snapshot immutable.
- Caller mutation không làm đổi captured values.
- Update tạo state mới.
- Original state không đổi.
- Hai Entity Attribute States độc lập.
- Không dùng global mutable state.
- Không mutate Entity Collection.

Có thể chia sẻ immutable scalar data, nhưng không được giữ mutable input aliases.

## 5.6. Identity Binding

Entity ID là association key.

Attribute state không tự kiểm tra Entity còn tồn tại trong một collection hay không, trừ khi caller explicit cung cấp collection và một contract đã duyệt yêu cầu việc đó.

Không tự query global Entity Collection.

Không tự xóa Attribute State khi một Entity bị remove khỏi collection.

Collection membership synchronization thuộc một integration decision khác, không được triển khai ngầm.

# 6. EC08 — Effective Attributes & Derived Stats

## 6.1. Objective

Cho phép tính Effective Attributes và Derived Stats từ:

- Entity Base Attributes.
- Caller-supplied numerical rules.
- Caller-supplied attribute baselines.
- Base stat inputs.
- Flat contributions.
- Canonical numerical modifiers.
- Optional stat transforms nếu contract cho phép.

Không đưa game rules vào Entity module.

## 6.2. Kernel Calculation Contract

Sử dụng `calculateStats()` từ `@rpg/core/kernel`.

Kernel nhận một `PreparedStatCalculationInput` với các thông tin cơ bản:

```ts
{
  attributeOrder,
  statOrder,
  attributeBases,
  attributeRules,
  attributeBaselines,
  baseStats,
  rules,
  flatContributions,
  transforms
}
```

và một `StatModifierResolver`.

Đầu vào này cần được chuẩn bị từ:

- Attribute State của L2.
- Stat Configuration của caller.
- Canonical Kernel modifier resolver.

Không copy nguyên thuật toán calculateStats sang L2.

## 6.3. Caller-Supplied Configuration

Cung cấp public type tương đương:

```ts
interface EntityStatConfiguration {
  readonly attributeOrder: readonly string[];
  readonly statOrder: readonly string[];
  // Kernel-compatible numeric rules,
  // baselines, baseStats, contributions,
  // modifiers and optional transforms.
}
```

Đây là conceptual contract.

Ưu tiên tái sử dụng Kernel public types:

- `NumericRule`
- `DerivedStatRule`
- `NumericalModifier`
- `PreparedStatCalculationInput`
- `StatCalculationResult`

Không định nghĩa bản sao không tương thích của các types này trong L2.

Agent có thể dùng `Pick`, `Omit` và type composition nếu phù hợp.

Configuration phải có owner rõ ràng:

- L3/caller cung cấp configuration.
- L2 validate/prepare.
- Kernel calculate.

Không tự tạo game-specific defaults.

## 6.4. Required Public Function

Cung cấp function tương đương:

```ts
calculateEntityStats(
  attributeState,
  statConfiguration
)
```

Trả về một immutable Entity Stat Snapshot.

Minimum observable output:

```ts
{
  entityId: "actor-1",
  effectiveAttributes: {
    strength: 10
  },
  stats: {
    power: 25
  }
}
```

Đây là conceptual shape.

Có thể bổ sung breakdown/diagnostics khi lấy trực tiếp từ Kernel result, nhưng không được tính lại chỉ để tạo diagnostics.

Không tự thay đổi kết quả Kernel.

## 6.5. Rule Ownership

L2 không định nghĩa:

- Strength tăng bao nhiêu Damage.
- Vitality tăng bao nhiêu HP.
- Dexterity tăng bao nhiêu Accuracy.
- Intelligence tăng bao nhiêu Mana.
- Stat nào bắt buộc tồn tại.
- Stat nào được phép âm.
- Modifier caps.
- Game-specific default precision.

Tất cả thuộc rules/configuration do consumer cung cấp.

Không tạo mặc định theo Võ Lâm hoặc Diablo.

## 6.6. Calculation Ordering

Bắt buộc bảo toàn:

1. Attribute evaluation order.
2. Effective attribute results.
3. Derived stat evaluation order.
4. Kernel modifier resolver semantics.
5. Kernel clamping/precision semantics.

Không tự sort keys trước khi gọi Kernel nếu caller đã cung cấp order.

Không tự áp đặt một thứ tự mặc định theo Strength/Dexterity/Vitality.

Validate:

- `attributeOrder` không có duplicate IDs.
- `statOrder` không có duplicate IDs.
- Mỗi ordered attribute có required base/rule/baseline.
- Mỗi ordered stat có corresponding rule.
- Scaling references phải trỏ tới các attribute hợp lệ.
- Tránh key collisions gây nhập nhằng giữa attribute targets và stat targets.
- Invalid/incomplete configurations fail trước khi tạo successful snapshot.

Không gọi Kernel trên malformed input rồi silently normalize kết quả.

Không thực hiện pre-calculation hoặc post-calculation arithmetic nhằm sửa output của Kernel.

## 6.7. Modifier Integration

Modifier arithmetic bắt buộc dùng:

```ts
prepareNumericalModifiers(modifiers)
```

Từ public Kernel.

Không tự viết:

```ts
base + flat
base * percent
```

trong L2.

Không tự implement:

- Modifier stacking.
- Modifier aggregation.
- Modifier deduplication.
- Source priority.
- Percentage normalization.
- Modifier numerical ordering.

Có thể cung cấp empty modifier list khi actor không có modifiers.

**No-modifier scenario vẫn phải sử dụng canonical Kernel calculation path**, không triển khai calculator riêng.

Modifier ownership/source activation policy do caller hoặc gameplay capabilities tương lai cung cấp.

Entity v0.2.2 chưa tự quyết định modifier đến từ Equipment, Skill, Effect hay Buff.

## 6.8. Calculation Result Snapshot

Kernel calculation result không mặc nhiên là immutable runtime snapshot.

L2 phải tạo result projection an toàn khi public contract tuyên bố immutable.

Minimum guarantees:

- Effective attribute values được detach khỏi mutable input.
- Derived stat values được detach.
- Public snapshot không thể bị caller mutate.
- Không freeze caller-owned rules, modifiers hoặc callbacks.
- Không giữ writable references làm thay đổi kết quả đã xuất bản.
- Không tự recompute numerical results để dựng snapshot.

Nếu expose Kernel diagnostic details, phải bảo đảm không làm rò rỉ mutable modifier contribution aliases hoặc ghi rõ ownership contract; ưu tiên chỉ expose detached data thực sự cần thiết trong v0.2.2.

Không xây generic deep clone framework chỉ để đóng gói hai numeric maps.

# 7. EC09 — Stat Recalculation

## 7.1. Objective

Cho phép tính lại Stats khi input thay đổi.

Các nguyên nhân:

- Base Attributes được cập nhật.
- Modifier inputs thay đổi.
- Stat rules thay đổi.
- Attribute baselines thay đổi.
- Base stat inputs thay đổi.

Không yêu cầu Entity tự phát hiện các thay đổi này.

## 7.2. Explicit Recalculation

Sử dụng canonical calculation function của EC08 cho mọi lần tính.

Ví dụ:

```ts
const first = calculateEntityStats(
  initialAttributes,
  configuration
);

const updatedAttributes = setEntityBaseAttribute(
  initialAttributes,
  "strength",
  15
);

const second = calculateEntityStats(
  updatedAttributes,
  configuration
);
```

Expected:

- `first` không đổi.
- `second` phản ánh Base Attribute mới.
- Không mutate original Attribute State.
- Không mutate configuration.
- Không giữ stale global result.

Không yêu cầu API `recalculateEntityStats()` riêng nếu nó chỉ gọi lại cùng thuật toán EC08.

**Một canonical calculation path là đủ.**

## 7.3. Modifier Recalculation

Khi caller cung cấp một modifier set mới:

```text
Calculation A:
  Base Attributes + Modifiers A

Calculation B:
  Base Attributes + Modifiers B
```

Expected:

- Calculation B phản ánh Modifiers B.
- Calculation A snapshot không đổi.
- Không dùng stale modifier resolver của lần A.
- Không tự mutate Entity Attribute State để lưu active modifiers.
- Không tạo modifier cache toàn cục.

Nếu prepared resolver được tạo mỗi calculation boundary thì phải sử dụng đúng các modifier inputs tương ứng của lần đó.

Không tự lưu modifier lifecycle trong Entity module.

## 7.4. Recalculation State Semantics

Computed Stat Snapshot là kết quả của một lần tính toán.

Không phải live binding.

Không auto-update snapshot khi caller thay đổi configuration.

Không tự phát event `stats-changed`.

Không tự cập nhật HP/MP khi Max HP/MP thay đổi.

Không tự cập nhật Equipment/Combat State.

Các integrations này phải được thiết kế ở milestone/module phù hợp.

## 7.5. Determinism

Cùng:

- Attribute State.
- Stat Configuration.
- Modifier inputs.
- Execution order.
- Deterministic callbacks.

Phải tạo cùng semantic calculated results.

Nếu caller cung cấp transform callbacks có hidden mutable/nondeterministic behavior, Foundation/Entity không cam kết bảo đảm sự thuần nhất ngoài điều kiện của Kernel contract.

Không tự inject Clock/RNG.

Không dùng current time hoặc random trong stat calculations.

# 8. Expected Functional Example

Ví dụ kiểm chứng đơn giản với caller-defined rules.

Base Attribute:

```ts
{
  strength: 10
}
```

Derived Stat:

```text
power = base 5 + strength × 2
```

Trong production, công thức này phải được biểu diễn bằng Kernel-compatible `DerivedStatRule`, không viết thành một hàm calculator riêng.

Configuration tương ứng:

```ts
{
  attributeOrder: ["strength"],
  statOrder: ["power"],
  attributeBaselines: {
    strength: 0
  },
  baseStats: {
    power: 5
  }
}
```

Caller cung cấp đầy đủ `attributeRules`, `rules`, `flatContributions` và các field Kernel bắt buộc khác.

Expected outcomes:

| Scenario | Expected power |
|---|---:|
| Strength = 10, không modifier | 25 |
| Strength = 12, không modifier | 29 |
| Strength = 12, thêm `power add_flat +3` | 32 |

Các expected values này chỉ được dùng làm **independent test oracle**.

Implementation L2 phải nhận kết quả từ `calculateStats()` và `prepareNumericalModifiers()`.

Không viết lại biểu thức tính `power` trong Entity production code.

# 12. Minimum Meaningful Test Scenarios

## Scenario A — Multiple Actors

Tạo:

- Player với strength/vitality.
- Monster với power/agility.
- NPC với empty attributes.

Expected:

- Cùng public functions.
- Không hardcode actor kind.
- Independent Attribute States.
- Không yêu cầu cùng attribute schema.

## Scenario B — Base Attribute Update

State A:

```text
strength = 10
vitality = 12
```

Update strength thành 15.

Expected:

```text
State A: strength 10, vitality 12
State B: strength 15, vitality 12
```

Không mutation.

## Scenario C — Kernel Stat Calculation

Dùng một attribute và derived stat theo ví dụ ở Section 8.

Expected:

```text
strength 10 → power 25
strength 12 → power 29
modifier +3 → power 32
```

Kiểm tra kết quả được public function trả về.

Không dùng snapshot từ chính implementation để sinh expected values.

## Scenario D — Recalculation Isolation

Tạo:

- Calculation A với base attributes cũ.
- Calculation B với updated attributes.
- Calculation C với modifier set mới.

Expected:

- A không đổi.
- B và C thay đổi đúng expected values.
- Không có stale results.
- Entity Collection không đổi.

## Scenario E — Invalid Inputs

Reject:

- Nonfinite base attributes.
- Invalid attribute key.
- Unknown attribute update key.
- Missing configuration.
- Duplicate order IDs.
- Missing attribute rules/baselines.
- Unknown scaling attribute.
- Invalid modifier/configuration inputs.

Không sửa test expected values chỉ để hợp thức hóa một kết quả Kernel bị gọi sai.

## Scenario F — Kernel Boundary

Chứng minh thực tế:

- `calculateStats()` được sử dụng.
- `prepareNumericalModifiers()` được sử dụng.
- Modifier arithmetic không được viết lại.
- Các edge cases có ý nghĩa từ canonical Kernel được bảo toàn.
- Không thêm hidden numerical fallback.

Source audit và installed consumer evidence cùng cần thiết; một lexical import assertion không đủ để chứng minh absence of duplicate calculations.
