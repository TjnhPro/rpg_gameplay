## 4. Proposed exact public API — freeze after Developer approval

**Seven runtime functions, eight public types.** These are deliberate concise contracts inherited from the old three task proposals and now created **together**. Do not add convenience aliases/APIs beyond this set.

```ts
export interface ItemDefinitionReference { readonly definitionId: string; }
export interface ItemInstanceInitialIdentity { readonly instanceId: string; }
export interface ItemInstanceReference {
  readonly instanceId: string;
  readonly definitionId: string;
}
export type ItemPropertyValue =
  | null | string | number | boolean
  | readonly ItemPropertyValue[]
  | Readonly<Record<string, ItemPropertyValue>>;
export interface ItemDefinitionContent {
  readonly categoryId: string | null;
  readonly tagIds: readonly string[];
  readonly rarityId: string | null;
  readonly properties: Readonly<Record<string, ItemPropertyValue>>;
}
export interface ItemDefinition extends ItemDefinitionContent {
  readonly definitionId: string;
}
export interface ItemInstanceInitialState {
  readonly instanceId: string;
  readonly properties: Readonly<Record<string, ItemPropertyValue>>;
}
export interface ItemInstanceState {
  readonly instanceId: string;
  readonly definitionId: string;
  readonly properties: Readonly<Record<string, ItemPropertyValue>>;
}

export function createItemDefinitionReference(
  reference: ItemDefinitionReference,
): ItemDefinitionReference;
export function createItemInstanceReference(
  definition: ItemDefinitionReference,
  initial: ItemInstanceInitialIdentity,
): ItemInstanceReference;
export function validateItemInstanceReference(
  definition: ItemDefinitionReference,
  instance: ItemInstanceReference,
): ItemInstanceReference;
export function createItemDefinition(
  reference: ItemDefinitionReference,
  content: ItemDefinitionContent,
): ItemDefinition;
export function validateItemDefinition(
  definition: ItemDefinition,
): ItemDefinition;
export function createItemInstance(
  definition: ItemDefinition,
  initial: ItemInstanceInitialState,
): ItemInstanceState;
export function validateItemInstance(
  definition: ItemDefinition,
  instance: ItemInstanceState,
): ItemInstanceState;
```

### 4.1. Structural conventions — normative

1. **Opaque IDs:** required nonblank strings, preserve exact bytes/case/whitespace. No trim, normalization, parsing or invented ID. All instance/definition binding compares exact string equality. Repeating an `instanceId` in independent calls is allowed structurally; L4/Inventory enforce global/local uniqueness where appropriate.
2. **Closed own-data records:** public definition/reference/initial/instance records must contain exactly the defined string own keys; no extra enumerable/nonenumerable string or symbol keys, inherited required fields, getters/setters, invalid prototype, array/class instance or unsafe proxy getter execution. Accept ordinary or null-prototype plain records when fully inspectable and structurally valid; reject hostile proxy-like forms where reliably detectable without invoking user accessors.
3. **Definition metadata:** `categoryId` and `rarityId` are `null` or exact nonblank opaque string; no fixed vocabulary, rank or default. `tagIds`: required dense ordered `string[]`, may be empty; reject duplicate exact tags and invalid tag ID, preserve order; Unicode/padded nonblank valid.
4. **Property dictionary:** required plain/null-prototype own-data record. Keys are **arbitrary exact strings**, including `''`, `__proto__`, `constructor`, `toString`, numeric-like keys and Unicode. These are inert keys, not special commands or forbidden words.
5. **Property values:** recursive `null | string | finite number | boolean | dense readonly array | plain/null-prototype own-data record`. Reject cycles, symbol own keys, accessors (without invoking them), sparse arrays, unexpected array own fields, custom prototypes, `undefined`, `NaN`, infinities, functions, BigInt, Date, Map, Set, RegExp and class instances. Preserve `-0` numerically without normalizing. Do not define arbitrary schema/max depth/size policies beyond what the accepted implementation can safely verify; report resource-exhaustion risk honestly.
6. **Copy/freeze:** every creation and validation function returns a freshly allocated, detached, deeply frozen safe data snapshot with exactly documented fields. No input is modified, frozen, registered or aliased into public output; dangerous own data keys must be defined safely without prototype pollution.
7. **Definition–instance binding:** `createItemInstance` validates a **complete** `ItemDefinition`; uses only its `definitionId` for binding and copies explicitly supplied `initial.properties`. It neither inherits nor merges definition `properties`. `validateItemInstance` fully validates its given instance against a complete definition, rejects ID mismatch, and produces fresh snapshot.
8. **Legacy reference helpers:** `createItemInstanceReference`/`validateItemInstanceReference` accept the *narrow definition reference* shape, not an entire contentful definition with extra fields. When using a contentful definition, explicitly project `{definitionId}`. Avoid contradictory acceptance tests.
9. **Failure:** malformed structure = deterministic `TypeError` with no partial output; no default coercions/repairs. Missing L3 catalog rows are **not** structurally invalid if only opaque ID has been supplied.
10. **Determinism:** same explicit inputs yield equal complete values/order, no implicit time/RNG/counters/store/ambient locale; values are newly detached regardless of caller object identity.
