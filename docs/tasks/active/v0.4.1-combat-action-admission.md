# 5. CB06 — Actor Existence

## 5.1. Objective

Kiểm tra source actor của một Combat Action có hiện diện trong Entity Collection được caller cung cấp hay không.

## 5.2. Input

Sử dụng actual Combat Action Context:

```ts
{
  actionId: "attack-001",
  actionType: "basic_attack",
  sourceEntityId: "player-1",
  target: {
    kind: "entity",
    entityId: "monster-1"
  }
}
```

Caller cung cấp:

`EntityCollection`

Ví dụ collection có:

```text
player-1
monster-1
```

## 5.3. Existence Semantics

Source existence:

```text
getEntity(collection, sourceEntityId)
```

Nếu tồn tại:

- Cho phép tiếp tục kiểm tra Life State.

Nếu không tồn tại:

- Return rejected admission.
- Reason: `source_not_found`.

Không:

- Tự tạo Entity.
- Tự thêm actor vào collection.
- Tự tìm actor trong global store.
- Tự load actor từ database.
- Tự dùng `Entity.kind` để suy đoán actor tồn tại.

## 5.4. Source vs Target

Ở v0.4.1 chỉ check:

`sourceEntityId`

Không check:

`target.entityId`

Ví dụ:

```text
Source = player-1
Target = unknown-target
```

Nếu source tồn tại, đang alive và eligible:

Actor-stage admission có thể trả `admitted`.

Target validation sẽ được thực hiện riêng ở v0.4.2.

Không kết luận target đã hợp lệ.

## 5.5. Player / Monster Parity

Cùng một API phải xử lý:

```text
player-1 → monster-1
```

và:

```text
monster-1 → player-1
```

Không có hardcoded rules:

```text
Only player can attack
Only monster can attack
```

Entity `kind` không phải cơ sở mặc định cho Combat Admission.

# 6. CB07 — Actor Life Eligibility

## 6.1. Objective

Kiểm tra source actor đang sống hay đã chết trước khi cho phép action attempt.

Dùng:

`EntityLifeState`

Không tạo Combat Life State riêng.

## 6.2. Life Input

Caller explicit cung cấp:

```ts
{
  entityId: "player-1",
  status: "alive"
}
```

hoặc:

```ts
{
  entityId: "player-1",
  status: "dead"
}
```

Không tự suy luận Life State từ:

- Entity kind.
- Character level.
- Current HP.
- Target information.
- Combat Action Type.

## 6.3. Identity Consistency

Bắt buộc:

```text
CombatActionContext.sourceEntityId
==
EntityLifeState.entityId
```

Nếu mismatch:

- Throw `TypeError`.
- Không trả rejected gameplay result.
- Không truy cập hoặc mutate state của actor khác.

Ví dụ:

```text
Action source = player-1
LifeState entityId = monster-1
```

Expected:

`TypeError`

Không tự sửa Entity ID.

## 6.4. Alive Actor

```text
LifeState.status = alive
```

Life check PASS.

Tiếp tục External Eligibility.

Không tự coi `alive` đồng nghĩa eligible vì external rules vẫn có thể từ chối.

## 6.5. Dead Actor

```text
LifeState.status = dead
```

Expected:

```text
status = rejected
reason = source_dead
```

Không:

- Gọi `reviveEntity()`.
- Tự tăng HP.
- Tự đổi Life State.
- Tự phát event.
- Tự xử lý death animation.

## 6.6. Canonical Life Ownership

`resolveEntityDefeat()` chỉ dùng khi caller cần đánh giá death từ Resource State theo explicit Entity policy.

Admission không được tự tính lại death bằng:

```text
currentHp <= 0
```

Nếu caller cung cấp Life State đang `alive`, Combat dùng chính Life State đó.

Consistency giữa HP và Life State là trách nhiệm của caller khi thực hiện Entity state transitions.

Không thêm HP input vào v0.4.1.

## 6.7. Missing Life State

Không có default:

```text
status = alive
```

Missing/invalid `EntityLifeState` phải reject malformed input bằng `TypeError`.

Không silent fallback.

Không tự tạo Life State từ Entity kind.

## 6.8. Structural Life Validation

Bảo vệ:

- Required own `entityId`.
- Required own `status`.
- Không extra fields.
- Không getters/accessors.
- Valid Entity ID.
- Valid Entity Life Status.

Dùng accepted Entity APIs khi phù hợp.

Không tạo public Life validation API mới.

Không copy Entity death/revival numerical logic.

# 7. CB08 — External Eligibility

## 7.1. Objective

Cho phép caller quyết định actor có được thực hiện action tại thời điểm đánh giá hay không.

Combat chỉ nhận kết quả policy.

Không tự triển khai gameplay-specific restrictions.

## 7.2. Policy Contract

Conceptual:

```ts
export interface CombatActorEligibilityPolicy {
  readonly eligible: boolean;
}
```

Ví dụ:

```ts
{
  eligible: true
}
```

Hoặc:

```ts
{
  eligible: false
}
```

Không có default.

Policy phải explicit ở mỗi evaluation.

## 7.3. Eligible = True

Nếu:

- Source actor tồn tại.
- Actor Life State là alive.
- `eligible = true`.

Expected:

```text
status = admitted
reason = none
```

Không tạo executed action.

## 7.4. Eligible = False

Nếu:

- Source tồn tại.
- Source alive.
- `eligible = false`.

Expected:

```text
status = rejected
reason = source_ineligible
```

Không mutate state.

## 7.5. Caller-Owned Conditions

`eligible` có thể đại diện cho kết quả đánh giá:

- Class restrictions.
- Silence.
- Stun.
- Combat permission.
- Game-specific conditions.
- Temporary action restrictions.
- Other gameplay policies.

Nhưng Combat v0.4.1 không tự hiểu hoặc tính các điều kiện đó.

Không import Effect System.

Không import Skill System.

Không tạo Stun/Silence state.

Không tạo Condition Engine.

## 7.6. No Policy Callbacks

v0.4.1 chỉ nhận explicit boolean.

Không cho phép:

```ts
eligible: () => true
```

hoặc asynchronous eligibility callbacks.

Caller đánh giá condition trước và truyền boolean vào Combat Admission.

Điều này tránh:

- Hidden IO.
- Side effects.
- Reentrancy.
- Nondeterministic callbacks.
- Unclear policy execution ownership.

Nếu future capabilities cần policy adapter, thiết kế riêng khi có bằng chứng.

## 7.7. Invalid Policy

Reject:

- Missing eligible.
- `eligible: null`.
- `eligible: 1`.
- `eligible: "true"`.
- Getter-based eligible.
- Unknown extra fields.
- Inherited eligible.

Malformed policy phải throw `TypeError`.

Không dùng `source_ineligible` để che invalid policy.

# 8. CB09 — Combat Admission Result

## 8.1. Objective

Trả kết quả evaluation với status/reason rõ ràng.

Không chỉ trả boolean.

## 8.2. Public Types

Conceptual:

```ts
export type CombatAdmissionStatus =
  | "admitted"
  | "rejected";

export type CombatAdmissionReason =
  | "none"
  | "source_not_found"
  | "source_dead"
  | "source_ineligible";

export interface CombatAdmissionResult {
  readonly context: CombatActionContext;
  readonly status: CombatAdmissionStatus;
  readonly reason: CombatAdmissionReason;
}
```

Không thêm target-related rejection reasons trong v0.4.1.

Không tạo global rejection framework.

## 8.3. Public Function

Đề xuất:

```ts
evaluateCombatActionAdmission(
  context: CombatActionContext,
  entities: EntityCollection,
  sourceLife: EntityLifeState,
  policy: CombatActorEligibilityPolicy
): CombatAdmissionResult
```

Đây là operation:

- Pure.
- Synchronous.
- Stateless.
- Deterministic.
- Immutable-result producing.

Không cần một second `admitCombatAction()` function nếu semantics hoàn toàn giống nhau.

Một canonical resolver là đủ.

## 8.4. Successful Result

Input:

```text
sourceEntityId = player-1
source exists = true
life.status = alive
eligible = true
```

Expected:

```ts
{
  context: {
    actionId: "attack-001",
    actionType: "basic_attack",
    sourceEntityId: "player-1",
    target: {
      kind: "entity",
      entityId: "monster-1"
    }
  },
  status: "admitted",
  reason: "none"
}
```

Context trong result phải là validated, detached immutable snapshot.

Không trả raw mutable input reference.

## 8.5. Rejected Result

Actor dead:

```ts
{
  context: actionContext,
  status: "rejected",
  reason: "source_dead"
}
```

Actor missing:

```text
status = rejected
reason = source_not_found
```

External eligibility false:

```text
status = rejected
reason = source_ineligible
```

Không tự sinh target-validation reason.

## 8.6. Invalid vs Rejected

**Malformed input:**

```text
sourceLife.status = invalid
```

Expected:

`TypeError`

**Valid gameplay request, actor missing:**

```text
sourceEntityId = unknown
```

Expected:

`rejected / source_not_found`

**Valid gameplay request, actor dead:**

```text
sourceLife.status = dead
```

Expected:

`rejected / source_dead`

**Valid gameplay request, external ineligible:**

```text
eligible = false
```

Expected:

`rejected / source_ineligible`

Không trộn contract errors với gameplay rejections.

## 8.7. Deterministic Rejection Priority

Sau khi validate toàn bộ input structures và matching source identity:

1. Source actor does not exist.
2. Source actor is dead.
3. External eligibility is false.
4. Admitted.

Expected priority:

```text
source_not_found
source_dead
source_ineligible
none
```

Nếu actor dead và eligible=false:

`source_dead`

Nếu actor missing và eligible=false:

`source_not_found`

Malformed policy phải bị reject trước khi trả gameplay result.

Không phụ thuộc vào object key order.

## 8.8. Admission Is Not Execution

Result `admitted` không có nghĩa:

- Target exists.
- Target relation valid.
- Target alive.
- Target within range.
- Skill available.
- Resource cost affordable.
- Cooldown ready.
- Damage applied.
- Action committed.

Không tạo hidden execution token.

Không có persistent admission record.

Admission result không tự bảo đảm rằng actor vẫn alive tại thời điểm execution sau này.

Caller phải dùng current state và đúng subsequent validation/commit flow.
