# 1. Approved Architecture Decisions

Developer đã chốt:

## Decision A — Action Context Only

Combat không sở hữu persistent engaged/disengaged state ở v0.4.0.

Combat Foundation quản lý contract của **một action attempt độc lập**.

Không tạo:

- `CombatSession`
- `CombatWorld`
- `CombatRoom`
- `CombatActorStore`
- `CombatStateManager`

Encounter hoặc application controller về sau quản lý vòng đời trận chiến.

## Decision B — Basic Attack Independent From Skill

Combat phải có khả năng thực hiện Basic Attack trong những milestones tiếp theo mà không cần Skill System.

Không yêu cầu:

- Skill Definition.
- Skill Instance.
- Skill Rank.
- Skill Cooldown.
- Skill Activation.

Skill System về sau có thể sử dụng Combat resolution, nhưng không phải prerequisite của Combat.

## Decision C — Canonical Ownership

Giữ:

- Entity owns Entity Identity, Attributes, Resources, Life.
- Progression owns EXP, Level, Skill Rank, Points.
- RPG Core Kernel owns numerical calculations.
- Foundation owns Modules, Commands, Events, Lifecycle, Clock/RNG.
- Combat owns action admission, target policy và attack resolution orchestration.

Không tạo second numerical engine.

## Decision D — Game-Mode Neutral

Combat phải dùng được cho:

- Text RPG.
- 2D RPG.
- 2.5D RPG.
- Turn-Based RPG.

Không hardcode:

- Frame timing.
- Turn timing.
- Grid.
- Coordinates.
- Distance.
- Camera.
- Movement.
- Animation.

Time/turn/spatial policies chỉ bổ sung khi approved milestones thật sự cần.

# 6. CB02 — Combat Action Identity

## 6.1. Objective

Chuẩn hóa cách định danh một Combat Action Attempt.

Mỗi action có:

- `actionId`
- `actionType`
- `sourceEntityId`
- `target`

Không cần tạo action registry.

## 6.2. Action ID

`actionId` là opaque string identifier do caller cung cấp.

Ví dụ:

```text
attack-001
action-202
turn5-player1-attack
```

Requirements:

- Nonblank string.
- Không tự generate.
- Không auto-trim.
- Không auto-normalize.
- Không ép UUID.
- Không ép numeric ID.
- Không đọc Clock/RNG.

**Action ID uniqueness không được đảm bảo trên toàn hệ thống ở v0.4.0.**

Hai independent contexts có thể dùng cùng actionId.

Nếu game cần idempotency hoặc global action uniqueness, caller/runtime authority phải xử lý trong capability được thiết kế riêng.

Không tạo Action ID Store.

## 6.3. Action Type

`actionType` là nonblank opaque string.

Ví dụ:

```text
basic_attack
```

Không hardcode một enum giới hạn vào:

```text
basic_attack
skill
item
```

vì Skill, Item và các gameplay actions tương lai chưa được triển khai.

`actionType` chỉ mô tả caller intent.

**Một `actionType` hợp lệ về cấu trúc không chứng minh action đó đã được hỗ trợ hoặc có thể thực thi.**

Action admission và dispatch policies sẽ xác định điều đó ở milestone sau.

Không tự tạo Action Catalog hoặc handler registry mới.

## 6.4. Source Entity Identity

`sourceEntityId`:

- Nonblank string.
- Exact Entity ID.
- Không tự lookup Collection.
- Không tự tạo Entity.
- Không tự suy diễn Player/Monster.
- Không dùng Entity kind để quyết định quyền tấn công.

Ví dụ:

```text
sourceEntityId = player-1
```

hoặc:

```text
sourceEntityId = monster-1
```

Cả hai hợp lệ.

## 6.5. Target Reference

Ở v0.4.0 chỉ định nghĩa Entity target reference.

Conceptual type:

```ts
export interface CombatEntityTarget {
  readonly kind: "entity";
  readonly entityId: string;
}
```

Ví dụ:

```ts
{
  kind: "entity",
  entityId: "monster-1"
}
```

Không triển khai:

- Ground target.
- Area target.
- Position target.
- Cone target.
- Line target.
- Multiple targets.

Những target shapes sẽ được thiết kế khi có actual target/delivery capability.

Không tạo placeholder union cases chưa có behavior.

## 6.6. Identity Scope

Phải phân biệt:

```text
Action identity
  actionId

Actor identity
  sourceEntityId

Target identity
  target.entityId
```

Không dùng cùng một field để thay thế các identity domains.

Tuy nhiên:

```text
sourceEntityId == target.entityId
```

phải hợp lệ ở Foundation.

Self-targeting có thể cần cho healing, self effects hoặc kỹ năng tự thân trong tương lai.

CB02/CB04 không tự reject self-target.

Target relation policy thuộc v0.4.2.

# 7. CB03 — Combat Action Context

## 7.1. Objective

Tạo một immutable snapshot mô tả ý định thực hiện một combat action.

Đây không phải execution context toàn game.

Không duplicate Foundation GF14–GF16 Execution Context.

## 7.2. Public Contract

Conceptual shape:

```ts
export interface CombatActionRequest {
  readonly actionId: string;
  readonly actionType: string;
  readonly sourceEntityId: string;
  readonly target: CombatEntityTarget;
}

export interface CombatActionContext {
  readonly actionId: string;
  readonly actionType: string;
  readonly sourceEntityId: string;
  readonly target: CombatEntityTarget;
}
```

Hai interfaces cùng mô tả một structural schema, không được trở thành hai state authorities.

Có thể sử dụng type alias hoặc shared private shape để tránh duplicate validation.

Không tạo một hierarchy nhiều lớp cho request/context khi chúng chưa khác semantics.

## 7.3. Public Factory

Bổ sung:

```ts
createCombatActionContext(
  request: CombatActionRequest
): CombatActionContext
```

Ví dụ:

```ts
const action = createCombatActionContext({
  actionId: "attack-001",
  actionType: "basic_attack",
  sourceEntityId: "player-1",
  target: {
    kind: "entity",
    entityId: "monster-1"
  }
});
```

Expected:

```ts
{
  actionId: "attack-001",
  actionType: "basic_attack",
  sourceEntityId: "player-1",
  target: {
    kind: "entity",
    entityId: "monster-1"
  }
}
```

Returned object phải immutable và detached.

## 7.4. Context Ownership

Combat Action Context chỉ chứa những thông tin cần thiết cho một action attempt.

Không thêm:

```text
currentHp
currentMp
currentLevel
attributes
stats
skillRank
cooldown
buffs
debuffs
damage
criticalChance
defense
position
velocity
turnNumber
timestamp
```

Những dữ liệu đó thuộc module/state khác hoặc được cung cấp lúc resolution.

Không copy toàn bộ Entity Snapshot vào Combat Context.

Context giữ identity references, không lưu second authoritative Entity data.

## 7.5. Pure Creation

Factory phải:

- Synchronous.
- Deterministic.
- Side-effect free.
- Không dùng Clock.
- Không dùng RNG.
- Không generate ID.
- Không mutate request.
- Không lưu global state.
- Không publish events.
- Không gọi RPG Core Kernel.

Không cần tạo Foundation Execution Context để sử dụng factory.

## 7.6. Context Is Not Trusted Execution Receipt

Một Combat Action Context hợp lệ không có nghĩa:

- Actor tồn tại.
- Target tồn tại.
- Actor còn sống.
- Target là enemy.
- Target nằm trong range.
- Action được phép.
- Action đã thực thi.
- Damage đã xảy ra.

Không gọi kết quả tạo context là `admitted`, `committed` hoặc `executed`.

Không tạo action success outcome tại v0.4.0.

# 8. CB04 — Combat Contract Validation

## 8.1. Objective

Kiểm tra structural correctness và identity fields trước khi tạo Combat Action Context.

Validation phải tương thích nguyên tắc strict runtime boundaries đã áp dụng ở Group A.

## 8.2. Required Input Shape

Accepted request có đúng bốn required fields:

```text
actionId
actionType
sourceEntityId
target
```

Accepted target có đúng:

```text
kind
entityId
```

Không cho arbitrary metadata bags.

Không silently omit unknown fields.

Không tự thêm defaults.

## 8.3. Identity Validation

Bắt buộc:

- `actionId`: nonblank string.
- `actionType`: nonblank string.
- `sourceEntityId`: nonblank string.
- `target.entityId`: nonblank string.
- `target.kind`: exact `"entity"`.

Không:

- Coerce number to string.
- Normalize case.
- Trim and replace original values.
- Suy diễn sourceEntityId từ actionId.
- Suy diễn targetEntityId từ Entity Collection.
- Tạo fake `EntitySnapshot` để gọi `createEntity()`.

Có thể dùng một private identifier validation helper cho opaque IDs trong Combat.

Helper này không được tái triển khai toàn bộ Entity definition validation.

## 8.4. Closed Own-Data Records

Reject:

- Null.
- Arrays thay cho objects.
- Missing fields.
- Unknown extra fields.
- Symbol keys.
- Accessor-based required fields.
- Getter-based `target`.
- Getter-based `target.entityId`.
- Getter-based `target.kind`.
- Inherited required fields.
- Malformed nested target object.

Không invoke getters để validate.

Đối với plain/null-prototype records, giữ các accepted own-data semantics nhất quán với repository conventions.

Không tạo một serialization hoặc deep-clone framework mới.

## 8.5. Immutability

Factory phải tạo:

- Frozen root context.
- Frozen target reference.
- Detached target reference.
- No mutable alias to caller input.

Ví dụ:

```ts
const input = {
  actionId: "attack-001",
  actionType: "basic_attack",
  sourceEntityId: "player-1",
  target: {
    kind: "entity" as const,
    entityId: "monster-1"
  }
};

const context = createCombatActionContext(input);
```

Sau đó caller thay đổi:

```text
input.target.entityId
```

Expected:

```text
context.target.entityId
```

không đổi.

Không freeze caller-owned original input như side effect.

## 8.6. Structural vs Referential Validation

v0.4.0 chỉ validate:

**Structural identity validity.**

Không validate:

**Entity existence hoặc gameplay relations.**

Ví dụ:

```text
sourceEntityId = unknown-actor
target.entityId = unknown-target
```

Có thể tạo structurally valid context.

Việc actor/target có tồn tại trong Entity Collection hay không sẽ được xử lý ở Action Admission/Target Validation.

Không tạo fake Collection lookup để thay thế tương lai.

## 8.7. Invalid Input Behavior

Malformed input:

- Throw `TypeError`.
- Không trả partial context.
- Không ghi global state.
- Không phát event.
- Không gọi Kernel.

Không tạo rejection reason catalog dùng cho gameplay admission tại Foundation.

`TypeError` ở đây thể hiện malformed contract, khác với future `CombatActionRejection`.

## 8.8. No Authorization Semantics

Không cố xác thực caller chỉ bằng:

```text
actionId
sourceEntityId
```

Các IDs là structural identifiers, không phải authentication credentials.

Combat authorization/ownership policy có thể được caller hoặc later admission module đánh giá.

Không tạo security token mechanism.
