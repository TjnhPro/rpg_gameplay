# 4. GF06 — Runtime Context

## 4.1. Objective

Tạo runtime context từ một composition đã được GF05 xác nhận hợp lệ.

Conceptual flow:

```text
Module Registry
      │
      ▼
Module Configuration
      │
      ▼
Dependency Resolution (GF04)
      │
      ▼
Module Composition (GF05)
      │
      ▼
Runtime Context (GF06)
```

GF06 không thực hiện registration, selection hoặc dependency resolution lại.

## 4.2. Required Public Function

Cung cấp function tương đương:

```ts
const runtime = createGameplayRuntime(
  composition,
  lifecycleBindings
);
```

Tên function/type cuối cùng có thể điều chỉnh cho nhất quán với codebase.

Runtime Context phải chứa tối thiểu:

- Reference/snapshot an toàn của module composition.
- Ordered selected module identities.
- Runtime lifecycle status.
- Trạng thái lifecycle của từng module.
- Lifecycle bindings được cung cấp rõ ràng bởi caller, nếu có.

**Không đưa gameplay state, Core numerical state, engine state hoặc application services vào Runtime Context.**

## 4.3. Input Contract

Runtime creation phải:

1. Nhận một `ModuleComposition` hợp lệ.
2. Không mutate input composition.
3. Không thay đổi registry hoặc configuration bên ngoài.
4. Không tự register hoặc enable module.
5. Không khởi chạy lifecycle hooks khi vừa tạo context.
6. Không sử dụng global runtime singleton.
7. Không tự sinh runtime ID bằng random/clock.

Nếu cần identity cho caller, có thể dùng identity explicit do caller cung cấp, nhưng không bắt buộc một ID generator trong version này.

### Composition Trust Boundary

Runtime chỉ được tạo từ một composition bảo đảm các invariants GF05.

Không được tin tuyệt đối vào object chỉ vì TypeScript khai báo `ModuleComposition`: consumer JavaScript hoặc TypeScript cast có thể truyền dữ liệu giả.

Cần validation tại boundary đủ để reject malformed composition, duplicate IDs, mismatch giữa IDs và definitions, sai dependency order hoặc dependency không nằm trong composition.

Không viết lại dependency graph algorithm.

Ưu tiên reuse canonical GF04/GF05 validation/resolution logic qua internal reusable helper nếu cần. Nếu kiểm tra một forged composition không thể thực hiện mà không thay đổi public contract GF05, báo cáo blocker kèm reproduction thay vì âm thầm chấp nhận input sai.

## 4.4. Runtime State

Áp dụng lifecycle phases rõ ràng:

```text
created
initialized
running
stopped
disposed
failed
```

Ý nghĩa:

| State | Meaning |
|---|---|
| `created` | Context đã được tạo, chưa initialize modules |
| `initialized` | Toàn bộ selected modules initialize thành công |
| `running` | Toàn bộ selected modules start thành công |
| `stopped` | Runtime đã dừng hoạt động |
| `disposed` | Runtime đã kết thúc lifecycle và cleanup |
| `failed` | Lifecycle operation thất bại; không được báo ready/running |

Không đưa game-loop ticks, frame time hoặc scheduler vào state.

# 5. GF07 — Module Lifecycle

## 5.1. Objective

Quản lý vòng đời module theo thứ tự dependency đã được GF04/GF05 xác định.

Lifecycle stages:

1. Initialize
2. Start
3. Stop
4. Dispose

Mỗi stage phải có observable result.

Các lifecycle functions phải callable trực tiếp trong unit/functional tests.

## 5.2. Lifecycle Binding Contract

GF01 hiện chỉ định nghĩa module metadata và dependency declarations.

Không sửa `GameplayModuleDefinition` để thêm lifecycle hooks.

Thay vào đó, GF07 nhận các lifecycle implementations qua explicit bindings tương ứng với selected module IDs.

Ví dụ định hướng:

```ts
const lifecycleBindings = {
  inventory: {
    initialize: context => {},
    start: context => {},
    stop: context => {},
    dispose: context => {}
  }
};
```

Yêu cầu:

- Bindings được cung cấp bởi consumer.
- Không tự discovery bằng dynamic import.
- Không dùng global handler registry.
- Reject binding có ID không thuộc composition.
- Lifecycle callbacks là synchronous trong v0.1.3.
- Không cấp ngầm clock, RNG, network, database hoặc rendering services.

Các hooks có thể optional; hook vắng mặt được xem là không cần hành động cho stage tương ứng.

Lifecycle stage vẫn phải chuyển đổi đúng kể cả khi module không cần một hook cụ thể.

Synchronous callback có thể tác động tới tài nguyên do caller sở hữu. Runtime Context chỉ quản lý lifecycle progress, không tuyên bố các side effects bên ngoài đã trở thành immutable.

Nếu callback trả về Promise/thenable, không được silently xem đó là lifecycle success. Phải báo lỗi rõ ràng vì async lifecycle chưa được duyệt.

## 5.3. Required Public Functions

Cung cấp các functions tương đương:

```ts
initializeGameplayRuntime(runtime);

startGameplayRuntime(runtime);

stopGameplayRuntime(runtime);

disposeGameplayRuntime(runtime);
```

Tên cuối cùng có thể điều chỉnh, nhưng phải giữ trách nhiệm tách biệt và public function-first usage.

Không yêu cầu class-based API hoặc một `GameEngine` object có phương thức tự chạy.

## 5.4. Lifecycle Ordering

**Initialize:** dependency-first.

**Start:** dependency-first.

**Stop:** reverse dependency order.

**Dispose:** reverse dependency order.

Ví dụ composition:

```text
character
inventory → character
equipment → inventory
```

Expected:

```text
Initialize:
  character
  inventory
  equipment

Start:
  character
  inventory
  equipment

Stop:
  equipment
  inventory
  character

Dispose:
  equipment
  inventory
  character
```

Không tự resolve graph lần nữa.

Sử dụng resolved order có sẵn từ `ModuleComposition`.

Module disabled không được nhận lifecycle calls.

## 5.5. Lifecycle Transition Contract

Bình thường:

```text
created
   │ initialize
   ▼
initialized
   │ start
   ▼
running
   │ stop
   ▼
stopped
   │ dispose
   ▼
disposed
```

Cho phép dispose một runtime đã `initialized` mà chưa `start`, vì consumer có thể quyết định không chạy.

Cho phép dispose một runtime vừa `created` mà chưa initialize, không được gọi dispose hooks cho các module chưa từng initialized.

Trong v0.1.3, **không yêu cầu restart sau stop** hoặc reinitialize sau dispose.

Không được silently thực thi lại các lifecycle hooks đã hoàn thành.

Các transitions sai phải reject rõ ràng:

- Start trước initialize.
- Stop trước start.
- Initialize lần hai.
- Start sau dispose.
- Stop sau dispose.
- Dispose lại sau disposed.
- Tiếp tục initialize/start bình thường sau failure.

Illegal transition không được gọi bất kỳ hook nào.

## 5.6. Idempotency & No Double Execution

Không sử dụng idempotent no-op ngầm để che giấu lifecycle misuse.

Repeated transition không hợp lệ phải bị từ chối theo contract.

Mỗi hook chỉ được gọi khi stage tương ứng thực sự cần thực thi.

Không gọi hook hai lần chỉ vì consumer gọi nhầm transition.

## 5.7. Lifecycle Failure Handling

Đây là yêu cầu bắt buộc, không được chỉ viết happy-path tests.

Khi một hook throw hoặc trả kết quả không hợp lệ:

1. Không báo transition thành công.
2. Xác định module ID và lifecycle stage thất bại.
3. Dừng việc gọi các module tiếp theo trong cùng transition.
4. Bảo toàn thông tin những module/stages đã hoàn thành.
5. Runtime chuyển sang trạng thái failure có thể inspection.
6. Không tự động retry.
7. Không giả định có thể rollback external side effects.
8. Không bỏ qua lỗi để tiếp tục chạy.

Public transition result cần chứa trạng thái runtime sau transition và failure diagnostics nếu có.

Có thể dùng discriminated result, chẳng hạn:

```ts
type LifecycleTransitionResult =
  | {
      readonly ok: true;
      readonly runtime: GameplayRuntime;
    }
  | {
      readonly ok: false;
      readonly runtime: GameplayRuntime;
      readonly failure: LifecycleFailure;
    };
```

Đây là định hướng để bảo toàn observable progress kể cả khi hook thất bại; không bắt buộc dùng đúng tên type.

Malformed inputs và illegal transitions có thể throw `TypeError` theo convention hiện có. Hook failures phải có một cơ chế nhất quán, không khiến caller mất thông tin về completed stages.

### Failure Cleanup

Sau failure, không cho phép tiếp tục start hoặc initialize như không có lỗi.

Cho phép một bước dispose/cleanup rõ ràng đối với những module đã initialize thành công, theo reverse dependency order.

Không gọi cleanup hooks cho những module chưa hoàn thành initialization.

Nếu cleanup cũng thất bại, báo cáo diagnostic và progress thực tế; không tuyên bố `disposed` thành công khi còn cleanup failure.

Không tạo transaction engine, rollback framework hoặc automatic retry system.

## 5.8. Explicit Non-Goals

Không triển khai:

- Task queue.
- Game scheduler.
- Background workers.
- Runtime module hot-reload.
- Dynamic enable/disable.

# 6. GF08 — Runtime Isolation

## 6.1. Objective

Cho phép tạo và điều khiển nhiều runtime contexts độc lập trong cùng một process.

Ví dụ:

```ts
const runtimeA = createGameplayRuntime(composition, bindingsA);
const runtimeB = createGameplayRuntime(composition, bindingsB);
```

Mọi framework-owned lifecycle state phải thuộc đúng runtime.

## 6.2. Required Behavior

- Hai runtime cùng composition không chia sẻ lifecycle state.
- Initialize runtime A không initialize runtime B.
- Start/stop runtime A không làm đổi runtime B.
- Failure ở runtime A không làm runtime B thành failed.
- Dispose runtime A không dispose runtime B.
- Module lifecycle progress được theo dõi riêng theo runtime.
- Không dùng global mutable stores.
- Không dựa vào singleton context.
- Không tự truyền lifecycle hooks giữa các runtimes.

Nếu caller chủ động dùng chung một external object giữa hai bindings, L2 không chịu trách nhiệm cô lập object đó. Phải ghi rõ giới hạn này.

## 6.3. Immutable Runtime Snapshots

Ưu tiên mô hình chuyển đổi qua functions với explicit state và immutable snapshots.

Một lifecycle transition thành công trả về runtime state mới.

Runtime snapshots trước đó không bị mutate.

Inspection từ snapshot cũ phải phản ánh chính xác trạng thái tại thời điểm snapshot được tạo.

Không bắt buộc deep copy các immutable composition definitions.

Không tạo một state-management framework tổng quát.

## 6.4. No Hidden Side Effects

Runtime creation không được:

- Start timers.
- Create global event listeners.
- Spawn workers.
- Open sockets.
- Start a game loop.
- Generate random entities.
- Call game-specific code.

Chỉ những lifecycle callbacks được caller cung cấp mới được thực thi khi caller chủ động yêu cầu transition tương ứng.

# 7. GF09 — Runtime Inspection

## 7.1. Objective

Cho phép consumer kiểm tra runtime context mà không cần đọc internal mutable stores.

Inspection phải sử dụng public functions và trả về dữ liệu mô tả trạng thái thực tế.

## 7.2. Required Public Functions

Cung cấp function tương đương:

```ts
inspectGameplayRuntime(runtime);
```

Có thể bổ sung một module-state lookup function nếu thật sự hữu ích và không trùng trách nhiệm.

Không xây debugging server hoặc observability platform.

## 7.3. Inspection Contract

Snapshot trả về tối thiểu:

- Overall runtime status.
- Selected module IDs.
- Lifecycle state của từng selected module.
- Resolved module order.
- Failed stage/module và failure information nếu runtime failed.

Ví dụ conceptual:

```ts
{
  status: "running",
  moduleIds: ["character", "inventory"],
  modules: [
    {id: "character", status: "running"},
    {id: "inventory", status: "running"}
  ]
}
```

Chỉ là ví dụ API shape, không bắt buộc đúng tên fields.

Không đưa vào:

- HP/MP.
- Character/Game State.
- Gameplay Event Log.
- Command History.
- Network state.
- Clock timestamps.
- Debug counters không có contract.

## 7.4. Inspection Invariants

- Read-only.
- Deterministic.
- Không mutate runtime.
- Không trigger lifecycle hooks.
- Không gọi Core calculations.
- Không chứa writable references tới internal progress state.
- Returned data không thể bị mutate để thay đổi runtime.
- Module order nhất quán với composition.

Nếu có failure, inspection phải thể hiện failure thay vì trả status `running` hoặc `initialized` giả.

Inspection phải hoạt động với:

- Empty composition.
- Created runtime.
- Initialized runtime.
- Running runtime.
- Stopped runtime.
- Disposed runtime.
- Failed runtime.

# 8. Public API & Architecture Ownership

## 8.1. Ownership

GF01–GF05 tiếp tục thuộc Foundation Module owner đã có.

GF06–GF09 thuộc một canonical Runtime/Lifecycle owner của Foundation.

Cấu trúc tham khảo:

```text
src/
  foundation/
    modules/
      ...
    runtime/
      ...
  index.ts
```

Agent được điều chỉnh chi tiết tổ chức file theo codebase, nhưng phải giữ ownership rõ ràng.

Không nhân bản:

- Module Registry.
- Dependency Resolver.
- Composition builder.
- Lifecycle coordinator.
- Runtime state authority.

Không tạo nhiều execution engines hoặc một generic DI framework.

## 8.2. Public Exports

Public APIs mới phải được export từ:

`@rpg/gameplay`

Chỉ export các functions/types cần thiết cho GF06–GF09.

Giữ public root entrypoint duy nhất nếu không có bằng chứng cần subpath mới.

Không export private bookkeeping structures, internal state mutation helpers hoặc implementation-specific caches.

## 8.3. Existing API Preservation

Không thay đổi semantics:

- GF01 Module Contract.
- GF02 Module Registry.
- GF03 Module Enable/Disable.
- GF04 Dependency Resolution.
- GF05 Composition.

Chỉ cho phép additive public APIs thuộc GF06–GF09.

Không thêm hooks vào `GameplayModuleDefinition` đã được nghiệm thu.

Không thay đổi `ModuleComposition` để lưu runtime state.

Không sửa Core pin.

## 8.4. Runtime Is Not the Game Application

Phân biệt:

**L2 Gameplay Runtime Context**

- Selected module composition.
- Lifecycle coordination.
- Module-level status.
- Deterministic lifecycle ordering.

**L4 Game Application Runtime**

- Application loop.
- Frame scheduling.
- Client/server integration.
- Rendering.
- Network/persistence adapters.
- Scene management.

Không di chuyển trách nhiệm L4 vào L2.

- Operation bị reject.
- Không gọi start hooks.
- Runtime vẫn `created`.
- Inspection không báo `running`.

Kiểm tra thêm các invalid transitions có invariant khác thực sự cần bảo vệ, không tạo mọi tổ hợp trạng thái × operation nếu chỉ chứng minh cùng một lỗi.

## 9.5. Scenario D — Partial Failure

Composition có nhiều selected modules.

Một initialize/start hook được cấu hình throw.

Expected:

- Hook failure được ghi nhận chính xác.
- Modules trước failure được ghi nhận đã hoàn thành stage tương ứng.
- Modules sau failure không được gọi.
- Runtime không báo success.
- Cleanup có thể xử lý đúng những modules đã initialize.
- Không tự retry hoặc âm thầm rollback external side effects.

## 9.6. Scenario E — Inspection

Truy vấn runtime ở các lifecycle states hợp lệ.

Expected:

- Correct overall status.
- Correct selected modules.
- Correct per-module states.
- Correct order.
- No hooks invoked by inspection.
- Returned snapshot không mutate runtime.

## 9.7. Scenario F — Empty Composition

Tạo runtime từ composition rỗng.

Expected:

- Runtime creation hợp lệ.
- Initialize/start/stop/dispose transitions hợp lệ.
- Không có lifecycle hooks.
- Inspection trả danh sách module rỗng.

Không tự tạo default Foundation module.
