# 2. Approved Architecture & Ownership

## 2.1. Strict Layer Responsibilities

| Capability | Canonical Owner | Responsibility |
|---|---|---|
| Numerical calculations | L1 — RPG Core | Resource, cooldown, damage và các numerical operations |
| Skill Definition Contract | L2 — Skill | Schema, identity, structural validation |
| Skill Instance | L2 — Skill | Instance identity, immutable state |
| Skill Admission | L2 — Skill | Reusable admission evaluation và rejection result |
| Entity Identity / Collection | L2 — Entity | Actor identity và existence lookup |
| Entity Life State | L2 — Entity | Alive/dead state |
| Skill Rank State | L2 — Progression | Registered ranks và rank values |
| Combat Admission | L2 — Combat | Combat-specific actor/action admission |
| Skill Configuration | L3 | Concrete skill content và required rank |
| Game-specific Eligibility | L3 | Class, profession, unlock, game-mode restrictions |
| Runtime Coordination | L4 | Cung cấp current snapshots, gọi operations và xử lý results |
| Persistence / Concurrency | L4 / caller | Authoritative storage, freshness, synchronization |

**Single Canonical Owner là bắt buộc.**

Không tạo second ownership authority cho Entity, Skill Rank, Combat hoặc numerical calculations.

## 2.2. Skill vs Progression

Progression đã sở hữu:

```ts
EntitySkillRankState
getSkillRank()
```

Existing semantic:

- Registered skill có thể có rank `0`.
- Rank `0` nghĩa là registered nhưng chưa học.
- `getSkillRank()` trả `undefined` nếu skill chưa registered.
- Progression quản lý rank transitions và upgrades.

Skill không được:

- Lưu rank trong Skill Instance.
- Tạo `SkillRankState` mới.
- Tạo `getSkillRank()` thay thế.
- Tự upgrade rank.
- Tự grant skill points.
- Tự synchronize Progression State.

Skill chỉ được đánh giá rank eligibility từ **caller-supplied rank snapshot**.

Đối với ranked skills, caller lấy rank từ canonical Progression API.

Đối với rankless skills, admission không yêu cầu Progression.

Không thêm static dependency:

```text
skill → progression
```

## 2.3. Skill vs Combat

Combat hiện sở hữu:

```ts
evaluateCombatActionAdmission()
evaluateCombatTargetValidation()
resolveCombatAttack()
applyCombatAttackDamage()
```

Skill không được copy hoặc thay thế các operations này.

Phải phân biệt:

**Skill Admission**

Đánh giá:

- Skill instance có phù hợp actor không.
- Ownership policy có cho phép không.
- Skill rank có đáp ứng không.
- Actor có tồn tại và còn sống không.
- Game-specific eligibility có cho phép không.

**Combat Admission**

Đánh giá:

- Combat action context.
- Combat-specific actor eligibility.
- Combat action admission.
- Combat target validation.

Hai capabilities có semantic scope khác nhau.

Skill không được import Combat chỉ để sử dụng Combat admission.

Một số kiểm tra actor/life có thể trùng điều kiện về mặt dữ liệu, nhưng phải đọc từ canonical Entity state, không tạo duplicate Entity life authority hoặc một generic admission engine.

Không chỉnh sửa Combat APIs.

## 2.4. L3 Policy Boundary

L3 quyết định:

- Skill có yêu cầu rank không.
- Minimum required rank.
- Skill có phải được learned/unlocked không.
- Class/profession eligibility.
- Các điều kiện game-specific.
- Ownership authorization rules.

L2 chỉ nhận kết quả và configuration explicit để thực hiện reusable validation.

Không hardcode:

```text
Warrior can use Sword Skill
Mage can use Fireball
Level 10 unlocks Heal
Monster cannot use Player Skill
```

Không suy luận eligibility từ Entity `kind`.

# 5. SK06 — Skill Admission Contracts

## 5.1. Objective

Thiết kế một reusable admission operation đánh giá một Skill Instance trước khi activation.

Operation phải:

- Pure.
- Deterministic.
- Synchronous.
- Explicit inputs.
- Structured outputs.
- Immutable.
- Side-effect free.

Không tạo persistent Skill Activation State.

## 5.2. Proposed Public API

```ts
evaluateSkillActivationAdmission(
  definition: SkillDefinition,
  instance: SkillInstanceState,
  actorEntityId: string,
  entities: EntityCollection,
  actorLife: EntityLifeState,
  policy: SkillAdmissionPolicy
): SkillAdmissionResult
```

Tên và public contract này là target cho v0.5.1.

Input sử dụng existing public Entity và Skill contracts.

Không tạo alternate Entity Collection hoặc Entity Life contract.

## 5.3. Skill Admission Policy

Conceptual shape:

```ts
export interface SkillAdmissionPolicy {
  readonly owned: boolean;
  readonly eligible: boolean;
  readonly rank: SkillRankAdmissionPolicy;
}

export type SkillRankAdmissionPolicy =
  | {
      readonly mode: "not_required";
    }
  | {
      readonly mode: "required";
      readonly currentRank: number | null;
      readonly minimumRank: number;
    };
```

Ý nghĩa:

- `owned`: Caller-supplied ownership authorization assessment.
- `eligible`: Caller-supplied game-specific actor eligibility.
- `rank`: Explicit rank eligibility input.

`owned` không phải một mutable Skill-owned entitlement store. Nó là kết quả xác định quyền sở hữu từ authoritative caller/game policy.

Identity binding vẫn phải được L2 Skill kiểm tra độc lập, kể cả khi `owned === true`.

Rank mode:

- `not_required`: Skill không cần Progression rank.
- `required`: Skill cần rank đạt tối thiểu.

Không suy luận rank mode từ Skill ID hoặc Entity kind.

Không thêm arbitrary metadata bag.

Không chấp nhận unknown fields.

## 5.4. Admission Result

Conceptual public types:

```ts
export type SkillAdmissionStatus =
  | "admitted"
  | "rejected";

export type SkillAdmissionReason =
  | "none"
  | "actor_not_found"
  | "actor_dead"
  | "skill_not_owned"
  | "skill_rank_unregistered"
  | "skill_rank_too_low"
  | "actor_ineligible";

export interface SkillAdmissionResult {
  readonly instanceId: string;
  readonly skillId: string;
  readonly actorEntityId: string;
  readonly status: SkillAdmissionStatus;
  readonly reason: SkillAdmissionReason;
}
```

Không thêm execution receipts hoặc mutable tokens.

## 5.5. Admission Meaning

`admitted` chỉ có nghĩa:

> Skill-stage availability requirements của v0.5.1 đã được đáp ứng tại thời điểm evaluation.

Không có nghĩa:

- Đã đủ resource.
- Đã hết cooldown.
- Target hợp lệ.
- Combat admission đã thành công.
- Skill đã activation.
- Skill đã execute.
- Gameplay state đã commit.
- Caller đã được cấp quyền bảo mật.

Không dùng result như authorization token hoặc exactly-once execution receipt.

## 5.6. No Hidden State

Operation không được:

- Đọc Clock.
- Đọc RNG.
- Generate ID.
- Ghi Skill Instance.
- Ghi Progression.
- Ghi Entity.
- Tạo activation session.
- Publish Foundation event.
- Lưu kết quả admission vào global registry.

# 6. SK07 — Skill Ownership Validation

## 6.1. Objective

Đánh giá Skill Instance có thuộc actor đang yêu cầu sử dụng hay không.

Phải phân biệt:

```text
Definition identity
  skillId

Instance identity
  instanceId

Instance-bound actor identity
  instance.entityId

Requesting actor identity
  actorEntityId

External ownership permission
  policy.owned
```

Không gộp các identity domains.

## 6.2. Instance-to-Actor Binding

Input:

```text
instance.entityId = player-1
actorEntityId = player-1
```

Expected:

```text
Identity binding matches.
```

Input:

```text
instance.entityId = player-2
actorEntityId = player-1
```

Expected:

```text
status = rejected
reason = skill_not_owned
```

Không cho phép actor A sử dụng instance gắn actor B chỉ vì hai actor có cùng Skill Definition.

## 6.3. Definition-to-Instance Consistency

Definition và Instance phải tham chiếu cùng `skillId`.

Input:

```text
definition.skillId = fireball
instance.skillId = heal
```

Đây là **inconsistent contract**, không phải gameplay rejection hợp lệ.

Expected:

```text
TypeError
```

Không silently chọn một skillId.

Không convert hoặc rebind instance.

Không tự sửa Skill Instance State.

## 6.4. Explicit Ownership Eligibility

Input:

```text
instance.entityId = player-1
actorEntityId = player-1
policy.owned = false
```

Expected:

```text
status = rejected
reason = skill_not_owned
```

Input:

```text
instance.entityId = player-1
actorEntityId = player-1
policy.owned = true
```

Ownership stage passes.

Tuy nhiên các stages tiếp theo vẫn có thể reject.

## 6.5. Ownership vs Learned/Unlocked

Không đồng nhất:

```text
Instance exists
```

với:

```text
Skill learned/unlocked and authorized
```

Game-specific learned/unlocked rules do L3 xác định, dựa trên canonical state và policy tương ứng.

Ở v0.5.1, caller chịu trách nhiệm đưa kết quả vào explicit ownership/eligibility input.

Không tạo:

```text
SkillOwnershipStore
LearnedSkillRegistry
UnlockTree
SkillEntitlementManager
```

Không implement skill learning/unlocking transitions tại milestone này.

## 6.6. No Global Uniqueness Authority

Không đảm bảo:

- `instanceId` globally unique.
- Một actor chỉ có một instance của một skill.
- Một instance chỉ được evaluated một lần.
- Concurrent attempts được serialize.

Những vấn đề này thuộc caller/runtime authority hoặc future approved capability.

# 7. SK08 — Skill Rank Eligibility

## 7.1. Objective

Đánh giá rank requirement mà không tạo một second Skill Rank owner.

## 7.2. Canonical Rank Source

Existing Progression:

```ts
getSkillRank(
  state: EntitySkillRankState,
  skillId: string
): number | undefined
```

Caller chịu trách nhiệm đọc canonical Skill Rank State.

L2 Skill nhận explicit rank snapshot.

Không import Progression vào Skill production module.

Không tự đọc hoặc mutate rank map.

## 7.3. Rankless Skill

Input:

```ts
rank: {
  mode: "not_required"
}
```

Expected:

- Rank stage passes.
- Không yêu cầu Progression state.
- Không yêu cầu registered rank.
- Không tự gán effective rank bằng `1`.

Đây là cách hỗ trợ skills không sử dụng progression rank.

Không thay đổi Skill Instance để lưu rankless flag.

## 7.4. Ranked Skill

Input:

```ts
rank: {
  mode: "required",
  currentRank: 3,
  minimumRank: 2
}
```

Expected:

```text
Rank eligible.
```

Input:

```ts
rank: {
  mode: "required",
  currentRank: 1,
  minimumRank: 2
}
```

Expected:

```text
status = rejected
reason = skill_rank_too_low
```

Minimum rank là L3 configuration, không hardcode trong L2.

## 7.5. Registered but Unlearned

Progression cho phép registered skill có rank `0`.

Input:

```ts
rank: {
  mode: "required",
  currentRank: 0,
  minimumRank: 1
}
```

Expected:

```text
status = rejected
reason = skill_rank_too_low
```

Không chuyển rank `0` thành unregistered.

Không tự upgrade rank.

## 7.6. Unregistered Skill

Canonical Progression có thể trả:

```ts
undefined
```

Caller phải biểu diễn missing registration theo explicit contract:

```ts
rank: {
  mode: "required",
  currentRank: null,
  minimumRank: 1
}
```

Expected:

```text
status = rejected
reason = skill_rank_unregistered
```

`null` chỉ là admission representation cho missing registered rank.

Không lưu `null` vào canonical Progression state.

Không dùng `undefined` hoặc `0` thay thế `null` một cách ngầm định.

## 7.7. Rank Validation

`currentRank` khi là number phải:

- Finite.
- Safe integer.
- Nonnegative.

`minimumRank` phải:

- Finite.
- Positive safe integer.

Reject malformed inputs:

```text
currentRank = -1
currentRank = NaN
currentRank = Infinity
currentRank = 1.5

minimumRank = 0
minimumRank = -1
minimumRank = 2.5
minimumRank = Infinity
```

Malformed rank configuration:

```text
TypeError
```

Không coi malformed rank là legitimate gameplay rejection.

## 7.8. Rank Identity & Provenance

Rank snapshot không chứa một second EntitySkillRankState.

Caller phải bảo đảm rank được đọc từ:

```text
Correct Entity
Correct Skill ID
Current authoritative Progression snapshot
```

Skill admission result không tự chứng minh freshness hoặc provenance của supplied rank value.

Installed integration phải chứng minh caller lấy rank qua canonical `getSkillRank()`.

Không tự tạo rank cache hoặc trusted rank token.

# 8. SK09 — Actor Eligibility & Life

## 8.1. Objective

Kiểm tra actor tồn tại, còn sống và đáp ứng game-specific eligibility.

## 8.2. Entity Existence

Reuse:

```ts
getEntity(
  entities: EntityCollection,
  entityId: string
)
```

Không tự:

- Scan `collection.entities` bằng implementation riêng.
- Tạo Actor Registry.
- Tạo second Entity lookup.
- Create fake Entity.
- Infer actor existence từ Life State.

Input:

```text
actorEntityId = unknown-actor
```

Nếu Entity Collection không chứa actor:

```text
status = rejected
reason = actor_not_found
```

Đây là valid gameplay rejection.

Malformed collection vẫn phải fail theo canonical Entity validation.

## 8.3. Actor Life State

Reuse:

```ts
EntityLifeState
EntityLifeStatus
```

Allowed statuses:

```text
alive
dead
```

Nếu:

```text
actorLife.entityId = player-1
actorEntityId = player-1

actorLife.status = dead
```

Expected:

```text
status = rejected
reason = actor_dead
```

Nếu alive, life stage passes.

Không:

- Recalculate HP.
- Infer dead từ HP.
- Call `resolveEntityDefeat()`.
- Call `reviveEntity()`.
- Tạo `SkillLifeState`.

Entity giữ nguyên life-state authority.

## 8.4. Life Identity Consistency

Input:

```text
actorEntityId = player-1
actorLife.entityId = player-2
```

Expected:

```text
TypeError
```

Mismatch giữa supplied Life Snapshot và requesting actor là malformed invocation.

Không silently rebind Life State.

Không dùng Life Snapshot của actor khác.

## 8.5. Game-Specific Actor Eligibility

Caller cung cấp:

```ts
eligible: boolean
```

Ví dụ L3 có thể xét:

- Character class.
- Profession.
- Silence/restriction policy.
- Game mode.
- Special conditions.
- Skill-specific requirements.

Tuy nhiên L2 v0.5.1 chỉ tiêu thụ explicit eligibility assessment.

Không tự xây:

```text
Condition Engine
Class Rule Engine
Status Effect Engine
Restriction Engine
```

Input:

```text
actor exists
actor alive
skill owned
rank eligible
eligible = false
```

Expected:

```text
status = rejected
reason = actor_ineligible
```

## 8.6. Relation to Combat Admission

Combat đã có:

```ts
evaluateCombatActionAdmission()
```

Skill không được copy full Combat workflow.

Skill Actor Eligibility chỉ là requirement của việc sử dụng kỹ năng.

Combat-specific eligibility vẫn thuộc Combat.

Khi Skill Execution cần Combat sau này:

```text
Skill-stage admission
  → other required activation checks
  → Combat-stage admission (when applicable)
```

Không giả định Skill admission thay thế Combat admission.

Không gọi Combat tại v0.5.1.

# 9. SK10 — Activation Rejection & Outcomes

## 9.1. Objective

Trả structured admission result với deterministic rejection semantics.

## 9.2. Rejection Reasons

| Reason | Condition |
|---|---|
| `none` | Toàn bộ Skill admission requirements pass |
| `actor_not_found` | Actor không tồn tại trong Entity Collection |
| `actor_dead` | Actor có Life State là dead |
| `skill_not_owned` | Instance/actor mismatch hoặc ownership assessment false |
| `skill_rank_unregistered` | Ranked skill chưa registered |
| `skill_rank_too_low` | Registered rank nhỏ hơn minimum rank |
| `actor_ineligible` | External eligibility false |

Không thêm speculative reasons:

```text
insufficient_resource
cooldown_active
invalid_target
out_of_range
silenced_by_effect
cast_interrupted
execution_failed
```

Các mechanisms tương ứng chưa được triển khai trong v0.5.1.

Nếu một game-specific restriction trả false, sử dụng `actor_ineligible`, không tạo status-specific taxonomy quá sớm.

## 9.3. Fixed Rejection Priority

Khi nhiều điều kiện đều không hợp lệ về gameplay, sử dụng thứ tự:

```text
1. actor_not_found
2. actor_dead
3. skill_not_owned
4. skill_rank_unregistered
5. skill_rank_too_low
6. actor_ineligible
7. none
```

Ví dụ:

```text
Actor not found
Skill not owned
Rank too low
```

Expected:

```text
actor_not_found
```

Ví dụ:

```text
Actor alive
Skill not owned
Rank too low
```

Expected:

```text
skill_not_owned
```

Priority phải stable và deterministic.

Không phụ thuộc vào thứ tự property của input object.

## 9.4. Full Validation Before Admission Decision

Trước khi trả một gameplay rejection, operation phải validate toàn bộ supplied contracts.

Ví dụ:

```text
Actor not found
Rank configuration malformed
```

Expected:

```text
TypeError
```

Không được trả `actor_not_found` để che malformed rank policy.

Validation cần fail-closed, không mutate state.

## 9.5. Malformed vs Rejected

**Malformed Contract**

Ví dụ:

- Missing fields.
- Unknown fields.
- Invalid rank.
- Invalid identity shape.
- Definition/instance mismatch.
- Life/actor identity mismatch.
- Getter-based fields.
- Unsupported rank mode.

Expected:

```text
TypeError
```

**Valid Gameplay Rejection**

Ví dụ:

- Actor dead.
- Actor not found.
- Skill not owned.
- Rank insufficient.
- Actor ineligible.

Expected:

```text
status = rejected
reason = <specific reason>
```

Không throw exception cho normal gameplay rejection.

## 9.6. Accepted Result

Nếu mọi stage pass:

```ts
{
  instanceId: "skill-instance-001",
  skillId: "fireball",
  actorEntityId: "player-1",
  status: "admitted",
  reason: "none"
}
```

Không thêm:

```text
activationId
executionId
timestamp
resourceSpent
cooldownStarted
combatResult
```

Admission result không phải execution receipt.

## 9.7. Immutability

Returned result phải:

- Frozen.
- Detached.
- No mutable aliases.
- No exposed internal state.
- No caller-input mutation.

Nếu gọi lại với cùng inputs:

```text
Equivalent result.
```

Không yêu cầu reference equality.

## 9.8. No Automatic Transitions

Evaluation không được:

- Spend resources.
- Modify cooldown.
- Modify ranks.
- Mark learned/unlocked.
- Change Entity Life.
- Create Combat Action.
- Publish events.
- Generate activation ID.
- Reserve a skill instance.

No partial state changes on rejection.

## 9.9. Non-Authoritative Assessment

Admission result là snapshot assessment, không phải một transaction guarantee.

Giữa admission và activation, Entity, Rank hoặc game policy có thể thay đổi.

L4/caller chịu trách nhiệm cung cấp current authoritative snapshots và điều phối các validation/commit bước sau.

Không tạo locking, rollback hoặc transaction manager trong Skill để giải quyết stale state tại milestone này.

# 19. Completion Criteria

v0.5.1 đạt `CHECKPOINT_COMPLETE` khi:

- SK06–SK10 hoàn chỉnh.
- Actor/Skill Instance ownership được kiểm tra rõ ràng.
- Rank eligibility sử dụng canonical Progression data khi cần.
- Rankless Skill không phụ thuộc Progression.
- Entity existence và Life State sử dụng canonical Entity contracts.
- Game-specific eligibility được L3 cung cấp explicit.
- Rejection reasons deterministic và có priority rõ ràng.
- Malformed contracts không bị che bởi gameplay rejection.
- Admission không gây gameplay state changes.
- Không duplicate Combat Admission hoặc Skill Rank owner.
- Không tạo numerical calculation hoặc generic engine.
- Public contracts và installed consumer PASS.
- Existing regressions PASS.
- Exact-head CI PASS.

**Final Architecture Rule**

- **L1:** Canonical numerical calculations.
- **L2 Entity:** Actor Identity, Collection, Life.
- **L2 Progression:** Skill Rank State.
- **L2 Skill:** Skill-specific availability/admission.
- **L2 Combat:** Combat-specific admission/execution.
- **L3:** Skill requirements, configuration và eligibility policies.
- **L4:** Authoritative state supply, orchestration và execution commit.

Không được thay đổi ownership hoặc viết lại accepted modules để hoàn thành milestone.
