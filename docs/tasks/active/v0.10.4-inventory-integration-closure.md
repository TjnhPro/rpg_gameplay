### Ownership and non-goals

| Layer | Owns | Inventory restriction |
| --- | --- | --- |
| L1 `@rpg/core/kernel` | Game numerical work | No Core changes or new stats/damage/weight calculations. Counting integer item quantities is collection bookkeeping, not a second RPG math engine. |
| L2 Item | Definition/Instance/properties/structural validation/compatibility | Inventory invokes **accepted public Item APIs**; no copy of Item validators, creator or classifier. |
| L2 Inventory | Stable inventory identity, entry membership/quantity, snapshots, safe candidate changes | **Single canonical Inventory owner** in `src/modules/inventory/`. |
| L3 | Stack eligibility, limits, bag configuration, admission and future game policies | Passed as explicit data; nothing hardcoded for potion/weapon/player. |
| L4 | Authoritative current state, ID generation, ownership/authorization, commit/persistence, concurrency, UI | Pure L2 operations never claim atomic DB transfer, global uniqueness, or authoritative grant. |

Existing sibling modules (Entity/Skill/Combat/Effect/AI/Encounter/Progression/Foundation) stay untouched. Inventory must work as a headless optional module. No InventoryManager singleton, ItemStore, SQL/Redis, renderer, event bus, implicit RNG/clock/ID provider, system-specific alternative state owner or premature transfer coordinator.
