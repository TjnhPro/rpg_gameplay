# 1. Objective

Triển khai reusable **Skill Slots & Loadout** tại RPG Gameplay L2.

Hệ thống cho phép một Entity tổ chức Skill Instances vào các slot được định nghĩa bởi game, đồng thời bảo đảm các thao tác assignment, replacement và removal tạo ra immutable state transitions có thể kiểm chứng.

| ID | Feature | Responsibility |
|---|---|---|
| SK26 | Skill Loadout Foundation | Loadout identity, slot layout, immutable initial state |
| SK27 | Slot Assignment | Gán Skill Instance vào slot trống, kiểm tra identity và policy |
| SK28 | Slot Replacement | Thay Skill Instance trong occupied slot |
| SK29 | Slot Removal | Gỡ Skill Instance khỏi slot |
| SK30 | Loadout Validation & Integration | Structural validation, policy boundaries, installed package, regressions |

## Expected Consumer Outcome

Consumer có thể:

1. Tạo Loadout cho một Entity.
2. Định nghĩa danh sách slot từ L3 configuration.
3. Gán một Skill Instance vào slot trống.
4. Thay Skill Instance trong một occupied slot.
5. Gỡ Skill Instance khỏi slot.
6. Kiểm tra structural correctness của Loadout State.
7. Áp dụng game-specific slot restrictions qua explicit policies.
8. Giữ nguyên tất cả previous immutable snapshots.

Ví dụ:

```ts
const loadout = createSkillLoadoutState(player, {
  loadoutId: "primary",
  slotIds: ["slot-1", "slot-2", "slot-3"]
});

const assigned = assignSkillLoadoutSlot(
  loadout,
  "slot-1",
  fireballInstance,
  {
    eligible: true,
    allowDuplicateInstance: false
  }
);
```

Expected:

```text
status = applied
reason = none

loadout:
  entityId = player-1
  loadoutId = primary

slots:
  slot-1 → fireball instance
  slot-2 → empty
  slot-3 → empty
```

Original Loadout State không thay đổi.

**Một skill được gán vào slot không đồng nghĩa với việc skill có thể activation.**

# 2. Approved Architecture Decisions

## Decision A — Strict Layer Ownership

| Capability | Canonical Owner | Responsibility |
|---|---|---|
| Numerical calculations | L1 — RPG Core | Resource, damage, cooldown numerical calculations |
| Entity identity | L2 — Entity | Canonical Entity Snapshot và validation |
| Skill identity/instance | L2 — Skill | Skill Definition và Skill Instance |
| Skill rank/points | L2 — Progression | Learned rank, upgrade và points |
| Skill availability | L2 — Skill | SK06–SK10 admission |
| Resource costs | L2 — Skill + Entity/Core | Cost orchestration và canonical resource transitions |
| Cooldown lifecycle | L2 — Skill | Cooldown state và readiness |
| Activation/execution request | L2 — Skill | Activation result và execution handoff |
| Slot assignment state | L2 — Skill | Immutable slot references |
| Slot restrictions | L3 | Layout, allowed skills, duplicate policy, eligibility |
| Active loadout selection | L4 — Application | Current selected loadout và input binding |
| Loadout persistence | L4 — Application | Save/load, serialization, authoritative storage |
| Execution dispatch | L4 — Application | Gọi Skill Activation và Combat khi cần |

**Skill Loadout chỉ sở hữu việc sắp xếp references tới Skill Instances.**

Không trở thành owner của Skill Instance, Rank, Cooldown, Resource hoặc Combat.

## Decision B — Loadout References Skill Instances

Loadout lưu:

```text
slotId → instanceId
```

Không lưu bản sao:

```text
SkillDefinition
SkillInstanceState
EntitySnapshot
SkillRankState
SkillCooldownState
EntityResourceState
```

`instanceId` là canonical reference tới Skill Instance do caller quản lý.

Không lưu nguyên Skill Instance trong từng slot.

## Decision C — Loadout Assignment Is Not Skill Admission

Phải phân biệt:

**Loadout Eligibility**

> Skill Instance có được phép nằm trong slot này theo game rules không?

**Skill Activation Admission**

> Actor hiện có được phép sử dụng Skill Instance không?

Hai operations không đồng nghĩa.

Loadout assignment không được bắt buộc actor:

- Đang alive.
- Đủ resource.
- Hết cooldown.
- Có valid target.
- Đã vượt qua Combat admission.

L3/caller có thể áp các hạn chế learned/rank/class khi gán slot, nhưng phải cung cấp kết quả qua explicit policy.

Không tự gọi `evaluateSkillActivationAdmission()`.

## Decision D — Layout Belongs to L3

L3 quyết định:

- Loadout có bao nhiêu slot.
- Slot IDs là gì.
- Slot nào cho phép skill nào.
- Skill nào có thể được gán vào slot.
- Có cho phép duplicate instance trong nhiều slot không.
- Có cho phép thay thế/gỡ slot trong trạng thái hiện tại không.

L2 cung cấp structural schema và deterministic transitions.

Không hardcode:

```text
1–8 hotbar slots
weapon slots
passive slots
active slots
primary bar
secondary bar
```

Không tự suy luận slot type từ tên slot.

## Decision E — Duplicate Instance Is L3 Policy

Một game có thể cho phép cùng một Skill Instance xuất hiện trong nhiều slot.

Game khác có thể cấm.

Vì vậy **không hardcode một instance chỉ được nằm trong một slot**.

L3 cung cấp explicit:

```ts
allowDuplicateInstance: boolean
```

L2 thực thi chính sách này ở assignment/replacement.

Structural Loadout validation không được coi duplicate instance references là malformed state.

Slot IDs thì bắt buộc unique trong cùng một loadout.

## Decision F — Multiple Loadouts Are Independent

Một Entity có thể có nhiều loadouts:

```text
player-1 / primary
player-1 / secondary
```

Mỗi Loadout là immutable state riêng.

v0.5.5 không sở hữu:

- Active loadout pointer.
- Loadout switching lifecycle.
- Global loadout registry.
- Account-wide skill bars.

L4 quyết định loadout nào đang active.

## Decision G — No Runtime Loadout Manager

Không tạo:

```text
SkillBarManager
LoadoutRegistry
LoadoutController
SlotStore
SkillInventory
AbilityInventory
ActiveLoadoutManager
GlobalSkillCatalog
```

Không tạo generic equipment/inventory engine.

# 5. SK26 — Skill Loadout Foundation

## 5.1. Objective

Tạo immutable Loadout State với Entity association, Loadout identity và ordered slots.

## 5.2. Loadout Layout Contract

Proposed public contract:

```ts
export interface SkillLoadoutLayout {
  readonly loadoutId: string;
  readonly slotIds: readonly string[];
}
```

L3 cung cấp concrete layout.

Ví dụ:

```ts
{
  loadoutId: "primary",
  slotIds: [
    "slot-1",
    "slot-2",
    "slot-3",
    "slot-4"
  ]
}
```

Không lưu slot display names, icons, keybindings hoặc UI coordinates trong L2.

## 5.3. Loadout Identity

`loadoutId`:

- Nonblank string.
- Exact caller-supplied ID.
- Case-sensitive.
- Không normalize.
- Không generate.
- Không ép UUID.

Uniqueness scope:

```text
entityId + loadoutId
```

Caller/L4 chịu trách nhiệm uniqueness giữa những loadout snapshots độc lập.

Không tạo global loadout registry.

## 5.4. Slot Identity

`slotId`:

- Nonblank string.
- Exact caller-supplied ID.
- Case-sensitive.
- Unique trong cùng loadout.
- Không generate.
- Không auto-number.
- Không hardcode maximum slot count.

Accept:

```text
slot-1
slot-2
primary-attack
secondary-skill
custom-slot
```

Không suy luận slot type từ identifier.

## 5.5. Empty Layout

```ts
{
  loadoutId: "primary",
  slotIds: []
}
```

Là valid structural input.

Expected:

- Loadout có zero slots.
- Không tự thêm default slots.
- Assignment vào unknown slot trả structured rejection.

Không tự ép minimum hoặc maximum slot count.

L3 quyết định layout có meaningful trong game hay không.

## 5.6. Slot Contract

```ts
export interface SkillLoadoutSlot {
  readonly slotId: string;
  readonly instanceId: string | null;
}
```

Ý nghĩa:

```text
instanceId = null
  Slot empty.

instanceId = nonblank string
  Slot refers to a Skill Instance.
```

Không lưu:

```text
skillId
rank
cooldown
resourceCost
target
effect
```

Những dữ liệu đó đã có owner riêng.

## 5.7. Loadout State Contract

```ts
export interface SkillLoadoutState {
  readonly entityId: string;
  readonly loadoutId: string;
  readonly slots: readonly SkillLoadoutSlot[];
}
```

Requirements:

- Entity ID exact.
- Loadout ID exact.
- Stable slot order.
- Unique slot IDs.
- Immutable slots.
- No hidden metadata.
- No duplicated Skill Instance objects.

## 5.8. Public Factory

```ts
createSkillLoadoutState(
  entity: EntitySnapshot,
  layout: SkillLoadoutLayout
): SkillLoadoutState
```

Factory:

1. Validate Entity qua canonical `createEntity()`.
2. Validate layout.
3. Validate all slot IDs.
4. Reject duplicate slot IDs.
5. Tạo slots với `instanceId: null`.
6. Return detached frozen state.

Expected:

```ts
{
  entityId: "player-1",
  loadoutId: "primary",
  slots: [
    {slotId: "slot-1", instanceId: null},
    {slotId: "slot-2", instanceId: null},
    {slotId: "slot-3", instanceId: null}
  ]
}
```

## 5.9. No Runtime Binding

Factory không:

- Query Skill Instance registry.
- Query Progression.
- Evaluate Skill Admission.
- Read Clock.
- Generate IDs.
- Publish events.
- Create active loadout.
- Register keybindings.
- Modify Entity State.

# 6. SK27 — Slot Assignment

## 6.1. Objective

Gán Skill Instance vào một empty slot.

Không overwrite occupied slots.

## 6.2. Assignment Policy

Proposed:

```ts
export interface SkillSlotAssignmentPolicy {
  readonly eligible: boolean;
  readonly allowDuplicateInstance: boolean;
}
```

`eligible`:

- Explicit L3/caller eligibility assessment.
- Có thể bao gồm slot restrictions, learning requirements hoặc game-specific rules.
- Không phải authentication credential.

`allowDuplicateInstance`:

- `true`: cùng instance được phép nằm trong nhiều slot.
- `false`: không cho phép duplicate reference trong cùng loadout.

Không infer policy từ slotId.

Không tạo Skill Requirement Engine.

## 6.3. Public API

```ts
assignSkillLoadoutSlot(
  state: SkillLoadoutState,
  slotId: string,
  instance: SkillInstanceState,
  policy: SkillSlotAssignmentPolicy
): SkillLoadoutMutationResult
```

## 6.4. Entity Identity

Required:

```text
state.entityId == instance.entityId
```

Nếu mismatch:

```text
TypeError
```

Không gán Skill Instance của player khác.

Không tự đổi Entity ownership.

## 6.5. Empty Slot Assignment

Input:

```text
Loadout:
  player-1 / primary

Slot:
  slot-1 → empty

Skill Instance:
  instanceId = fireball-instance
  entityId = player-1

Policy:
  eligible = true
  allowDuplicateInstance = false
```

Expected:

```text
status = applied
reason = none

slot-1 → fireball-instance
```

Original state unchanged.

## 6.6. Occupied Slot

Input:

```text
slot-1 → fireball-instance
```

Caller attempts:

```text
assign heal-instance to slot-1
```

Expected:

```text
status = rejected
reason = slot_occupied
```

Không silently overwrite.

Caller phải sử dụng explicit replacement operation.

## 6.7. Unknown Slot

Input:

```text
slotId = slot-99
```

Nếu slot không tồn tại:

```text
status = rejected
reason = slot_not_found
```

Không tự thêm slot mới.

## 6.8. Ineligible Assignment

Policy:

```ts
{
  eligible: false,
  allowDuplicateInstance: false
}
```

Expected:

```text
status = rejected
reason = slot_ineligible
```

Không sửa loadout.

## 6.9. Duplicate Instance Policy

Current:

```text
slot-1 → fireball-instance
slot-2 → empty
```

Attempt:

```text
assign fireball-instance to slot-2
```

Nếu:

```text
allowDuplicateInstance = false
```

Expected:

```text
rejected / instance_already_assigned
```

Nếu:

```text
allowDuplicateInstance = true
```

Expected:

```text
applied / none
```

Result:

```text
slot-1 → fireball-instance
slot-2 → fireball-instance
```

Cả hai slots chỉ tham chiếu cùng một canonical Skill Instance.

Không tạo Skill Instance bản sao.

Không tự tạo independent cooldown cho từng slot.

## 6.10. No Hidden Ownership Authority

Caller-supplied Skill Instance vẫn chỉ là immutable structural reference.

`eligible: true` không chứng minh instance thực sự đã learned/unlocked.

L3/L4 chịu trách nhiệm resolve authoritative permission trước khi gọi API.

Không tạo Skill Ownership Store.

# 7. SK28 — Slot Replacement

## 7.1. Objective

Thay Skill Instance đang nằm trong một occupied slot bằng instance khác.

## 7.2. Public API

```ts
replaceSkillLoadoutSlot(
  state: SkillLoadoutState,
  slotId: string,
  instance: SkillInstanceState,
  policy: SkillSlotAssignmentPolicy
): SkillLoadoutMutationResult
```

## 7.3. Successful Replacement

Current:

```text
slot-1 → fireball-instance
slot-2 → heal-instance
```

Replace:

```text
slot-1 → lightning-instance
```

Expected:

```text
status = applied
reason = none

slot-1 → lightning-instance
slot-2 → heal-instance
```

Không thay đổi slot order.

Không mutate original state.

## 7.4. Empty Slot Replacement

Input:

```text
slot-1 → empty
```

Replace with:

```text
fireball-instance
```

Expected:

```text
rejected / slot_empty
```

Không silently chuyển `replace` thành `assign`.

## 7.5. Same Instance Replacement

Input:

```text
slot-1 → fireball-instance
```

Replace with:

```text
fireball-instance
```

Expected:

```text
rejected / same_instance
```

Đây là explicit no-change rejection.

Không tạo giả transition với state mới nhưng không có thay đổi thực tế.

## 7.6. Duplicate Policy During Replacement

Current:

```text
slot-1 → fireball-instance
slot-2 → heal-instance
```

Attempt:

```text
replace slot-2 with fireball-instance
```

Nếu duplicate prohibited:

```text
rejected / instance_already_assigned
```

Nếu allowed:

```text
applied / none
```

Slot-1 vẫn giữ tham chiếu cũ.

Không di chuyển instance khỏi slot-1 ngầm định.

## 7.7. No Side Effects on Replaced Skill

Replacement không:

- Delete Skill Instance.
- Remove learned Skill Rank.
- Reset cooldown.
- Refund resources.
- Cancel active Combat action.
- Remove effects.
- Destroy skill content.

Loadout chỉ thay đổi reference trong slot.

## 7.8. No Implicit Move/Swap

Không tạo:

```text
moveSkillSlot()
swapSkillSlots()
reorderSkillSlots()
```

v0.5.5 chỉ yêu cầu assignment, replacement và removal.

Nếu game cần atomic move/swap, phải có approved semantics riêng.

Không giả lập atomic move bằng hidden multi-operation transaction.

## 8.9. No Skill Destruction

Removal không:

- Destroy Skill Instance.
- Reset rank.
- Reset cooldown.
- Cancel activation.
- Modify resources.
- Unlearn skill.
- Emit gameplay effects.

Không tạo cascade cleanup engine.

# 9. SK30 — Loadout Validation & Outcomes

## 9.1. Objective

Cung cấp một canonical Loadout structural validation boundary và deterministic mutation results.

## 9.2. Public Validator

Proposed:

```ts
validateSkillLoadoutState(
  state: SkillLoadoutState
): SkillLoadoutState
```

Operation phải:

- Validate complete state.
- Preserve exact identities.
- Preserve slot order.
- Reject malformed records.
- Return a detached frozen snapshot.

Không mutate input.

Không truy cập global catalog.

## 9.3. Structural Invariants

Loadout must have exact fields:

```text
entityId
loadoutId
slots
```

Mỗi slot có exact:

```text
slotId
instanceId
```

Reject:

- Missing fields.
- Unknown fields.
- Symbol keys.
- Accessor/getter fields.
- Inherited required fields.
- Invalid entity/loadout IDs.
- Invalid slot IDs.
- Duplicate slot IDs.
- Invalid instance references.
- Sparse arrays.
- Arrays with extra own fields.
- Malformed nested slots.

Không invoke getters.

Không silently drop fields.

## 9.4. Instance Reference Validation

Allowed:

```text
instanceId = null
```

hoặc:

```text
instanceId = nonblank string
```

Không cho phép:

```text
instanceId = undefined
instanceId = number
instanceId = ""
instanceId = {}
```

**Duplicate nonnull instance IDs không phải structural error.**

Duplicate policy thuộc L3.

## 9.5. Referential Validity Limit

Một structurally valid Loadout có thể chứa:

```text
instanceId = no-longer-existing-instance
```

Validator không thể kết luận reference còn tồn tại vì v0.5.5 không sở hữu Skill Instance registry.

Do đó:

- Structural validation PASS nếu ID hợp lệ.
- Không claim referential integrity với external instance catalog.
- L4/caller chịu trách nhiệm resolve references khi load/persist/use.

Không tự tạo fake catalog để validate.

## 9.6. Mutation Operations

Proposed operation type:

```ts
export type SkillLoadoutMutationOperation =
  | "assign"
  | "replace"
  | "remove";
```

Proposed reasons:

```ts
export type SkillLoadoutMutationReason =
  | "none"
  | "slot_not_found"
  | "slot_ineligible"
  | "slot_occupied"
  | "slot_empty"
  | "same_instance"
  | "instance_already_assigned";
```

## 9.7. Mutation Result

Proposed discriminated union:

```ts
export type SkillLoadoutMutationResult =
  | {
      readonly status: "applied";
      readonly reason: "none";
      readonly operation: SkillLoadoutMutationOperation;
      readonly slotId: string;

      readonly beforeInstanceId: string | null;
      readonly afterInstanceId: string | null;

      readonly state: SkillLoadoutState;
    }
  | {
      readonly status: "rejected";
      readonly reason: Exclude<
        SkillLoadoutMutationReason,
        "none"
      >;
      readonly operation: SkillLoadoutMutationOperation;
      readonly slotId: string;

      readonly beforeInstanceId: string | null;
      readonly afterInstanceId: null;

      readonly state: null;
    };
```

Success result:

- Contains final immutable Loadout State.
- Exact operation.
- Before/after slot references.
- Does not contain Skill Instance snapshots.

Rejected result:

- `state = null`.
- No partial candidate.
- `beforeInstanceId` là current value của target slot nếu slot tồn tại.
- Nếu slot không tồn tại, `beforeInstanceId = null`.
- `afterInstanceId = null` vì không có mutation.

## 9.8. Malformed vs Rejected

**Malformed input:**

```text
TypeError
```

Ví dụ:

- Invalid Loadout schema.
- Invalid Skill Instance.
- Entity identity mismatch.
- Invalid policy shape.
- Invalid slot ID type.

**Valid gameplay rejection:**

```text
status = rejected
reason = specific reason
```

Ví dụ:

- Slot not found.
- Slot occupied.
- Slot empty.
- Assignment ineligible.
- Duplicate instance prohibited.

Không throw exception cho ordinary gameplay rejection.

## 9.9. Full Validation Before Rejection

Phải validate toàn bộ supplied contracts trước khi chọn rejection reason.

Ví dụ:

```text
slotId = unknown-slot

policy:
  eligible = "yes"
```

Expected:

```text
TypeError
```

Không trả `slot_not_found` và bỏ qua malformed policy.

## 9.10. Rejection Priority

Sau full structural validation:

```text
1. slot_not_found
2. slot_ineligible
3. operation-specific state reason
4. instance_already_assigned
5. none
```

Operation-specific reasons:

```text
assign:
  slot_occupied

replace:
  slot_empty
  same_instance

remove:
  slot_empty
```

Duplicate instance evaluation chỉ áp dụng cho assign/replace.

Nếu replacement là same instance ở target slot, trả `same_instance`, không tự coi đó là duplicate ở slot khác.

Không thay đổi priority theo property enumeration order.

## 9.11. Immutable Results

Mọi returned objects:

- Frozen.
- Detached.
- No mutable aliases.
- No mutation of caller state.
- Stable slot order.
- Deterministic.

Không freeze original caller input như side effect.

## 9.12. No Automatic Activation

Mutation success chỉ có nghĩa:

```text
Loadout slot reference updated.
```

Không có nghĩa:

```text
Skill learned.
Skill admitted.
Skill activated.
Resource paid.
Cooldown started.
Combat executed.
```

Không tạo activation request từ assignment.
