# 1. Objective

Mở rộng Combat System để **resolve kết quả một đòn đánh** sau khi source actor và target đã vượt qua các validation stages.

Triển khai:

| ID | Feature | Responsibility |
|---|---|---|
| CB16 | Attack Resolution Contract | Attack inputs, preconditions, identity và immutable result |
| CB17 | Hit & Dodge Resolution | Delegate hit/dodge cho RPG Core Kernel |
| CB18 | Critical Resolution | Delegate critical chance/bonus, bảo toàn RNG semantics |
| CB19 | Damage & Mitigation | Delegate B0/B1/mitigation cho Kernel |
| CB20 | Attack Integration & Verification | Stage ordering, diagnostics, deterministic replay, installed consumers |

## 1.1. Expected Outcome

Một consumer có thể:

1. Tạo Combat Action Context.
2. Evaluate Actor Admission.
3. Validate Target.
4. Cung cấp numerical attack configuration.
5. Cung cấp caller-owned RNG.
6. Resolve Hit/Dodge.
7. Nếu đòn đánh trúng, resolve Critical.
8. Tính raw damage thông qua Kernel Damage B0.
9. Tính damage bonuses qua Kernel Damage B1.
10. Tính mitigation qua Kernel.
11. Nhận final damage và các calculation diagnostics.
12. Không thay đổi Entity Resource/Life State.

**v0.4.3 chỉ tính toán kết quả đòn đánh.**

Không apply damage.

Không tự trừ HP.

Không resolve death.

## 1.2. Fundamental Boundary

```text
Combat Action Context
         │
         ▼
Actor Admission (v0.4.1)
         │
         ▼
Target Validation (v0.4.2)
```

# 5. CB16 — Attack Resolution Contract

## 5.1. Objective

Cung cấp typed contract cho một numerical attack request.

Tách rõ:

1. Accepted actor-stage admission.
2. Accepted target-stage validation.
3. Attack numerical inputs.
4. Caller-owned RNG.
5. Attack calculation results.

## 5.2. Required Stage Inputs

Conceptual public function:

```ts
resolveCombatAttack(
  admission,
  targetValidation,
  attackInput,
  executionContext
);
```

Trong đó:

- `admission`: actual CB09 Combat Admission Result.
- `targetValidation`: actual CB15 Target Validation Result.
- `attackInput`: caller-configured numerical attack inputs.
- `executionContext`: accepted Foundation execution context có RNG provider khi cần.

Tên API có thể điều chỉnh theo conventions đã được triển khai, nhưng phải chỉ có **một canonical attack resolver**.

Không tạo separate `BasicAttackEngine`.

## 5.3. Stage Preconditions

Bắt buộc:

```text
Admission.status = admitted
TargetValidation.status = accepted
```

Nếu Actor Admission rejected:

- Không resolve attack.
- Không gọi RNG.
- Không gọi Kernel damage functions.
- Không trả successful attack result.

Nếu Target Validation rejected:

- Không resolve attack.
- Không gọi RNG.
- Không gọi Kernel damage functions.

Invalid stage precondition phải reject bằng `TypeError`.

Không chuyển:

```text
source_dead
```

thành:

```text
attack_missed
```

Các rejection reasons trước đó vẫn thuộc canonical owners của chúng.

## 5.4. Action Identity Consistency

Admission và Target Validation phải tham chiếu cùng một action.

Kiểm tra exact:

- `actionId`
- `actionType`
- `sourceEntityId`
- `target.kind`
- `target.entityId`

Không chỉ so sánh `actionId`.

Ví dụ:

```text
Admission actionId = attack-001
TargetValidation actionId = attack-002
```

Expected:

`TypeError`

Không resolve bằng cách lấy context của một phía và bỏ qua phía còn lại.

## 5.5. Combat Action Type

`actionType` tiếp tục là opaque string theo v0.4.0.

Không hardcode Skill definitions.

Không mặc định rằng mọi `actionType` hợp lệ đều có thể gây damage.

Việc caller gọi explicit `resolveCombatAttack()` thể hiện operation là một attack-resolution attempt; caller phải chịu trách nhiệm chọn đúng action type theo game rules.

Ví dụ Basic Attack:

```text
actionType = basic_attack
```

được dùng trong acceptance scenarios.

Không tạo generic Action Type Registry.

Không tự triển khai Skill execution routing.

## 5.6. Numerical Input Contract

Conceptual:

```ts
interface CombatAttackInput {
  readonly hit: {
    readonly dodgeChance: number;
    readonly eligible: boolean;
    readonly rule: ProbabilityRule;
  };

  readonly critical: {
    readonly chance: number;
    readonly bonus: number;
    readonly eligible: boolean;
    readonly rule: ProbabilityRule;
  };

  readonly damage: {
    readonly base: number;
    readonly rank: number;
    readonly perRank: number;

    readonly scaling: readonly {
      readonly source: string;
      readonly value: number;
      readonly coefficient: number;
    }[];

    readonly flat: {
      readonly definition: number;
      readonly additional: number;
      readonly resolved: number;
    };

    readonly bonuses: readonly ResolvedDamageBonus[];
  };

  readonly mitigation:
    Omit<MitigationCalculationInput, "damage">;
}
```

Đây là conceptual shape, không bắt buộc tạo toàn bộ interfaces mới nếu có thể compose Kernel types chính xác.

Ưu tiên:

- Import public Kernel types.
- Không copy numerical rule schemas.
- Không thêm numerical fields chưa được sử dụng.
- Không tạo calculator-specific game defaults.

## 5.7. Numerical Policy Ownership

Caller cung cấp:

- Dodge chance.
- Critical chance/bonus.
- Damage base.
- Rank.
- Per-rank scaling.
- Attribute/stat scaling inputs.
- Already-resolved flat contributions.
- Already-resolved bonuses.
- Defense rating.
- Mitigation rule.
- Level values khi mitigation policy cần.

Không hardcode:

```text
Basic Attack Damage = 10
Crit Chance = 5%
Crit Multiplier = 1.5
Defense Formula = ...
```

Không tự đọc Entity Stats theo hardcoded keys như:

```text
attackPower
defense
criticalChance
```

Game-specific stat mapping thuộc caller.

## 5.8. Damage Input Mapping

Combat được phép chuyển numerical snapshots sang Kernel input structure.

Ví dụ:

```text
Caller ordered scaling values
          │
          ▼
Kernel DamageB0Input accessors
          │
          ▼
calculateDamageB0()
```

Adapter chỉ:

- Capture values.
- Preserve declared order.
- Resolve exact source lookup.
- Expose synchronous numeric accessors.
- Validate types/identity.

Adapter không được:

- Nhân scaling coefficients.
- Tính rank factor.
- Cộng flat damage.
- Cộng bonuses.
- Tính mitigation.

Mọi numerical arithmetic đó thuộc Kernel.

Nếu chọn một dạng public input khác để reuse Kernel contracts trực tiếp, phải giữ những invariants tương đương.

## 5.9. No Duplicate Skill Rank Authority

Damage `rank` là numerical input do caller cung cấp.

Combat không:

- Tạo Skill Rank State.
- Lookup Skill Rank.
- Upgrade Skill Rank.
- Normalize rank theo Skill Definition.

Basic Attack có thể dùng caller-supplied rank 1.

Không tự tạo một second rank progression system.

# 6. CB17 — Hit & Dodge Resolution

## 6.1. Objective

Resolve hit/dodge bằng canonical:

`calculateHit()`

## 6.2. Kernel Delegation

Combat truyền caller-supplied:

- `dodgeChance`
- `eligible`
- `rule`
- Lazy RNG provider

vào Kernel.

Không tự tính:

```text
roll < dodgeChance
```

trong Combat production source.

Kernel sở hữu so sánh xác suất.

## 6.3. Hit Semantics

Nếu Kernel trả:

```text
hit = true
dodged = false
```

Tiếp tục Critical Resolution.

Nếu Kernel trả:

```text
hit = false
dodged = true
```

Dừng numerical pipeline.

Không:

- Resolve Critical.
- Calculate B0.
- Calculate B1.
- Calculate Mitigation.

Không áp damage.

## 6.4. Dodge RNG Consumption

RPG Core 2.0.0 có lazy dodge semantics:

- Dodge chance bằng 0 → không draw.
- Dodge rule disabled → không draw.
- Dodge ineligible → không draw.
- Eligible positive dodge chance → draw đúng khi Kernel yêu cầu.

Không pre-sample RNG trước khi gọi Kernel.

Không tự dùng:

```ts
const dodgeRoll = nextExecutionRandom(context);
const critRoll = nextExecutionRandom(context);
```

trước khi biết các stages có cần random hay không.

## 6.5. Missed Attack Result

Ví dụ:

```text
Dodge chance = 0.5
RNG roll = 0.2
```

Expected:

```text
outcome = dodged
finalDamage = 0
```

Chỉ Hit diagnostics tồn tại.

Không tạo fake Critical/B0/B1/Mitigation results chứa toàn số 0.

Những stages không chạy phải được biểu diễn rõ là **not evaluated** bằng result shape.

## 6.6. No Gameplay Miss Side Effects

On dodge:

- Không trừ HP.
- Không trigger OnHit effects.
- Không gọi target death evaluation.
- Không publish attack-missed event tự động.

Caller có thể publish event qua Foundation sau khi nhận result.

# 7. CB18 — Critical Resolution

## 7.1. Objective

Resolve Critical bằng canonical:

`calculateCritical()`

Chỉ gọi sau successful Hit.

## 7.2. Critical Input

Caller cung cấp:

- Critical chance.
- Critical bonus.
- Eligibility.
- Probability rule.
- RNG provider.

Không tự suy ra critical chance từ Entity attributes.

Không tự lấy Skill Rank.

Không hardcode critical bonus.

## 7.3. Critical RNG Semantics

Kernel có semantics quan trọng:

**Eligible + enabled Critical vẫn tiêu một RNG draw ngay cả khi critical chance bằng 0.**

Bắt buộc giữ nguyên.

Ví dụ:

```text
Hit landed
Critical eligible = true
Critical enabled = true
Critical chance = 0
```

Expected:

- Critical stage được đánh giá.
- RNG được draw một lần.
- `isCritical = false`.

Nếu critical ineligible hoặc disabled:

- Không draw.
- Dùng actual Kernel result.

Không thay đổi Kernel ordering.

## 7.4. No Critical On Dodge

Khi đòn đánh bị dodge:

- Critical stage không chạy.
- Không tiêu Critical RNG.
- Không đọc unnecessary critical numerical callbacks.
- Không tính damage.

## 7.5. Critical Bonus Semantics

Kernel trả:

```text
critical.bonus
critical.multiplier
```

Trong đó:

- `bonus` là additive critical bonus được đưa vào Damage B1.
- `multiplier` là diagnostic.

**Không được nhân Damage B1 thêm một lần với critical.multiplier.**

Ví dụ:

```text
B0 raw = 100

Critical bonus = 0.5
Other bonuses = 0
```

Expected:

```text
Before defense = 150
```

Không được:

```text
100 × 1.5 × 1.5 = 225
```

Không tạo second critical calculator.

## 7.6. Critical Roll Validation

Foundation `nextExecutionRandom()` có contract RNG:

```text
0 <= roll < 1
```

Bắt buộc sử dụng accepted validated RNG source, hoặc một explicitly validated equivalent nếu actual task-approved public contract yêu cầu.

Không phụ thuộc vào việc `calculateCritical()` tự validate roll range vì pinned Kernel không thực hiện kiểm tra range tương tự Hit.

Không silently clamp invalid RNG results.

# 8. CB19 — Damage & Mitigation

## 8.1. Objective

Tính final numerical attack damage sau successful Hit.

Pipeline:

```text
Hit landed
    │
    ▼
Critical Resolution
    │
    ▼
Damage B0
    │
    ▼
Damage B1
    │
    ▼
Mitigation
    │
    ▼
Final Damage
```

## 8.2. Damage B0

Gọi:

`calculateDamageB0()`

Caller cung cấp:

- Base damage.
- Rank.
- Per-rank coefficient.
- Ordered scaling sources.
- Scaling values.
- Scaling coefficients.
- Resolved flat terms.

Kernel thực hiện:

- Rank factor.
- Base damage scaling.
- Ordered source scaling.
- Flat aggregation.
- Raw damage.

Combat không thực hiện những phép tính trên.

## 8.3. Damage B0 Stage Order

Bảo toàn thứ tự numerical access trong Kernel:

1. Base/rank fields.
2. Ordered scaling values/coefficient callbacks.
3. `resolveFlat()`.
4. Raw result.

Không tự reorder scaling sources.

Không đọc hoặc gọi `resolveFlat()` nhiều lần để tạo diagnostics.

Nếu dùng snapshot adapter, chuẩn bị immutable scalar inputs trước stage và bảo toàn thứ tự Kernel tiêu thụ.

Không tự viết một equivalent B0 implementation để test dễ hơn.

## 8.4. Damage B1

Gọi:

`calculateDamageB1()`

Inputs:

- Actual B0 raw damage.
- Caller-supplied already-effective bonuses.
- Actual Critical bonus.

Không tự tính `criticalBonus`.

Không tự tính tổng Damage Bonuses.

Không tự nhân Critical multiplier.

Không thêm second clamping rule.

## 8.5. Damage Bonus Sources

Damage bonuses có thể xuất phát từ:

- Attributes.
- Equipment.
- Skill configuration.
- Effects.
- Game-specific rules.

Nhưng v0.4.3 **không resolve các nguồn này**.

Caller cung cấp effective numerical bonuses thông qua accepted Kernel-compatible contracts.

Combat không:

- Query Equipment.
- Query Buff/Debuff instances.
- Query Skill Definition.
- Resolve modifier eligibility bằng engine riêng.

Nếu sau này Effect/Equipment integration cần source resolution, dùng canonical Kernel modifier resolver và explicit module integration.

Không tạo placeholder integrations tại đây.

## 8.6. Mitigation

Gọi:

`calculateMitigation()`

Sử dụng actual B1 `beforeDefense` làm `damage`.

Caller cung cấp:

- `ruleKey`
- `rating`
- `rule`
- `sourceLevel`, nếu applicable.
- `targetLevel`, nếu applicable.

Không tự tính:

```text
Defense Reduction = Defense / (Defense + K)
```

hoặc bất kỳ formula khác.

## 8.7. Mitigation Diagnostics

Bảo toàn actual Kernel result:

- `status`
- `missing`
- `levelGap`
- `effectiveK`
- `rawReduction`
- `reduction`
- `inputDamage`
- `preventedDamage`
- `finalDamage`

Không rewrite diagnostics.

Không tự làm tròn.

Không tự tái dựng `preventedDamage` hoặc `finalDamage`.

## 8.8. Missing Mitigation Configuration

Phải phân biệt:

**Explicitly disabled mitigation:**

```text
rule.enabled = false
```

Kernel có thể trả:

```text
status = disabled
```

Đây là caller-selected disabled policy, không phải thiếu input ngầm.

**Enabled mitigation nhưng thiếu required numerical configuration:**

Kernel có thể trả:

```text
status = missing_config
```

Combat không được âm thầm coi missing configuration là successful defense resolution.

Yêu cầu:

- Validate completeness của enabled mitigation policy trước RNG consumption khi có thể.
- Không tự chọn default `baseK`, `levelPenalty` hoặc rating.
- Nếu Kernel vẫn trả `missing_config`, không xuất successful landed damage resolution.
- Report explicit configuration failure với diagnostics.

Không thay đổi Kernel semantics hoặc sửa numerical output để che missing configuration.

## 8.9. Final Damage

Final attack damage phải lấy trực tiếp từ:

```text
mitigation.finalDamage
```

Đối với landed attack.

Không tạo:

```ts
Math.max(0, customDamageFormula(...))
```

Không tính lại final damage trong Combat.

Đối với dodged attack:

```text
finalDamage = 0
```

Đây là outcome projection, không phải một fake mitigation calculation.

## 8.10. Nonfinite Numerical Outputs

Các numerical outputs phải là finite values trước khi đưa vào immutable public result.

Nếu caller configuration tạo ra nonfinite numerical output:

- Reject invalid calculation result.
- Không fallback zero.
- Không clamp bằng công thức riêng.
- Không apply damage.
- Không mutate state.

Không che invalid input bằng một successful zero-damage result.

# 9. RNG Ownership & Determinism

## 9.1. Canonical RNG Source

Ưu tiên sử dụng:

`GameplayExecutionContext`

và:

`nextExecutionRandom()`

từ Foundation.

Caller cấp explicit RNG provider.

Combat không dùng:

- `Math.random()`
- `Date.now()`
- `performance.now()`
- Global RNG singleton.
- Internal random seed generator.

Không tạo Combat RNG Engine.

## 9.2. Lazy RNG Adapter

Khi giao cho Kernel, sử dụng lazy callback tương đương:

```ts
roll: () => nextExecutionRandom(executionContext)
```

Không gọi trước.

Kernel tự quyết định có cần tiêu sample hay không.

## 9.3. Consumption Matrix

| Scenario | Dodge RNG | Critical RNG |
|---|---:|---:|
| Dodge eligible, chance > 0, attack dodged | 1 | 0 |
| Dodge eligible, chance > 0, attack landed, Critical enabled/eligible | 1 | 1 |
| Dodge chance = 0, landed, Critical enabled/eligible | 0 | 1 |
| Dodge disabled, landed, Critical enabled/eligible | 0 | 1 |
| Dodge ineligible, landed, Critical enabled/eligible | 0 | 1 |
| Landed, Critical disabled | According to Dodge | 0 |
| Landed, Critical ineligible | According to Dodge | 0 |

| Rejected admission | 0 | 0 |

Không tiêu thêm RNG để tạo Damage ID, Crit ID hoặc visual result.

## 9.4. Deterministic Replay

Hai independent sessions được cung cấp:

- Same action context.
- Same admitted/accepted snapshots.
- Same numerical policies.
- Same deterministic RNG stream.

Expected:

- Same stages.
- Same roll consumption.
- Same hit/critical outcomes.
- Same B0/B1/Mitigation.
- Same finalDamage.
- Same immutable diagnostics.

Không khẳng định hai lần dùng cùng một stateful RNG context sẽ luôn có kết quả giống nhau.

Determinism được đánh giá bằng independent equivalent RNG streams.

## 9.5. RNG Failure

Nếu provider:

- Missing khi cần sample.
- Trả NaN/Infinity.
- Trả giá trị ngoài `[0,1)`.
- Throw.

Operation phải fail.

Không generate random sample thay thế.

Không retry RNG.

Không tự rollback state nội bộ của caller-owned RNG provider; ghi rõ limitation này.

# 10. Attack Resolution Result

## 10.1. Objective

## 10.2. Result Outcome

Đề xuất:

```ts
type CombatAttackOutcome =
  | "dodged"
  | "landed";
```

## 10.3. Discriminated Result

Conceptual:

```ts
type CombatAttackResolutionResult =
  | {
      readonly context: CombatActionContext;
      readonly outcome: "dodged";
      readonly hit: Readonly<HitCalculationResult>;
      readonly finalDamage: 0;
    }
  | {
      readonly context: CombatActionContext;
      readonly outcome: "landed";
      readonly hit: Readonly<HitCalculationResult>;
      readonly critical: Readonly<CriticalCalculationResult>;
      readonly b0: Readonly<DamageB0Result>;
      readonly b1: Readonly<{
        criticalBonus: number;
        totalBonus: number;
        beforeDefense: number;
      }>;
      readonly mitigation:
        Readonly<MitigationCalculationResult>;
      readonly finalDamage: number;
    };
```

Implementation phải compose actual Kernel result types, không copy incompatible numerical contracts.

Nếu cần đặt một số diagnostics vào nested `calculation`, vẫn phải giữ discriminated outcome chính xác.

## 10.4. Dodged Result

```text
outcome = dodged

```

Không có:

- Critical diagnostics.
- B0 result.
- B1 result.
- Mitigation result.

Không xuất fake numerical calculations chưa chạy.

## 10.5. Landed Result

```text
outcome = landed
hit.hit = true

critical:
  actual Kernel result

b0:
  actual Kernel result

b1:
  actual Kernel result

mitigation:
  actual Kernel result

  mitigation.finalDamage
```

Không tạo `damageApplied` field.

## 10.6. Immutability

Bắt buộc:

- Embedded Combat Action Context frozen/detached.

## 10.7. No Successful Partial Result

Nếu:

- Invalid RNG.

# 11. Numerical Input Validation

## 11.1. Required Validation

Bảo vệ:

- Required own-data records.
- Closed input shapes.
- Nonblank source identifiers.
- Finite numeric scalars.
- Valid positive safe rank.
- Valid probability rule fields.
- Valid bounds.
- Valid mitigation policy fields.
- Valid scaling source order.
- No duplicate source identifiers.
- Valid flat contribution values.
- Valid already-effective bonus records.
- Dense arrays.
- No extra array properties.
- No inherited required fields.
- No getter-based input fields.

Không silently coerce values.

## 11.2. Validation vs Calculation

L2 được phép kiểm tra:

```text
number is finite
rank is valid
required policy exists
source ID is valid
bounds are structurally valid
```

L2 không được tự tính:

```text
effective dodge chance
critical bonus
rank factor
raw damage
damage bonus multiplier
mitigation percentage
```

Các phép tính thuộc Kernel.

## 11.3. Preflight Before RNG

Trước khi bắt đầu tiêu RNG:

1. Validate stage result structures.
2. Validate action identity alignment.
3. Validate actor admitted.
4. Validate target accepted.
5. Validate numerical input structures.
6. Validate mitigation configuration.
7. Validate captured scaling/bonus data.

Sau đó bắt đầu Kernel execution.

Không để malformed B0 configuration tiêu RNG trước rồi mới fail, nếu lỗi có thể được phát hiện bằng structural validation.

Không execute caller-supplied numerical callbacks chỉ để preflight nếu implementation chọn trực tiếp callback-based Kernel contracts; trường hợp đó phải ghi rõ giới hạn và bảo đảm không duplicate execution.

Ưu tiên snapshot-based input adapter để preflight deterministic.

## 11.4. No Silent Defaults

Không mặc định:

- Critical chance.
- Dodge chance.
- Damage base.
- Rank.
- Defense rating.
- Mitigation coefficients.
- Damage bonuses.
- RNG seed.

Nếu caller muốn zero bonus, cung cấp:

```text
bonuses = []
```

Nếu caller muốn no scaling, cung cấp:

```text
scaling = []
```

Nếu caller muốn disabled defense, cung cấp explicit disabled policy.
