Triển khai reusable **Skill Cooldown** cho RPG Gameplay L2, dựa trên canonical RPG Core Kernel và Foundation Execution Clock.

# 2. Approved Architecture Decisions

## Decision A — Strict L1/L2/L3/L4 Ownership

| Capability | Canonical Owner | Responsibility |
|---|---|---|
| Cooldown numerical duration | L1 — RPG Core | Tính duration từ base cooldown và effective CDR |
| Execution Clock | L2 — Foundation | Nhận caller-owned clock, validate và đọc execution time |
| Skill Cooldown State | L2 — Skill | Immutable cooldown lifecycle state |
| Skill Cooldown Assessment | L2 — Skill | Ready/active, remaining time, reuse rejection |
| Skill Instance Identity | L2 — Skill | Identity gắn cooldown với đúng instance |
| Skill Rank | L2 — Progression | Rank state, upgrade, rank queries |
| Entity Resources | L2 — Entity | Resource state và resource transitions |
| Combat Operations | L2 — Combat | Combat admission, targets, attack và damage |
| Base Cooldown Configuration | L3 | Giá trị cooldown của từng skill |
| Effective CDR Input | L3 / caller | Resolve numerical modifier/stat từ canonical source |
| Activation Coordination | L4 | Kết hợp admission, costs, cooldown và execution |
| Runtime Time Authority | L4 | Clock origin, monotonic timeline, simulation advancement |
| Persistence & Concurrency | L4 | Commit state, storage, synchronization |

**Không tạo cooldown calculator thứ hai trong Skill.**

**Không tạo clock provider hoặc timer engine thứ hai trong Skill.**

## Decision B — Core Owns Cooldown Duration Calculation

Pinned Core đã cung cấp:

```ts
calculateCooldownDurationMs(
  baseMs: number,
  effectiveCdr: number
): number
```

Import duy nhất từ:

```ts
import {
  calculateCooldownDurationMs
} from "@rpg/core/kernel";
```

Actual Core semantic:

```text
durationMs = baseMs × (1 - effectiveCdr)
```

Công thức trên là tài liệu mô tả expected behavior, **không được copy thành implementation tại L2**.

Core sở hữu phép tính duration.

Skill chỉ gọi canonical API và sử dụng returned duration.

## Decision C — Foundation Owns Execution Time

Existing Foundation:

```ts
createExecutionContext()
readExecutionTime()
```

Trong đó:

```ts
interface GameplayClock {
  now(): number;
}
```

Time contract:

- Milliseconds.
- Finite.
- Nonnegative.
- Relative to caller-chosen origin.
- Không bắt buộc Unix epoch.
- Không tự suy luận wall-clock time.

Skill phải sử dụng:

```ts
readExecutionTime(context)
```

Không gọi trực tiếp:

```ts
Date.now()
performance.now()
setTimeout()
setInterval()
```

Không tự tạo Scheduler hoặc Timer Manager.

## Decision D — Cooldown State Is Separate From Skill Instance

Existing:

```ts
interface SkillInstanceState {
  readonly instanceId: string;
  readonly skillId: string;
  readonly entityId: string;
}
```

Không bổ sung cooldown fields vào Skill Instance.

Cooldown sở hữu một immutable state riêng gắn với cùng identity.

Không thêm:

```text
lastUsedAt
cooldownRemaining
cooldownEnd
```

vào `SkillInstanceState`.

Không tạo second Skill Instance authority.

## Decision E — Assessment Is Not Activation

Một cooldown ready result chỉ chứng minh:

> Theo cooldown state và execution time được cung cấp, instance có thể bắt đầu một cooldown mới.

Nó không chứng minh:

- Skill đã learned.
- Actor alive.
- Admission PASS.
- Resources đủ.
- Target hợp lệ.
- Combat đã admitted.
- Activation đã commit.

Những stages trên thuộc các canonical owners đã thiết kế.

v0.5.4 mới điều phối đầy đủ activation.

## Decision F — No Global Cooldown Engine

Không tạo:

- CooldownManager.
- CooldownScheduler.
- CooldownTimer.
- CooldownRegistry.
- CooldownQueue.
- GlobalCooldownStore.
- Universal Ability Cooldown.
- Shared cooldown across skills.
- Cooldown groups.
- Persistent activation session.

Mỗi Skill Cooldown State chỉ mô tả lifecycle của một Skill Instance.

# 5. SK16 — Skill Cooldown State

## 5.1. Objective

Tạo immutable cooldown lifecycle state cho một Skill Instance.

Cooldown State phải:

- Có exact identity association.
- Không lưu game-specific content.
- Không lưu Skill Rank.
- Không lưu Resource State.
- Không lưu Combat State.
- Không có mutable timer.
- Không phụ thuộc global state.

## 5.2. Public Contract

Conceptual type:

```ts
export interface SkillCooldownState {
  readonly instanceId: string;
  readonly skillId: string;
  readonly entityId: string;

  readonly startedAtMs: number | null;
  readonly readyAtMs: number | null;
}
```

Hai timestamp có ý nghĩa:

| Field | Meaning |
|---|---|
| `startedAtMs` | Time mà cooldown được bắt đầu |
| `readyAtMs` | Time mà cooldown trở lại ready |
| `null / null` | Cooldown chưa từng được bắt đầu trong snapshot hiện tại |

Không lưu thêm `remainingMs` vào persistent cooldown state.

Remaining time được tính từ current clock và `readyAtMs`.

## 5.3. State Identity

Identity phải match:

```text
state.instanceId == instance.instanceId
state.skillId == instance.skillId
state.entityId == instance.entityId
```

Nếu mismatch:

```text
TypeError
```

Không tự rebind cooldown sang instance khác.

Không dùng cùng cooldown snapshot cho hai Skill Instances chỉ vì có cùng Skill Definition.

## 5.4. Public Factory

```ts
createSkillCooldownState(
  instance: SkillInstanceState
): SkillCooldownState
```

Expected:

```ts
{
  instanceId: "instance-001",
  skillId: "fireball",
  entityId: "player-1",

  startedAtMs: null,
  readyAtMs: null
}
```

Factory phải:

- Validate exact Skill Instance contract.
- Capture identities.
- Return detached frozen state.
- Không đọc clock.
- Không gọi Core.
- Không tạo timestamp.
- Không generate instance ID.
- Không mutate Skill Instance.

## 5.5. State Invariants

Accepted lifecycle shapes:

```text
Never started:
  startedAtMs = null
  readyAtMs = null

Started:
  startedAtMs = finite nonnegative number
  readyAtMs = finite nonnegative number
  readyAtMs >= startedAtMs
```

Reject:

```text
startedAtMs = null
readyAtMs = 1000

startedAtMs = 1000
readyAtMs = null

startedAtMs = 2000
readyAtMs = 1000
```

Reject nonfinite, negative, unknown, missing hoặc accessor fields.

Không silently repair malformed state.

## 5.6. No Implicit Expiration Mutation

Cooldown expiration không yêu cầu background transition.

Nếu:

```text
readyAtMs = 2000
nowMs = 2500
```

Cooldown được đánh giá là ready.

Nhưng stored `readyAtMs` vẫn là `2000`.

Không tự reset về `null`.

Không tạo timeout callback để cập nhật state.

## 5.7. Immutable Versioning

Mỗi successful cooldown start trả new state.

Original state giữ nguyên.

Ví dụ:

```text
State A:
  startedAt = null
  readyAt = null

Start at 1000:
  duration = 750

State B:
  startedAt = 1000
  readyAt = 1750
```

State A không thay đổi.

Không tạo mutable state store trong Skill.

# 6. SK17 — Core Cooldown Duration

## 6.1. Objective

Sử dụng canonical Core calculation để resolve cooldown duration.

## 6.2. Public Configuration Contract

```ts
export interface SkillCooldownConfiguration {
  readonly baseDurationMs: number;
  readonly effectiveCdr: number;
}
```

`baseDurationMs` thuộc L3 Skill Configuration.

`effectiveCdr` là already-resolved numerical input do caller cung cấp.

L2 Skill không thực hiện:

- Stat lookup.
- CDR modifier resolution.
- Rank scaling.
- Equipment bonus aggregation.
- CDR cap calculation.
- Custom reduction formula.

## 6.3. Input Validation

`baseDurationMs`:

- Number.
- Finite.
- Nonnegative.

`effectiveCdr`:

- Number.
- Finite.
- Trong khoảng `[0, 1]`.

Accept:

```text
baseDurationMs = 0
baseDurationMs = 1000
baseDurationMs = 1500.5

effectiveCdr = 0
effectiveCdr = 0.25
effectiveCdr = 1
```

Reject:

```text
baseDurationMs = -1
baseDurationMs = NaN
baseDurationMs = Infinity
effectiveCdr = -0.1
effectiveCdr = 1.1
effectiveCdr = NaN
```

Malformed input:

```text
TypeError
```

Không tự clamp CDR.

Không silently normalize base duration.

## 6.4. Canonical Calculation

Bắt buộc gọi:

```ts
calculateCooldownDurationMs(
  baseDurationMs,
  effectiveCdr
)
```

Ví dụ:

```text
Base cooldown:
  1000 ms

Effective CDR:
  0.25
```

Expected:

```text
Duration:
  750 ms
```

Không tự tính duration trong Skill.

## 6.5. No Double Reduction

`effectiveCdr` đã là effective value.

Không gọi thêm modifier resolver hoặc áp dụng một reduction lần thứ hai.

Ví dụ:

```text
Base = 1000
Effective CDR = 0.25
```

Expected:

```text
Duration = 750
```

Không được giảm tiếp 25% trên duration đã được Core tính.

## 6.6. Zero Duration

Các trường hợp:

```text
baseDurationMs = 0
```

hoặc:

```text
effectiveCdr = 1
```

Có thể tạo:

```text
durationMs = 0
```

Đây là valid cooldown duration.

Không tự ép minimum cooldown:

```text
1 ms
100 ms
1 second
```

Game-specific minimum cooldown cần L3/Core approved policy riêng.

## 6.7. Numerical Integrity

Không round hoặc convert milliseconds sang integer.

Không dùng:

```text
Math.floor(duration)
Math.ceil(duration)
Math.round(duration)
```

trừ khi Core contract sau này quy định.

Nếu Core trả fractional milliseconds, giữ nguyên value.

Không đặt epsilon riêng.

## 6.8. Representability

Ngay cả khi Core trả finite duration, việc tạo absolute ready timestamp có thể overflow:

```text
readyAtMs = nowMs + durationMs
```

Đây là timestamp bookkeeping ở L2, không phải tính lại cooldown reduction.

Nếu ready timestamp không finite:

```text
TypeError
```

Nếu duration dương nhưng floating-point timestamp addition không biểu diễn được thời điểm ready lớn hơn start:

```text
TypeError
```

Không silently biến positive cooldown thành zero cooldown do mất độ chính xác của timestamp.

Không tự clamp sang `Number.MAX_VALUE`.

Không thay đổi Core duration.

# 7. SK18 — Foundation Clock Integration

## 7.1. Objective

Cooldown sử dụng caller-owned Execution Clock thông qua existing Foundation contract.

## 7.2. Required Foundation APIs

```ts
createExecutionContext()
```

```ts
GameplayExecutionContext
```

## 7.3. Clock Contract

```ts

```

Units:

```text
Milliseconds
```

Origin:

```text
Caller-chosen origin
```

Expected:

```text
0
500
1000
1750
```

Không yêu cầu time zone.

Không sử dụng wall-clock date.

## 7.4. Public Readiness API

Proposed:

```ts
evaluateSkillCooldownReady(
  instance: SkillInstanceState,
  state: SkillCooldownState,
  context: GameplayExecutionContext
): SkillCooldownAssessment
```

Operation phải gọi:

```ts

```

**Exactly once per invocation.**

Không đọc clock lần nữa khi tính remaining time.

Không gọi `context.clock.now()` trực tiếp.

Không dùng hidden clock provider.

## 7.5. Determinism

Với cùng:

```text
Skill Instance
Cooldown State
Execution time
```

Expected:

```text
Same assessment
Same remainingMs
Same status
Same reason
```

Không phụ thuộc:

- Real wall-clock.
- RNG.
- Generated IDs.
- Global mutable timer.
- Event loop timing.

## 7.6. Clock Origin Consistency

All timestamps trong cùng cooldown state phải sử dụng một consistent time origin.

Caller/L4 chịu trách nhiệm duy trì origin và authoritative clock source.

Không lưu Unix timestamp hoặc time zone trong Skill.

Không tự convert timestamps.

## 7.7. Time Rewind

Nếu supplied clock cho giá trị:

```text
nowMs < startedAtMs
```

Expected:

```text
TypeError
```

Vì observation không nhất quán với timeline bắt đầu cooldown.

Không biến rewind thành ordinary `cooldown_active`.

Không auto-reset cooldown.

Không dùng absolute difference để sửa.

Lưu ý:

- Skill chỉ kiểm tra những contradictions có thể phát hiện từ state hiện có.
- Không đảm bảo phát hiện mọi dạng clock rewind giữa những lần evaluation độc lập.
- Clock monotonicity và simulation replay authority vẫn thuộc L4.
- Không thêm `lastObservedAtMs` hoặc global observation store chỉ để theo dõi clock.

## 7.8. Provider Errors

Nếu `readExecutionTime()` reject:

- Propagate error.
- No partial state.
- No cooldown transition.
- No fallback to `Date.now()`.

Nếu input state/config malformed, validate trước khi đọc clock để tránh gọi provider không cần thiết.

Một invocation hợp lệ của readiness/start được đọc clock đúng một lần, kể cả khi cooldown đang active.

# 8. SK19 — Ready & Reuse Validation

## 8.1. Objective

Đánh giá trạng thái cooldown và tạo một cooldown transition mới khi reuse được phép.

## 8.2. Assessment Contracts

Proposed types:

```ts
export type SkillCooldownStatus =
  | "ready"
  | "active";

export type SkillCooldownReason =
  | "none"
  | "cooldown_active";

export interface SkillCooldownAssessment {
  readonly instanceId: string;
  readonly skillId: string;
  readonly entityId: string;

  readonly observedAtMs: number;
  readonly readyAtMs: number | null;
  readonly remainingMs: number;

  readonly status: SkillCooldownStatus;
  readonly reason: SkillCooldownReason;
}
```

Không tạo `activationId`, execution receipt hoặc timer handle.

## 8.3. Ready Semantics

Cooldown ready khi:

```text
startedAtMs = null
readyAtMs = null
```

hoặc:

```text
nowMs >= readyAtMs
```

Expected:

```text
status = ready
reason = none
remainingMs = 0
```

Thời điểm đúng bằng `readyAtMs` phải ready.

Không thêm epsilon.

## 8.4. Active Semantics

Cooldown active khi:

```text
startedAtMs <= nowMs < readyAtMs
```

Expected:

```text
status = active
reason = cooldown_active
```

Remaining time:

```text
remainingMs = readyAtMs - nowMs
```

Đây là time interval bookkeeping ở L2.

Không tính lại Core cooldown duration trong readiness evaluation.

Không dùng baseDuration/effectiveCdr để tính lại remaining.

## 8.5. Ready At Exact Boundary

Input:

```text
startedAtMs = 1000
readyAtMs = 1750
nowMs = 1750
```

Expected:

```text
status = ready
remainingMs = 0
```

Không reject vì `nowMs` bằng exact boundary.

## 8.6. Start Cooldown API

Proposed:

```ts
startSkillCooldown(
  instance: SkillInstanceState,
  state: SkillCooldownState,
  context: GameplayExecutionContext,
  config: SkillCooldownConfiguration
): SkillCooldownStartResult
```

Operation:

1. Validate Skill Instance.
2. Validate Cooldown State và identity matching.
3. Validate full configuration.
4. Read execution time exactly once.
5. Evaluate ready/reuse on that captured time.
6. Nếu active, reject.
7. Nếu ready, gọi Core để calculate duration.
8. Derive representable ready timestamp.
9. Return new immutable candidate Cooldown State.

Không gọi public readiness API nếu việc đó khiến clock bị đọc hai lần.

Có thể reuse private pure readiness resolver với captured `nowMs`.

## 8.7. Start Result Contract

Proposed:

```ts
export type SkillCooldownStartResult =
  | {
      readonly status: "started";
      readonly reason: "none";
      readonly assessment: SkillCooldownAssessment;
      readonly durationMs: number;
      readonly state: SkillCooldownState;
    }
  | {
      readonly status: "rejected";
      readonly reason: "cooldown_active";
      readonly assessment: SkillCooldownAssessment;
      readonly durationMs: null;
      readonly state: null;
    };
```

`assessment` phản ánh state trước khi attempt start.

Nếu started:

- `durationMs` lấy từ Core.
- `state` là new immutable candidate state.

Nếu rejected:

- Không có updated state.
- Không có duration calculation.
- Original state không đổi.

Không expose partial state.

## 8.8. Successful Start

Input:

```text
Current time:
  1000 ms
```

- Publish activation event.

**Không sử dụng successful cooldown start để chứng minh skill đã activated.**

# 9. Contract Validation

## 9.1. Closed Records

Reject:

- Null.
- Arrays thay object.
- Missing required fields.
- Unknown fields.
- Symbol keys.
- Accessor/getter fields.
- Inherited required fields.
- Invalid identity strings.
- Invalid state timestamps.
- Invalid configuration.
- Mismatched Skill Instance and Cooldown State.

Không invoke getters để validate.

Không silently omit unknown fields.

## 9.2. State Validation

Full validation trước gameplay outcome.

Ví dụ:

```text
Cooldown state:
  active

Configuration:
  effectiveCdr = NaN
```

Expected:

```text
TypeError
```

Không trả `cooldown_active` để che malformed configuration.

## 9.3. Time Validation

`readExecutionTime()` sở hữu time-provider validation.

Invalid time:

```text
-1
NaN
Infinity
"1000"
```

Expected:

```text
TypeError
```

Không normalize.

Không fallback time source.

## 9.4. Malformed vs Rejected

**Malformed contracts:**

```text
TypeError
```

**Valid gameplay cooldown rejection:**

```text
status = rejected
reason = cooldown_active
```

Không throw exception khi cooldown đơn giản là chưa kết thúc.

## 9.5. Snapshot Isolation

Returned state/result:

- Detached.
- Frozen.
- No mutable aliases.
- No mutation of caller inputs.
- No global state.

Nếu nested assessment nằm trong result, phải frozen riêng.

Không freeze caller-owned Execution Context hoặc Clock provider.

```text
L2 — Skill Lifecycle
  ready / active
  start / reject
           │
           ▼
L4 — Application
  authoritative state commit
  activation coordination
```

**L1 quyết định cooldown duration.**

**L2 Foundation cung cấp execution time.**

**L2 Skill quản lý cooldown state và readiness.**

**L3 quyết định cooldown configuration.**

**L4 quyết định khi nào một successful candidate cooldown state được commit cùng activation.**
