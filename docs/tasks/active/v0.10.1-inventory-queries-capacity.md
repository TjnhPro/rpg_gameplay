## Contract freeze

**Preserve** `InventoryState {inventoryId,owner,entries}`, `InventoryEntry {item,quantity}`, the accepted public Item v0.9.3 types/functions and `InventoryValidationContext`. Do not add `maxSlots`, `slotIndex` or capacity data to canonical state: a capacity is L3 policy supplied at the call.

### Proposed additive public API (accept actual v0.10.0 signature at preflight)

```ts
export interface InventoryCapacityPolicy {
  readonly maxEntries: number | null; // 0 and positive safe integer; null means unbounded
}
export type InventoryCapacityAssessment = {
  readonly fits: boolean;
  readonly occupied: number;
  readonly available: number | null;
};
export function getInventoryEntry(state: InventoryState, context: InventoryValidationContext, instanceId: string): InventoryEntry | null;
export function listInventoryEntries(state: InventoryState, context: InventoryValidationContext): readonly InventoryEntry[];
export function hasInventoryItem(state: InventoryState, context: InventoryValidationContext, instanceId: string): boolean;
export function assessInventoryCapacity(state: InventoryState, context: InventoryValidationContext, policy: InventoryCapacityPolicy, additionalEntries: number): InventoryCapacityAssessment;
```

**Proposal:** four functions + two types; no public state change. `maxEntries` counts entries, **not units**. `additionalEntries` is a safe integer >=0 (0 valid); `available=max(maxEntries - occupied,0)` for finite policy; `available:null` for unbounded; `fits` iff occupied + additionalEntries <= maxEntries without unsafe arithmetic. Existing state may exceed current policy after L3 changes: assessment reports nonfit, **does not mutate or invalidate historical state**. Avoid storing policy in Inventory.
