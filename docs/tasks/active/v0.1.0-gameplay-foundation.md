## 3. Implementation Scope

### 3.1. Package & Source Foundation

Thiết lập TypeScript library:

- Package name: `@rpg/gameplay`.
- Version: `0.1.0`.
- Native ESM.
- Strict TypeScript.
- JavaScript output và TypeScript declarations.
- Package exports rõ ràng.
- Build có thể tái lập.
- `private: true` trong giai đoạn Foundation.

Thiết lập `src/index.ts` làm public root entrypoint.

Chỉ export contracts hoặc functions đã thực sự được triển khai và kiểm chứng.

**Không tạo fake APIs, placeholder functions, module implementation giả hoặc class chỉ để package có nhiều exports.**

Entrypoint rỗng về gameplay là chấp nhận được ở v0.1.0 nếu package build/load và declaration verification hoạt động đúng.

### 3.2. Repository Conventions

Giữ conventions tương thích Harness hiện có:

- `src/` chứa canonical implementations.
- `src/index.ts` là public entrypoint.
- `src/modules/<module-id>/` dành cho gameplay modules khi được triển khai.
- `harness/modules.json` quản lý ownership và dependencies theo schema hiện hành.
- `tests/` chứa function, contract, architecture và integration tests.
- `docs/` chứa architecture, task và verification evidence.

Chỉ tạo thư mục cần thiết. Không tạo trước 14 module trống.

Không tự tách package hoặc repository mới.

### 3.3. RPG Core Kernel Integration

Thiết lập dependency đến `@rpg/core/kernel`.

Yêu cầu bắt buộc:

- Chỉ import public `@rpg/core/kernel`.
- Không import `@rpg/core` root.
- Không import Legacy Skills, Effects, Combat, Spatial, Mechanics.
- Không import source nội bộ hoặc `dist` deep paths.
- Không copy numerical implementation từ Core.
- Không sửa repository `rpg_core`.

Core phải được tiêu thụ dưới dạng package đã build/install, không import trực tiếp source checkout.

Vì Core hiện là private package, agent cần chọn phương thức cài đặt tái lập dựa trên một Git revision hoặc artifact đã pin.

Có thể sử dụng build + pack + install từ revision chính xác nếu phù hợp.

Phải bảo đảm:

1. Local development cài đặt được.
2. CI cài đặt được.
3. Không phụ thuộc đường dẫn tuyệt đối trên máy Developer.
4. Không phụ thuộc floating branch hoặc artifact thay đổi âm thầm.
5. Có evidence nhận diện revision, package và kết quả import.

Nếu không tìm được cách cài đặt tái lập, không được thay thế Core bằng mock hoặc calculator tự viết để vượt verification.

### 3.4. Public API & Packaging

Thiết lập khả năng tiêu thụ `@rpg/gameplay` từ một project độc lập.

Cần kiểm chứng:

- Import package root hợp lệ.
- ESM runtime hoạt động.
- TypeScript declarations được phát hành đúng trong package.
- NodeNext và strict TypeScript có thể resolve package.
- `exports` không mở tùy tiện internal source.
- Không cần import file nội bộ từ `src/` hoặc `dist/`.

Không cần thiết kế public API cho Module Registry, Character, Skill, Item hoặc Combat tại version này.

Các contract này thuộc milestones sau.

### 3.5. Architecture Boundaries

Sử dụng và cập nhật architecture checker hiện có khi cần thiết.

Bắt buộc kiểm soát:

| Boundary | Quy tắc |
|---|---|
| L2 → L1 | Chỉ public `@rpg/core/kernel` |
| L2 → L3 | Forbidden |
| L2 → L4 | Forbidden |
| Module → Module | Chỉ dependency được khai báo, qua public entrypoint |
| Numerical calculations | Một canonical implementation thuộc Kernel |
| Game-specific policy | Không hardcode vào Foundation |
| Renderer / Game Engine | Không phụ thuộc |
| Global gameplay state | Không được xuất hiện |

Các kiểm tra phải phát hiện dependency vi phạm thực sự, không chỉ kiểm tra tên file.

Giữ nguyên những Harness guards đã có hiệu lực.

Nếu checker hiện hành có giới hạn lexical/static analysis, phải báo cáo chính xác giới hạn đó. Chỉ sửa checker để đáp ứng invariant đã duyệt, không mở rộng thành một hệ thống phân tích kiến trúc mới nếu không cần thiết.

### 3.6. Development & Verification Tooling

Thiết lập các lệnh phù hợp:

- `npm run build`
- `npm run typecheck`
- `npm run test:functional`
- `npm run harness:check`
- `npm run harness:selftest`
- `npm run verify`

Có thể bổ sung package-consumer smoke command nếu cần.

`npm run verify` phải thực hiện các verification gates đã khai báo và thất bại khi bước bắt buộc thất bại.

Bắt buộc bảo đảm cross-platform Windows/Linux, đặc biệt với `process.execPath` và subprocess paths chứa khoảng trắng.

Không dùng `echo PASS`, no-op script hoặc skipped tests để tạo kết quả verification giả.

## 5. Functional Acceptance & Verification

Test policy: **Minimal & Sufficient — evidence over test count.**

| ID | Requirement / Invariant | Evidence cần chứng minh |
|---|---|---|
| R01 | Package build thành công | JS và declarations được emit đúng |
| R02 | Public root import hợp lệ | Package consumer load được từ installed artifact |
| R03 | Public type resolution | Strict NodeNext consumer typecheck PASS |
| R04 | Kernel integration chính xác | Installed `@rpg/core/kernel` import và thực thi public numerical API thành công |
| R05 | Legacy import bị chặn | Architecture guard phát hiện import sai |
| R06 | Không phụ thuộc game application | Dependency audit không có L3/L4 hoặc engine imports |
| R07 | Harness guards vẫn hoạt động | `harness:check` và `harness:selftest` PASS |
| R08 | Full verification không bỏ qua lỗi | Build/typecheck/test failures khiến verify thất bại |
| R09 | Windows subprocess compatibility | Verification hoạt động với Node executable path chứa khoảng trắng |
| R10 | Reproducible Core dependency | Local và CI sử dụng đúng Core revision/artifact đã pin |

### Test Quality Requirements

- Mỗi test phải chứng minh ít nhất một requirement hoặc invariant.
- Expected result phải xác định độc lập từ contract hoặc hành vi được yêu cầu.
- Không tạo nhiều test gần giống nhau nếu không thêm bằng chứng.
- Không đặt KPI theo số lượng tests.
- Không dùng snapshot lớn thay cho assertions có ý nghĩa.
- Không viết gameplay function giả chỉ để có test.
- Không dùng mocked Core implementation làm bằng chứng tích hợp Core.

Các Functional Tests ở v0.1.0 chủ yếu là package contract, dependency, export và integration smoke.

**Không bắt buộc ba Text/2D/2.5D functional profiles cho version này**, vì chưa có gameplay behavior tạo ra khác biệt giữa chúng.

Ba profiles sẽ được kiểm chứng khi các gameplay functions tương ứng xuất hiện và tại Foundation Closure.

### Verification Gates

1. Targeted checks cho phần vừa thay đổi.
2. Typecheck và build.
3. Architecture checks.
4. Package consumer verification.
5. `npm run verify`.
6. `git diff --check`.
7. GitHub CI trên PR.

Không được báo cáo PASS đối với bước chưa chạy hoặc chưa có kết quả.
