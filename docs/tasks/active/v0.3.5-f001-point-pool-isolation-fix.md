# 4. F-001 Root Cause

## 4.1. Existing Public Types

Hiện tại hai types tương đương:

```ts
interface EntityAttributePointState {
  readonly entityId: string;
  readonly unspentPoints: number;
  readonly spentPoints: number;
  readonly rewardedThroughLevel: number;
}

interface EntitySkillPointState {
  readonly entityId: string;
  readonly unspentPoints: number;
  readonly spentPoints: number;
  readonly rewardedThroughLevel: number;
}
```

Do TypeScript sử dụng structural typing, hai interfaces tương thích với nhau.

Điều này làm mất boundary giữa PG11 và PG15.

## 4.2. Existing Runtime Behavior

Runtime hiện dùng chung Point State reader.

Không có kiểm tra bắt buộc:

```text
Expected:
  attribute points

Actual:
  skill points
```

hoặc ngược lại.

Vì vậy các operations chỉ kiểm tra balance, entityId và numerical invariants vẫn có thể nhận sai loại pool.

## 4.3. Required Fix

Bảo vệ ở cả hai tầng:

**Compile-time:** Required literal type discriminants.

**Runtime:** Exact own-data `pointKind` validation tại mỗi public operation nhận Point State.

Không dựa duy nhất vào TypeScript.

Không tạo global registry hoặc mutable point store.

# 5. Public Point State Contract

## 5.1. Attribute Points

Thêm:

```ts
export interface EntityAttributePointState
  extends AttributePointInitialState {
  readonly entityId: string;
  readonly pointKind: "attribute";
}
```

Expected snapshot:

```ts
{
  entityId: "player-1",
  pointKind: "attribute",
  unspentPoints: 10,
  spentPoints: 0,
  rewardedThroughLevel: 3
}
```

## 5.2. Skill Points

Thêm:

```ts
export interface EntitySkillPointState
  extends SkillPointInitialState {
  readonly entityId: string;
  readonly pointKind: "skill";
}
```

Expected snapshot:

```ts
{
  entityId: "player-1",
  pointKind: "skill",
  unspentPoints: 3,
  spentPoints: 0,
  rewardedThroughLevel: 3
}
```

## 5.3. Initial State Contracts

**Không thay đổi initialization input shape.**

Giữ:

```ts
createAttributePointState(
  progression,
  {
    unspentPoints: 0,
    spentPoints: 0,
    rewardedThroughLevel: 1
  }
);
```

Và:

```ts
createSkillPointState(
  progression,
  {
    unspentPoints: 0,
    spentPoints: 0,
    rewardedThroughLevel: 1
  }
);
```

Caller không truyền `pointKind` khi khởi tạo.

Factories tự gắn discriminant chính xác.

Nếu caller cố truyền `pointKind` vào closed initial input, giữ nguyên closed-record validation và reject.

Không thay đổi Point Balance/Reward Cursor initialization semantics.

## 5.4. Point Kind Semantics

Chỉ cho phép:

```text
attribute
skill
```

Exact, case-sensitive values.

Không:

- Accept `"Attribute"`.
- Accept `"SKILL"`.
- Auto-normalize.
- Coerce strings.
- Default missing kind.
- Infer kind từ số điểm.
- Infer kind từ API được gọi rồi silently sửa snapshot.

Missing, wrong hoặc malformed `pointKind` phải reject.

Không hỗ trợ legacy untagged snapshots ngầm.

Chưa có persistent state migration trong scope.

## 5.5. Runtime Validation

Public operations phải validate:

- Own `pointKind` field.
- Value là exact expected literal.
- Field là own-data property, không phải getter.
- Closed state shape.
- Existing Entity ID validation.
- Existing point/balance/cursor validation.

Nếu là wrong kind:

- Throw `TypeError`.
- Không mutate caller input.
- Không trả successful state.
- Không cấp/thay đổi điểm.

Không dùng `as EntitySkillPointState` hoặc `as EntityAttributePointState` để che validation không đầy đủ.

# 6. Canonical Implementation

## 6.1. Keep Shared Bookkeeping

Hiện đã có private helpers phục vụ cả hai loại points.

Được phép tiếp tục reuse:

- `safePoints()`
- `pointValues()`
- `readPointState()`
- `createPointState()`
- `grantPointRewards()`

Nhưng phải bổ sung expected point kind vào validation path.

Không tạo hai numerical bookkeeping algorithms riêng với semantics khác nhau.

## 6.2. Expected Kind Must Be Explicit

Định hướng internal helper:

```ts
readPointState(input, expectedKind)
```

`expectedKind` là private trusted argument do public operation chọn, không phải giá trị lấy từ untrusted input.

Ví dụ:

```ts
readPointState(points, "attribute");
readPointState(points, "skill");
```

Có thể dùng TypeScript overloads hoặc generic helpers để giữ precise return types.

Implementation phải kiểm tra runtime kind thực tế.

Không chấp nhận việc compiler chỉ PASS nhờ broad type assertion.

## 6.3. Factory Ownership

`createAttributePointState()` phải tạo:

```text
pointKind = attribute
```

`createSkillPointState()` phải tạo:

```text
pointKind = skill
```

Hai factories có thể dùng chung private creator, nhưng phải chọn kind từ code path riêng.

Không thêm `pointKind` parameter vào public factory API.

Không để caller quyết định tạo Attribute hay Skill Point qua một generic public factory.

## 6.4. Type Preservation

Các private helpers phải giữ được mối liên hệ:

```text
attribute input → attribute output
skill input     → skill output
```

Không làm mất thông tin discriminant sau khi tạo next state.

Đặc biệt tránh kiểu public return:

```ts
EntityAttributePointState | EntitySkillPointState
```

ở những APIs vốn phải trả một type chính xác.

# 7. Required Public API Guards

## 7.1. Attribute Point Rewards

```ts
grantAttributePointRewards(
  attributePoints,
  advancement,
  rewardPolicy
);
```

Chỉ accept:

```text
pointKind = attribute
```

Wrong Skill Point State phải reject.

Returned state phải tiếp tục:

```text
pointKind = attribute
```

Giữ nguyên:

- Reward cursor.
- Level receipt validation.
- PointsGranted.
- Actual completed level rewards.
- Zero-reward behavior.
- Replay protection.

Không thay đổi reward calculation.

## 7.2. Skill Point Rewards

```ts
grantSkillPointRewards(
  skillPoints,
  advancement,
  rewardPolicy
);
```

Chỉ accept:

```text
pointKind = skill
```

Wrong Attribute Point State phải reject.

Returned state tiếp tục:

```text
pointKind = skill
```

Giữ nguyên independent reward cursor.

## 7.3. Attribute Allocation

```ts
allocateAttributePoints(
  points,
  attributes,
  allocation
);
```

Phải reject nếu:

```text
points.pointKind = skill
```

Dù:

- Entity ID khớp.
- Skill Points đủ.
- Attribute tồn tại.
- Point Cost hợp lệ.

Không cho Skill Points nâng Base Attributes.

Successful result:

```text
result.points.pointKind = attribute
```

Giữ nguyên Entity setter và all existing allocation semantics.

## 7.4. Skill Upgrade Evaluation

```ts
evaluateSkillUpgrade(
  progression,
  ranks,
  points,
  requirements
);
```

Phải reject nếu:

```text
points.pointKind = attribute
```

Không trả blocked `insufficient_points` để che wrong-kind input.

Wrong kind là invalid input, không phải valid gameplay blocker.

## 7.5. Skill Rank Upgrade

```ts
upgradeSkillRank(
  progression,
  ranks,
  points,
  requirements
);
```

Phải reject Attribute Point State.

Successful result:

```text
result.points.pointKind = skill
```

Blocked result cũng giữ exact Skill Point State kind.

Không tự chuyển Attribute Points sang Skill Points.

Không tự đổi numerical balance.

## 7.6. Validation Priority

Point-kind validation phải diễn ra trước khi thực hiện spending/grant calculation hoặc tạo successful result.

Nếu state vừa sai kind vừa không đủ điểm, operation phải reject invalid kind, không trả gameplay blocker.

Nếu cùng lúc có nhiều malformed fields, không yêu cầu thứ tự exception giữa các malformed conditions chưa được contract quy định.

Không mutate bất kỳ snapshot nào trên failure.

# 8. Compile-Time Acceptance

Bổ sung negative TypeScript consumer tests.

Các trường hợp sau phải bị TypeScript từ chối:

```ts
const attributePoints = createAttributePointState(
  progression,
  initialPoints
);

const skillPoints = createSkillPointState(
  progression,
  initialPoints
);
```

## 8.1. Attribute Points Cannot Be Skill Points

```ts
// @ts-expect-error Attribute points are not skill points.

  progression,
  ranks,
  attributePoints,
  skillRequirement
);
```

## 8.2. Skill Points Cannot Be Attribute Points

```ts
// @ts-expect-error Skill points are not attribute points.

  skillPoints,
  attributes,
  allocation
);
```

## 8.3. Reward API Type Isolation

```ts
// @ts-expect-error Wrong reward pool type.
grantAttributePointRewards(
  skillPoints,
  levelResult,
  attributeRewardPolicy
);

// @ts-expect-error Wrong reward pool type.
grantSkillPointRewards(
  attributePoints,
  levelResult,
  skillRewardPolicy
);
```

Ngoài ra:

- `evaluateSkillUpgrade()` không nhận Attribute Point State.
- Assignment giữa hai Point State interfaces phải compile FAIL.
- Missing `pointKind` trên trực tiếp constructed Point State phải compile FAIL.
- Returned Point States có chính xác discriminant literal.
- Existing valid public APIs tiếp tục strict NodeNext PASS.

Đặt `@ts-expect-error` chính xác trên dòng TypeScript báo lỗi để tránh false-positive unused directives.

Không dùng `any` để bypass test.

Không sửa TypeScript config để làm test PASS.
