## B. Implementation

- GF01: `GameplayModuleDefinition` plus `validateModuleDefinition(unknown)`.
  Same lowercase kebab-case identity convention as Harness; boolean optional,
  valid unique dependency IDs, no self-dependency. Returns a detached frozen
  canonical definition. Invalid definitions throw diagnostic `TypeError`.
- GF02: `createModuleRegistry`, `registerModule`, `getModule`, `listModules`.
  Frozen explicit `ModuleRegistry` snapshots; registration returns new state,
  duplicate IDs rejected without overwrite, lookup returns undefined if absent,
  listing preserves registration order. No global state or mutable map exported.
- GF03: `configureModules`, `isModuleEnabled`; `ModuleSelection` and
  `ModuleConfiguration`. Required modules default on; optional modules default
  off. Unknown/conflicting/duplicate IDs, malformed lists and required disable
  throw `TypeError`. Selection order follows registration order. Inputs are not
  retained; configurations remain isolated from each other and later registries.
- Public state types expose only readonly data snapshots (definitions and enabled
  IDs). Runtime arrays, definitions and snapshot objects are frozen. Private
  validation helpers do not appear in installed declarations/root exports.
- Owner: `src/foundation/modules/index.ts`; root exports only seven functions and
  four public types. Architecture registry remains empty and unchanged. No graph
  ordering, missing-dependency validation, auto-enablement or execution added.
