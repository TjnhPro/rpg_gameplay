## 9. Selection policy ownership

L3 supplies explicit retention and preferredTargetIds. No default policy, score,
relation inference or nearest-target calculation. Assessment integrity is checked
without repeating AI09 filtering; eligible facts already encode caller policy.
L4 owns observation authenticity/freshness and commit-time revalidation.

## 10. Retention modes

retain_if_eligible keeps an eligible current target despite higher preferences.
prefer_priority applies ranking every call; the same best ID yields retained.
Both modes fall back to normal acquisition when the old target is ineligible.
Both fields required; unknown retention and duplicate preferred IDs throw.

## 11. Preferred ordering

First preferred ID belonging to eligible wins. Unknown/excluded preferred IDs
are ignored, never synthesized as candidates. Exact case/whitespace preserved.
Empty priority is valid. Caller policy changes affect the next call, without cache.

## 12. Lexical fallback

No eligible preferred ID: choose minimum ID by JavaScript string comparison
(locale-independent UTF-16 order). Literal C,A,B→A and é,a,Z→Z demonstrate the
rule. Reordered assessment candidates keep the same choice. No localeCompare.

## 13. Acquisition

No old target plus a selected ID gives selected/acquired and lossReason:null.
Empty/all-excluded assessment gives no_target/no_candidates, null target.
Selected IDs always come from assessment.eligible.

## 14. Retention

Eligible old B remains B under retain_if_eligible even with A/C preferences.
prefer_priority retains B when B ranks first. State is detached/frozen even when
the target is unchanged; caller state is never committed or frozen by evaluation.

## 15. Switching

Eligible B→preferred A gives selected/switched with lossReason:null.
Lost old target→replacement C also gives switched, carrying the old target loss
reason. No unnecessary switching when selected ID already equals current ID.

## 16. Loss classification

Ineligible current ID uses its canonical assessment exclusion reason, including
entity_not_found, self_not_allowed, target_life_not_allowed, relation_not_allowed,
target_not_visible, target_out_of_range and target_not_reachable. Missing from
both lists gives not_perceived. Every reason tested with/without replacement,
under both retention modes. No replacement gives no_target/target_lost and null
target in the candidate, preserving original state. Eligible/no old target has
lossReason:null. Dead targets follow explicit AI09 policy, not a new default.

## 17. Manual control

Valid manual state returns blocked/manual_control, state:null, selected target
null, lossReason:null, preserving previous target. No AI candidate for manual
actors. Malformed assessment/policy still throws; manual is not a validation bypass.

## 18. Immutable candidate

All result objects and state snapshots are frozen and detached. Only
targetEntityId changes. Actor/profile/controller/behavior identity is preserved.
Caller facts, arrays, policy or AI state mutations after return cannot alter output.
L4 alone decides whether and when to commit the candidate.
