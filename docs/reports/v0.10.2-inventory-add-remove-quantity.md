## Implementation / ownership

Exactly three runtime exports: addInventoryEntry, removeInventoryEntry,
adjustInventoryQuantity. Two types: InventoryOperationAdmission and
InventoryMutationReason (seven task-approved reasons). Return the existing generic
InventoryTransitionResult; no second outcome engine or public policy validator.
Existing Inventory Foundation and Queries/Capacity source remains unchanged.

All operations validate the original complete state/context first. Incoming entry
quantity must be positive/safe; binding and complete Item data go through the actual
public validateItemDefinition/validateItemInstance APIs, with validateItemStackPolicy
for Item policy. Incoming binding lookup reads an own data descriptor, never a getter;
Inventory does not define a second Item schema. Entry structure is validated before
its proposed quantity is classified against stackability/cap. Closed admission and
capacity/ID/delta errors throw TypeError even when eligible is false.

After structural validation: ineligible first; add then checks duplicate, entry-count
capacity, nonstackability and cap. Remove/adjust check missing membership. Well-formed
policy denials return frozen rejected outcomes with candidate:null. Final accepted
states pass canonical validation and are detached/deeply frozen; result wrappers
are frozen. Add appends without auto-stacking, remove preserves remaining order,
ordinary quantity updates preserve order/Item identity and properties. Zero removes
membership; it never creates a zero-quantity entry or deletes Item existence globally.

Delta is a nonzero safe integer. Compare underflow against -current and overflow
against MAX_SAFE_INTEGER-current before adding. A safe-integer ceiling violation
returns stack_limit_exceeded using the approved reason union. Capacity limits apply
to membership adds, not quantity changes. No Kernel numerical calculator is replaced;
this is integer collection bookkeeping. L3 supplies policy/admission; L4 retains
entitlement, IDs, global uniqueness and authoritative commits. No merge/split/transfer,
Loot/Reward, storage, UI or other module implementation.
