## B. Implementation

PG07 retains PG02 level/EXP/entityId as the only state. Shared positiveLevel is
extracted from the existing validator without changing accepted input semantics;
max/target/toLevel reuse it. Explicit max/target are positive safe integers with
current <= target <= max. No stored mode/cap and no level-down.

PG08 validates closed own-data mode/max/target/list and all requirement entries
before projection. The array is dense, exact-length, descriptor-read without
getters/extras and contiguous current+1 through target. Finite nonnegative EXP
requirements accept fractions/zero; eligibility must be boolean. Cumulative
thresholds are nondecreasing; local costs need not increase. No callbacks/DSL.

PG09 uses one private resolveLevelAdvancement for both APIs, once per call. Each
step checks eligibility then EXP, records success and stops at the first blocker.
Cumulative preserves recorded EXP; local subtracts only successful explicit costs.
Partial success returns the prefix with the first blocker, never skipped levels
or mutable partial writes. All malformed requests reject before evaluation.

PG10 returns frozen independent state/assessment/list; dry-run equals transition.
Diagnostics cover before/projected level/EXP, target, levels gained, consumed EXP,
advancedLevels and optional blockedAtLevel. Reason none means requested steps
completed, target_reached means initially current=target, max_level takes precedence
when initially at cap. Reaching cap in this call succeeds with none. Native number
semantics apply; consumed EXP is before minus projected, without a decimal engine.

Public root adds evaluateLevelAdvancement, advanceProgressionLevel and the six
approved types (51 functions/60 types total). No private helper or deep export.
