## D. Limitations

Caller must thread updated snapshots; stale snapshots can create alternate
branches. No global exactly-once reward/double-spend guarantee or persistent
transaction. Receipt validation checks structure/consistency, not authenticated
provenance. Caller owns point-to-attribute economics and external restrictions,
joint storage of resulting snapshots and explicit stat recalculation/events.
No Skill Points/Ranks, respec/refund or automatic resource/level/EXP updates.
