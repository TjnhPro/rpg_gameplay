## Exact public delta and implementation

Four additive runtime exports:

```ts
listEquippedEntries(state:EquipmentState, context:EquipmentValidationContext):readonly EquippedEntry[];
getEquippedEntryBySlot(state:EquipmentState, context:EquipmentValidationContext, slotId:string):EquippedEntry|null;
hasEquippedItem(state:EquipmentState, context:EquipmentValidationContext, instanceId:string):boolean;
assessEquipmentAdmission(state:EquipmentState, context:EquipmentValidationContext,
  item:ItemInstanceState, slotIds:readonly string[], admission:EquipmentAdmission):EquipmentAdmissionResult;
```

Two additive types: readonly `EquipmentAdmission {eligible:boolean}` and
`EquipmentAdmissionResult`, the readonly union of `{allowed:true,reason:'none'}` and
`{allowed:false,reason:'already_equipped'|'slot_occupied'|'ineligible'}`.

Foundation source is preserved as the complete unchanged prefix of Equipment's
owner file; all five Foundation types and its two functions remain unchanged.
Queries delegate complete state/context validation to `validateEquipmentState`.
Listing/lookup return its freshly detached/deeply frozen entries; lookup returns the
whole multi-slot entry or null. Membership compares exact Item instance IDs.
Nonblank IDs preserve case/whitespace; no normalization/coercion.

Admission first validates current state/context. It then validates a separate
single-entry snapshot containing the requested Item/slots through the same Foundation
validator. This reuses exact canonical Item definition/binding validation and slot
rules, without copying Item schemas or altering Foundation. The private transient
snapshot is discarded: no candidate, transition or second validator owner is added.
Current/request occupancy is kept separate so a valid occupied slot is an ordinary
denial rather than an invalid snapshot. Complete context is validated on both calls;
this favors simple reuse over optimizing repeated definition capture.

Finally an exact closed own-data `{eligible:boolean}` fact is inspected without
calling getters. All structural checks precede every ordinary denial. Reflection
failures at the new admission boundary are converted to TypeError. No callback,
store, randomness, clock, allowed-slot catalog, game-policy or numerical execution.

| Valid input condition, first match wins | Result |
| --- | --- |
| Incoming instance ID already present | `{allowed:false,reason:'already_equipped'}` |
| Any requested slot occupied | `{allowed:false,reason:'slot_occupied'}` |
| Explicit eligible false | `{allowed:false,reason:'ineligible'}` |
| Otherwise | `{allowed:true,reason:'none'}` |

All outcomes are fresh closed frozen objects. No partial slot reservation, writes,
events, Item changes or authorization; new instances of an existing definition may
use free slots. L3 supplies meaning/eligibility and L4 checks current entitlement,
cross-storage uniqueness, freshness and later authoritative commits.
