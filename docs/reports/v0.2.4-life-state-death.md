### Decisions before implementation

Canonical owner src/modules/entity/index.ts. Append independent entityId/status
snapshots, three functions and five types; reuse fields/identifier/resourceState/
resourceBounds/resourceCurrent and createEntity. Existing 43 functions/44 types,
EC01–EC13, GF01–GF16 bodies, Core/deps/registry remain unchanged.
EC12 result is state/transition; transition is authoritative Kernel diagnostics.
Life-only resolve/revive never calculate, normalize or restore resources.
Validate all inputs before no-op; reject TypeError on malformed/inconsistent data.
Defeat accepts current above max, rejects below min, defeats only alive at min.
Revival requires bounded current; dead at min rejects; already alive is unchanged
for valid bounded input (including min pending explicit defeat). Equal bounds
cannot revive a dead actor. No-op returns detached frozen state/result too.
No hidden authority, replay protection, time/RNG, callbacks or automatic events.
Caller publishes via existing GF12, with GF13 ordering/snapshot/failure boundaries.

Planned files: Entity owner/root; new installed life JS/TS evidence; existing
installed harness inventory; package+lock version only; verify scope text only;
