## B. Implementation

PG04 keeps ProgressionState.experience as the only authoritative recorded EXP
value, read directly. PG05 adds gainExperience(state, amount, policy?) with finite
nonnegative amount, including zero. PG06 adds canonical adjustExperience(state,
{delta, maximumExperience?}); gain validates its boundary and delegates to it.
No redundant getter or separate state/store. Same canonical owner:
src/modules/progression/index.ts. Shared private dataFields/progressionValues
refactor PG03 validation without changing accepted creation inputs/values.
Transitions validate all three state fields, preserve exact nonblank entityId and
positive safe integer level, and never reconstruct an Entity with a fake kind.

Three new readonly public types: ExperienceAdjustment, ExperienceTransition and
ExperienceTransitionResult. Gain policy uses Omit<ExperienceAdjustment, 'delta'>.
Root exports add exactly two functions/three types (49 functions/54 types total).
All private helpers remain absent from declarations and deep exports stay closed.

One addition path applies finite signed delta. Below-zero result floors to0;
above explicit valid maximum caps to it. Maximum is optional finite/nonnegative,
operation-local and cannot be below current EXP, even for zero/negative delta.
Own maximum undefined is invalid; omit the property. Intermediate positive
overflow with a cap returns finite cap; uncapped overflow throws TypeError.
Diagnostics retain before/after/requestedDelta, signed after-before appliedDelta
and limited only for floor/cap clipping. Exact-bound and zero no-ops are not
limited. Native JavaScript precision remains unchanged:1e20+1 gives1e20,
appliedDelta 0, limited false. No separate precision/decimal algorithm is introduced.
All result levels are frozen and detached; old/caller states remain untouched.
