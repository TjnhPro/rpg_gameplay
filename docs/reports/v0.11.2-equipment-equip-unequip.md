## Public delta and semantics

Exactly three root runtime exports, all returning `EquipmentMutationResult`:

```ts
equipEquipmentItem(state:EquipmentState, context:EquipmentValidationContext,
  item:ItemInstanceState, slotIds:readonly string[], admission:EquipmentAdmission);
unequipEquipmentItem(state:EquipmentState, context:EquipmentValidationContext,
  instanceId:string, admission:EquipmentAdmission);
replaceEquipmentItem(state:EquipmentState, context:EquipmentValidationContext,
  replacedInstanceId:string, replacementItem:ItemInstanceState,
  replacementSlotIds:readonly string[], admission:EquipmentAdmission);
```

Two readonly types: `EquipmentMutationReason` (ineligible, already_equipped,
slot_occupied, not_equipped, same_instance) and discriminated `EquipmentMutationResult`:
accepted has reason none/full candidate/released Item or null; rejected has typed
reason and **both candidate/released null**. Every result is closed and frozen.

Full existing state/context, incoming canonical Item/slots and exact own-data
boolean admission are validated before ordinary denials. Invalid data throws
TypeError even for missing targets or eligibility false. Candidate construction
reuses canonical `validateEquipmentState`, never suppresses failure into a denial.
Existing Foundation/Query/Admission code is unchanged. Equip delegates admission
and appends; unequip removes exact membership and all its slots; replacement
excludes only the designated old entry during admission, preserves its position
and returns its complete old canonical Item. Same-instance property refresh is
rejected. No schema duplication, Inventory mutation, ownership authorization,
implicit destination, reservation, store, clock/RNG, stats or effects.

| Operation | First matching valid denial | Accepted result |
| --- | --- | --- |
| Equip | already_equipped → slot_occupied → ineligible | Append, released:null |
| Unequip | not_equipped → ineligible | Remove only target, released:old Item |
| Replace | not_equipped → same_instance → already_equipped → slot_occupied → ineligible | Replace at original index, released:old Item |

L3 supplies complete slot policy/eligibility; L4 checks entitlement, freshness,
cross-storage uniqueness and destination capacity and commits storage changes.
A returned candidate/released pair is local data, not a transaction receipt.
Failures leave inputs untouched; caller controls commit/rollback.
