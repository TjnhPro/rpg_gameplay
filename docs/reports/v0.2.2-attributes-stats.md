## B. Implementation and ownership

Canonical owner remains `src/modules/entity/index.ts`. Original EC01–EC06
function bodies and Foundation source/fixtures remain unchanged.

EC07 EntityAttributeState holds exact entityId and a detached frozen numeric map.
Creation reuses createEntity. Reads and keyed updates also validate/capture
structural states. Keys are caller-defined exact nonblank strings; empty maps,
finite negatives/fractions, constructor and __proto__ work safely. Custom
prototypes/inherited records, symbols, accessors, callable/nonfinite values and
malformed fields reject TypeError. Update requires an existing key, preserves
identity/other values and returns a new state. No numerical calculation or
collection/global membership lookup occurs.

EC08 EntityStatConfiguration composes public Kernel PreparedStatCalculationInput
and NumericalModifier. Caller owns rules/schema/balance; L2 owns validation and
capture. Orders are explicit/unique/dense; complete attribute/base/rule/baseline
maps and stat rules must match; partial stat bases/contributions/transforms may
only name ordered targets; attribute/stat targets cannot collide. Scaling refs,
finite values, bounds/precision, modifier identity/operation/target/enabled and
own-data shapes are checked. No missing required map or schema is invented.
Optional precision uses JS/Kernel integer decimalPlaces0–100; finite min/max
must be ordered. All mutable numeric/rule/modifier/order inputs are detached
before callbacks. Caller-owned objects/functions are never frozen.

Each calculateEntityStats invocation prepares the canonical Kernel resolver,
including empty lists, then calls calculateStats once. L2 performs no numerical
arithmetic, stacking/dedup, scalar calculation, clamping/rounding or output repair.
Kernel attributes/values are copied verbatim into frozen numeric maps. Mutable
diagnostic/contribution aliases are not exposed. Optional transforms are captured
and Kernel invokes them; L2 rejects nonfinite/nonnumeric/Promise returns rather
than coercing data or leaking mutable objects through the numeric snapshot.
Caller throws and canonical Kernel errors propagate.

EC09 is an explicit repeat call with changed inputs. No separate recalculate API,
live binding, cache, dirty state, implicit provider/event or modifier lifecycle.
Attribute state is associated by ID, not synchronized to collection membership;
removal/replacement leaves independent state and snapshots untouched.

Four new root functions: createEntityAttributeState, getEntityBaseAttributes,
setEntityBaseAttribute, calculateEntityStats. Three types: EntityAttributeState,
EntityStatConfiguration, EntityStatSnapshot. Root total38 functions/37 types;
all prior APIs retained, deep exports closed. Package/lock version0.2.2 only.

## D. Limitations and assumptions

Only EC07–EC09: no resources/current HP/MP, death, damage/healing, progression,
automatic recalculation/resource synchronization, modifier activation/lifecycle,
combat formula selection, engine/store, persistence or concrete game/profile.
Text/2D/2.5D gameplay behavior NOT_EVALUATED. macOS CI is not configured.
Kernel2.0.0 determines numerical semantics; training is passed through without L2
arithmetic. Callers supply deterministic synchronous finite-number transforms;
their closure state and ordinary JS Proxy traps remain caller code. No IO/runtime
isolation, performance target, reference-reuse or global membership guarantee.
Validation/capture copies each input per calculation, with no retained resolver.
