## E. Full phase architecture and robustness review

Audit range: original accepted baseline through all Entity milestones and this
EC18 delivery, including all production source, root/declarations, consumers,
registry, lock, governance/docs and phase records listed below.

- Exactly one Entity source owner (495 lines); root adds only approved 20 Entity
  functions/18 types during phase. No Entity facade, global store or second engine.
- Foundation sources, workflow, Core pin and tooling dependencies unchanged from
  baseline. Only package version changes in dependency lock. Entity imports only
  @rpg/core/kernel. Static registry exactly optional entity/dependencies[].
- Kernel alone computes modifiers/stats/normalization/transition/regeneration.
  L2 captures/validates, calls prepareNumericalModifiers/calculateStats,
  normalizeResource, calculateResourceTransition/calculateResourceRegeneration,
  copies authoritative numerical diagnostics and freezes next snapshots. No
  arithmetic repair/fallback, recomputed applied magnitude or duplicate rounding.
- Life reuses resource validators and only compares explicit bounds/status/IDs.
  Cross-domain association is exact entityId; no membership/global identity claim.
- Frozen detached maps/results use safe own-property handling/Object.fromEntries
  and object spread, retaining __proto__/constructor keys as data. No inherited
  map lookup, hidden live collection, mutable result binding or game-state cache.
- Closed own-data validators reject getters/unknown fields before callbacks; no
  input objects are frozen/mutated. Prior targeted contracts cover special keys,
  sparse arrays, non-finite values, accessor rejection and callback return errors.
  Intentional exception: ineligible regeneration inspects eligibility only and
  does not read ignored numeric fields, retaining the accepted Kernel boundary.
- Foundation opaque capability bindings remain private WeakMap associations, not
  reflectable mutators; existing runtime/messaging/execution regressions retained.
- Caller selects IDs, clock/RNG, stat/resource rules, timing, life policy,
  publication and cleanup. No implicit numerical synchronization/life/events,
  time/RNG/default ID access, scheduler, persistent state or renderer dependency.
- No unauthorized gameplay module/dependency or changed architecture; no Core
  modification. Static checks are lexical, supplemented by source review and
  installed behavior evidence, not described as a complete security analyzer.
