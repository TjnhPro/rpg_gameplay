## Implementation and contract rationale

Four root functions: `getInventoryEntry`, `listInventoryEntries`, `hasInventoryItem`,
`assessInventoryCapacity`. Two types: `InventoryCapacityPolicy`,
`InventoryCapacityAssessment`. Signatures match the supplied task.
All query/assessment paths validate complete state/context before answering.
Exact instance IDs are preserved; blank query IDs throw TypeError; no case folding,
trim normalization or Unicode normalization. Entry/list results are fresh detached
frozen snapshots through the canonical validator, not aliases or alternative serializers.

Capacity policy is a closed own-data `{maxEntries}` with a nonnegative safe integer
or explicit null. Additional count must be a nonnegative safe integer. Occupied
counts entries regardless of stack quantity. Finite available is clamped at zero;
fits checks `occupied <= maximum && additional <= maximum - occupied`, avoiding
unsafe addition. Unbounded fits is true for valid additional count even at
MAX_SAFE_INTEGER because no sum is calculated. A changed L3 policy can report
nonfit while leaving the valid historical state intact. Assessment itself is frozen.

Foundation types and create/validate implementation remain unchanged. L3 still owns
capacity/policy; L4 owns authorization, IDs, storage and commits. No weight/layout,
slots, add/remove, policy callbacks, store or other engine is introduced.
