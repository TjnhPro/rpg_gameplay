## Exact additive public signatures

```ts
export interface GameplayStateSchemaSupport {
  readonly moduleId: string;
  readonly stateKind: string;
  readonly supportedSchemaVersions: readonly number[];
}
export interface GameplayStateRestorePolicy {
  readonly supportedFormatVersions: readonly number[];
  readonly schemas: readonly GameplayStateSchemaSupport[];
  readonly requiredRecords: readonly GameplayStateRecordKey[];
}
export type GameplayStateRestorePreparation =
  | {readonly status: 'ready'; readonly reason: 'none'; readonly records: readonly GameplayStateRecord[]}
  | {readonly status: 'rejected';
     readonly reason: 'unsupported_format' | 'unknown_state_kind' | 'unsupported_schema' | 'missing_required';
     readonly records: null};
export function prepareGameplayStateRestore(
  archive: GameplayStateArchive, policy: GameplayStateRestorePolicy,
): GameplayStateRestorePreparation;
```

The function first revalidates/copies the entire archive through the canonical
validator, then captures the entire closed own-data policy with existing safe
field/array/ID/version helpers. All malformed inputs throw TypeError before
compatibility decisions. Support lists are nonempty, unique positive safe integer
versions. Schema pairs and required triples are exact and unique. Required keys
must reference declared schema kinds. Empty schemas/requiredRecords are allowed.
Getters, symbols, hidden properties, sparse/augmented arrays and nonplain objects
are rejected; thrown inspection traps become TypeError.

Well-formed inputs follow separate passes: unsupported format → unknown kind in
archive order → unsupported schema in archive order → missing required key in
required order → ready. Unknown kinds always fail, with no loose/preservation mode.
Every rejection is frozen with records:null, never partial state. Ready hands off
the fully detached frozen records, in original order, with no payload transformation.
