## 9–11. Grouping, source consistency and policy

Key is targetEntityId + effectId + sourceKey with exact case-sensitive opaque
strings. First-appearance group order and canonical instance order are retained.
Special __proto__/constructor identities work without object-key storage.
Views are detached/frozen; stackCount derives from instanceIds.length. No stored
count or maxStacks. Existing same-group source.kind/sourceId collisions throw
TypeError; conflicting incoming origins reject source_identity_conflict, including
entity/system collisions. Different sourceKeys/effects/targets remain independent.

Closed policy: refresh requires exactly maxStacks1; stack accepts a positive safe

## 12–16. Addition, renewal, independent expiration, capacity and persistence

Admission validates all supplied structures, duration arithmetic, context and
policy first. EF09 receipt must be accepted and match the entire ordered current
EffectState plus exactly one incoming instance. It is a structural receipt, not
an authenticated token. Rejection priority is explicit: application_rejected,
stale_application, time_regressed, lifecycle_not_advanced, pending_expiry,
source_identity_conflict, group_policy_conflict, duration_mode_conflict,
persistent_already_present, max_stacks_reached.

EF12 and stack addition share startLifetimeAtTime, extracted without changing
EF12's transition body. No second lifetime append implementation or manufactured
clock. A time-sensitive public boundary reads actual Foundation time once.
Assessment returns no state. Empty groups allow add under either policy.
Stack at/above max rejects without implicit refresh, replacement or partial state.
Stack/1 and refresh/1 differ explicitly.

Refresh retains original instance, source/target/effect ID, startedAtMs and every
other lifetime. Expiry is max(oldExpiry, now+duration); e.g. start1000/expiry6000,
refresh4000+5000 → expiry9000, shorter renewal4000+1000 retains9000.
Nonfinite/nonlater timestamp arithmetic throws TypeError, with no clamp/rounding.
Incoming attempt ID is discarded; no replacement or extra stack. Explicit renewal
targets one ID, preserving independent A5000/B7000/C9000 deadlines except selected
B→10000. EF13 advance6000 removes A only.

Persistent first applications and stack additions retain null expiry. Automatic
refresh with incompatible mode rejects duration_mode_conflict; persistent plus
persistent rejects persistent_already_present. Explicit renewal on persistent
or with persistent duration rejects not_timed. No fake deadline/refreshed event.

Stack validation admits structurally coherent due membership only to report
pending_expiry; mutations never silently expire it. EF11–EF15 keep strict active
validation. Caller advances the last valid canonical snapshot through EF13, then
builds a fresh receipt; manually changing observedAtMs is not advancement.
The installed test proves both old strict validation and this recovery sequence.

## 17–19. Consumption, group removal and deterministic ordering

Consume validates a closed request/exact key/positive-safe count, rejects missing
group or insufficient membership, then removes exactly N instance/lifetime pairs.
No partial consumption. One stack-consumed event reports IDs and remaining count;
it never fabricates an EF14 removal reason or numerical effect.

Whole-group removal coordinates canonical removeEffectLifetime for each selected
ID, with caller-supplied existing reason. It returns one terminal removed event per
instance, no numerical rollback/publication; repeated group removal rejects missing.
Both operations read no clock and use observedAtMs.

Selection sorts earliest expiry, code-unit lexical instance ID ties, persistent
last with lexical ties. Literal fixture selects Z before a at the same5000 deadline,
then A7000, then persistent P. Survivors retain canonical input order. Unrelated
groups and their lifetime metadata remain unchanged.
