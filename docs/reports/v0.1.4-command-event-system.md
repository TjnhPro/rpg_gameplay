## B. Implementation

GF10 routes one valid command type to its selected module owner. Registration
snapshots metadata/callback, rejects duplicates without replacement and never
auto-enables modules. Command/event identities use lowercase kebab-case; envelopes
require a payload field, including explicit undefined. Creation uses canonical
definition validation and checks alignment/preceding dependencies in one pass;
no graph resolution or Runtime creation. Only selected IDs are retained privately.

GF11 distinguishes explicit success/value, rejected/nonempty caller reason,
unhandled/type and failed/type/owner/message. Invalid outcome, throw or async
return is failed. Rejection remains a business decision, not technical failure.
Foundation envelopes and result/diagnostic metadata are detached/frozen; arbitrary
business payload/value references are unknown, caller-owned and never deep-frozen
or mutated by Foundation. Callbacks may deliberately mutate their own objects.

GF12/GF13 subscriptions use opaque context-owned tokens; listeners run in
subscription order, independent of composition dependency order. Publish snapshots
matching active registrations. Subscribe/unsubscribe/owner cleanup during a
callback affects only the next publish. First listener failure stops fan-out,
identifies exact token/module/type, and reports only completed previous deliveries.
No rollback/retry. Promise/thenable and non-void listener output fail; native
rejection is observed without awaiting and arbitrary thenables never execute.

Unsubscribe returns true once, then false; forged/copied/foreign tokens throw.
Owner cleanup removes all event types for that owner, returning the count; repeat
returns zero. It does not remove command handlers or dispose messaging. Same-context
nested dispatch/publish throws; if uncaught it becomes the outer callback failure.
Caught rejection remains observable; other contexts execute independently.
Execution guards release in finally, including malformed input/failure paths.

Seven new public functions:
`createGameplayMessaging`, `registerCommandHandler`, `dispatchCommand`,
`subscribeEvent`, `publishEvent`, `unsubscribeEvent`, `unsubscribeModuleEvents`.
Eleven new public types:
`GameplayMessaging`, `GameplayCommand`, `CommandOutcome`,
`CommandHandlerRegistration`, `CommandFailure`, `CommandResult`, `GameplayEvent`,
`EventSubscription`, `EventSubscriptionRegistration`, `EventFailure`,
`EventPublishResult`. Combined root inventory: 22 functions / 26 types; deep
exports closed. Full signatures and caller-wired cleanup example: `docs/API.md`.

Canonical owner `src/foundation/messaging/index.ts` owns per-context command and
subscription maps, a weak token membership set and execution flag. A private weak
capability association exposes none of those through reflection or declarations;
public contexts/tokens contain only frozen passive branding. There is no global
bus or gameplay store, no Runtime dependency or second engine. Context lifetime
does not imply runtime running; callers explicitly subscribe/cleanup in lifecycle
hooks. Historical inspection is not live authority. No default services, implicit
events, clock/RNG or scheduling.

caller-defined `CALLER_RULE`, absent handler unhandled, thrown `probe failure`
failed with beta/type diagnostic. Invalid outputs never become success.

Independent event trace: A(event-x), B(event-x), C(event-y), D(event-x) -> A,B,D.
Unsubscribe B -> A,D. Cleanup beta removes A/D but preserves C. During a different
publish A removes itself/B and adds D: first A,B,C; next C,D. Failure probe A,B
(B throws `listener probe`) stops C, reports completed=1 and exact B token.
Removing failing B permits A,C on the next explicit publish; no automatic retry.
