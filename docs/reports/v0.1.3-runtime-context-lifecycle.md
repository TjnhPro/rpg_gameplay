## B. Implementation

### GF06 / composition boundary

`createGameplayRuntime` validates the composition shape, snapshots definitions
through the existing canonical `validateModuleDefinition`, and checks exact
IDs/definition alignment, uniqueness and dependencies appearing earlier in the
supplied order. Missing dependencies, cycles and reversed dependency order fail
this single ordered validation pass. It neither re-registers modules nor computes
a new order. Original GF01–GF05 code and APIs are unchanged.

Bindings accept selected own IDs only, four optional callable stages, and no
unknown stage. Tables are detached and frozen at creation; callbacks themselves
remain caller-owned. Creation does not invoke them. Internal composition,
bindings and immutable progress belong to the returned runtime capability.

### GF07 / transition and failure model

| Function | Allowed status | Success | Hook order |
| --- | --- | --- | --- |
| initializeGameplayRuntime | created | initialized | composition order |
| startGameplayRuntime | initialized | running | composition order |
| stopGameplayRuntime | running | stopped | reverse order |
| disposeGameplayRuntime | created, initialized, stopped, failed | disposed | reverse, initialized/not-yet-disposed only |

Dispose while running is rejected; stop first. No restart. Missing hooks complete
their stages without side effects. Created disposal invokes nothing; never
initialized modules retain created/failed status even when runtime cleanup is
complete. Malformed/illegal operations throw TypeError before hooks.

Hooks receive frozen `{moduleId, stage, runtime}` with progress immediately before
that invocation, without implicit services. Hooks must return undefined. Throw,
Promise/thenable or non-void return stops immediately with frozen
`{ok:false, runtime, failure:{moduleId,stage,message}}`. The failed runtime and
per-module completed stages are retained. No later hooks, automatic retry or
rollback. Native Promise rejection is observed without waiting; arbitrary
thenables are not executed. This does not cancel effects caller code started.

Only explicit dispose may continue from failure. It visits initialized modules
whose dispose has not completed. Cleanup failure preserves progress and remains
failed; a subsequent explicit dispose retries outstanding cleanup, skipping
completed hooks. It never retries initialize/start. Latest diagnostic survives
successful cleanup; per-module diagnostics remain available. No recovery engine.

### GF08 / snapshot and execution isolation

Every successful or failed transition returns a distinct frozen runtime snapshot.
Previous inspection remains unchanged. Each snapshot owns a small closure that
claims its execution once before callbacks; stale replay and reentrant execution
reject. No module-global mutable store/WeakMap, singleton or runtime ID generator.
Capability identity checks reject structurally copied/forged runtime objects.
Independent runtimes from one composition have independent guards, bindings,
progress and failures. Deliberate sharing inside caller closures remains the
caller's responsibility; L2 cannot clone resources or undo external effects.

### GF09 / inspection and public inventory

`inspectGameplayRuntime` returns frozen overall status, selected/resolved IDs,
ordered module status/completedStages and failure diagnostics. It exposes no
callbacks or writable progress, invokes nothing and works at all six statuses,
including empty runtime and failed cleanup.

Six new root functions: `createGameplayRuntime`, `initializeGameplayRuntime`,
`startGameplayRuntime`, `stopGameplayRuntime`, `disposeGameplayRuntime`,
`inspectGameplayRuntime`. Ten new public types: `GameplayRuntime`, `RuntimeStatus`,
`LifecycleStage`, `LifecycleFailure`, `ModuleLifecycleSnapshot`,
`GameplayRuntimeSnapshot`, `LifecycleContext`, `ModuleLifecycleBindings`,
`LifecycleBindings`, `LifecycleTransitionResult`. Combined package: fifteen
functions/fifteen types. Runtime is opaque, not a class/method-based engine;
private mutation helpers/data do not appear in public declarations/exports.
