## 8–10. Timing, identity and single canonical owner

Timed duration is finite and >0, fractional milliseconds allowed, no defaults,
rounding, clamping or instant mode. Expiry is start + duration; nonfinite addition
or loss of representation giving expiry <= start throws TypeError. Persistent
configuration has exactly mode and expiry is null; no automatic expiration.

EffectLifecycleState embeds exactly one canonical EffectState and an ordered
array of metadata {effectInstanceId,mode,startedAtMs,expiresAtMs}, plus observedAtMs.
Metadata never duplicates instance objects. Exact array length/order/identity
binding prevents missing, orphaned and duplicated lifetimes. Active starts cannot
be after observation; timed expiry must be strictly after start/observation.
Transitions remove membership and timing together, preserving survivor order.
Transient selection arrays/sets are local to a call, not additional live stores.
L4 retains authoritative current lifecycle after commit; old snapshots are history.

## 11–13. Clock, EF09 binding and stale applications

Factory requires empty EffectState so no historical start times are invented.
Initialize/start/advance each call actual Foundation readExecutionTime exactly
once. Removal has no context argument and uses observedAtMs. Caller clock origin
is arbitrary, nonnegative and finite. No new clock wrapper/provider is introduced.

Start validates the lifecycle, full nested EF09 result/request/candidate, duration,
Foundation context/output and expiry arithmetic before ordinary rejection.
Applied/none must agree with admitted/none, with request equal in all fields to the
last candidate instance. Rejected application must be rejected/null with matching
admission status and exact non-none reason. Malformed consistency throws TypeError.

Accepted candidate must have the same Entity, unchanged ordered prefix by every
instance/source value and exactly one appended unique instance. Reference identity
is irrelevant; detached equivalent clones work. Wrong baseline returns
stale_application, including replaying the already-started application. No merge,
overwrite or partial candidate. Assessments remain caller assertions, not tokens.

After full validation, start priority is time_regressed, lifecycle_not_advanced,
application_rejected, stale_application. Newer time must be explicitly advanced
first. Advance regressed time rejects; malformed context/output throws.
Every rejected operation returns state=null/events=[] and leaves inputs unchanged.

## 14–16. Expiration, delayed advance and persistent retention

Timed expiry <= now removes the instance and its lifetime. At 5999 an effect with
deadline6000 remains; at6000 it expires. Fractional exact boundary0.25 works without
epsilon. Expiration event atMs is actual deadline, not delayed observation.
Advance1000→8000 expires deadlines3000/5000/7000 directly, with no interval loop.
Events sort by expiry ascending, then exact code-unit lexical instance ID; the
literal Z-before-a tie distinguishes this from locale/input-order sorting.
Survivors retain canonical input order, including persistent survivor-z before
survivor-a. Persistent survives advancement to Number.MAX_VALUE. Repeated advance
does not duplicate terminal events; removed/expired IDs cannot be removed again.
D15 documents this function as expiration boundary only, after future tick intent.

## 17–20. Removal, death handling and events

Removal reasons: explicit, dispel, target_defeated, source_removed, session_cleanup.
All reasons are caller supplied and tested for timed and persistent lifetimes.
Only the selected ID and its timing are removed; no source/group cascade.
Unknown/already-terminal ID returns effect_not_found with no event/candidate.

Real canonical Entity defeat makes the source dead externally; advance retains
the target's effects. Real target defeat does not trigger a listener; explicit L4
remove(target_defeated) returns one removed event and preserves the other effect.
HP/mana, attributes, Progression ranks, Skill, Combat and Life snapshots supplied
to external owners remain unchanged by lifecycle calls.

Returned started/expired/removed events contain exact instance/effect/target IDs
and atMs; removed adds reason. Events are detached frozen values, never published.
Each operation returns a complete immutable candidate; L4 alone commits or forwards
events. No global terminal ledger or idempotency store is maintained.

## 21–23. Isolation, replay and numerical boundary

Outputs are recursively frozen/detached, without freezing caller inputs. Mutating
mutable lifecycle/application clones after start cannot change the output. Prior
initial/after-A/after-B/after-removal/final snapshots keep their exact values.
Two independent sessions each assert literal final empty state at6000 and terminal
trace B removed4000, A expired6000. Date.now, performance.now, Math.random and timer
functions are blocked during replay; explicit Foundation clock counts are asserted.

Lifecycle arithmetic is approved timestamp bookkeeping only; it neither calls
cooldown calculation nor calculates damage/healing/stats/resources. No numerical
Core capability, Legacy import/copy, fallback or protected owner edit is needed.
