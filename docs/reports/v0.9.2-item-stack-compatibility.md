## Exact API and ownership delta

Only validateItemStackPolicy and assessItemStackCompatibility are appended to the
existing Item owner and exported from root; types ItemStackPolicy and
ItemStackCompatibilityResult match the task exactly. All ten earlier functions and
eleven earlier types retain unchanged source/declaration prefixes. The full root
runtime inventory remains exact-name checked; Item declarations are exactly twelve
functions/thirteen types. Historical Item consumers change only the exact two new
runtime inventory names, with no behavioral assertion changes. Original historical
scope/hash oracles are preserved, normalizing only approved additive root bytes.

Policy is a closed own-data {stackable:boolean}. Existing fields/inspect helpers
reject symbols/accessors/prototype violations without getter reads, then return a
fresh frozen detached policy. The assessment calls canonical definition validators
for both full definitions and canonical bound-instance validators for both full
instances, then validates policy before returning any compatibility refusal. No
second parser was introduced. Private equality sees only captured canonical data.

Valid operand reason priority is frozen:

1. Same exact instance ID -> same_instance.
2. Different exact definition ID -> different_definition.
3. Different category, rarity, ordered tags or full definition properties -> definition_conflict.
4. stackable:false -> not_stackable.
5. Different full instance properties -> different_properties.
6. Otherwise -> {compatible:true,reason:'none'}.

Every result is fresh, frozen and has exactly compatible/reason. Record comparison
uses equal own key sets independent of insertion order; arrays compare by position;
scalars use Object.is, preserving negative zero. Hostile string keys are inert own
data. No coercion, JSON serialization, hash or game-specific key whitelist.

Literal installed results for distinct A/B with equal definitions/properties are
{compatible:true,reason:'none'} for true policy and
{compatible:false,reason:'not_stackable'} for false. Reusing A/A gives
{compatible:false,reason:'same_instance'}. Malformed operands throw TypeError even
behind same-ID, different-definition and nonstackable refusals.

L2 returns an advisory structural assessment only. L3 supplies stackability;
L4 supplies current complete operands and rechecks freshness, authority and identity
before any future commit. Quantity/capacity/merge/split/storage/ID retirement belong
to future Inventory, and no global uniqueness or ownership proof is implied.
