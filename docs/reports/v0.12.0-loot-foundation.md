## Research and ownership decisions

[Lyra inventory/equipment/pickups](https://dev.epicgames.com/documentation/en-us/unreal-engine/lyra-inventory-and-equipment-in-unreal-engine)
separates held inventory, active equipment and pickup integration. Our inference is to
retain separate canonical owners and leave world pickup orchestration in L4; none of
Lyra's Actors/components/lifetimes are copied.

[Unity Economy custom and instance data](https://docs.unity.com/en-us/economy/custom-data)
distinguishes resource-definition configuration from a player's specific Item instance.
Our inference is that Loot definitions and intents must remain separate from Item instances;
there is no Unity SDK dependency or manager.

[Godot RandomNumberGenerator](https://docs.godotengine.org/en/stable/classes/class_randomnumbergenerator.html)
documents weighted choice and reproducible seed/state sequences. Its randf includes the
upper endpoint, so it cannot be assumed to satisfy the task's future `[0,1)` input contract.
This checkpoint implements no generator or selector. Future sample supply remains caller
owned, with existing Foundation execution ports available outside Loot.

LT-D01–LT-D08 are reflected in the implementation: immutable definition; independent
optional owner; separate noDropWeight; ordered drops array; safe integer weights/total;
fixed quantity; no embedded RNG; intent-only outcome. L1 remains numerical Kernel;
Item owns actual definitions/instances; Inventory stored quantity; Equipment slots;
future Reward entitlement; L3 catalogs/weights; L4 source selection and delivery/commit.

validateLootTableDefinition, validateLootRollResult. Exactly four readonly types:
LootTableEntry, LootTableDefinition, LootDropIntent, LootRollResult. Public fields and
signatures are in [API](../API.md); no helper/alias or deep package export added.
Release audit compared the unchanged baseline inventory plus these exact names against
the root source and installed native ESM namespace: **189 runtime names, 304 type exports**.
These are observed release evidence, not new daily export-count gates.

One canonical owner `src/modules/loot/index.ts`; no imports. One optional `loot -> []`
registration; all ten earlier graph entries unchanged. Table creation delegates to the
table validator. Private descriptor capture checks every record/array before reading values,
rejects accessors/symbols/unsupported prototypes, and wraps inspection failures as TypeError.
Plain Object/null-prototype records and standard dense arrays are supported; outputs use
fresh plain records and recursively frozen arrays/entries, never caller references.

Exact nonblank IDs retain whitespace/case; entryId uniqueness is table-local; repeated
definitionId is legal. Weight/quantity are positive safe integers, noDropWeight nonnegative,
running total safe and final total positive. Empty entries require positive noDropWeight.
Result validation allows empty/multiple/repeated opaque intents and performs no table or
catalog binding. No normalization, selection, Item creation, state store or reward grant.
