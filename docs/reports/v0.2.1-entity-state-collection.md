## B. EC04–EC06 implementation

Canonical owner remains `src/modules/entity/index.ts`. EC04 adds one
EntityCollection structural readonly entities array, empty creation, append,
exact-ID get/has, ordered list and explicit removal. Uniqueness is local to each
collection; same ID with another kind is still duplicate. Unknown valid lookup
returns undefined/false. Unknown removal and malformed IDs throw TypeError.

EC05 freezes collection, membership and entity data. Every successful transition
returns a new version; old versions are intact. Add appends; removal keeps
remaining relative order; remove/readd appends at the end. EC06 full replacement
requires an existing exact ID, preserves its position and accepts caller's new
kind. No upsert, rename, partial merge, implicit event or policy change.

All add/replace and collection boundary entries use canonical createEntity.
Collection inputs must be a closed own entities data property with a dense own
data array; extra keys, holes, accessors, invalid entities and duplicate IDs reject.
Structural inputs are accepted and detached even for get/list, so readonly type
assertions cannot expose mutable caller arrays/entities through returned data.
No brand, backing map, weak identity table, singleton or mutable module record.
The temporary validation Set exists only for one synchronous operation.

Seven new root functions: createEntityCollection, addEntity, getEntity, hasEntity,
listEntities, removeEntity, replaceEntity. One new public type: EntityCollection.
Root total34 functions/34 types; original Foundation26/31 and Entity1/2 retained.
No deep exports. Package/lock checkpoint version0.2.1 only; dependencies unchanged.
Static optional Entity/no-dependency entry is unchanged; no Collection module.
