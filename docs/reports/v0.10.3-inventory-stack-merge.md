## S05 contract discrepancy — decision required

S05 asks two conflicting complete definitions with the same definitionId to reach
Inventory item_incompatible. The protected context admits exactly one definition per ID;
Inventory entries carry no per-entry definition content. Such an input is structurally
invalid before any merge or admission. The task also explicitly requires malformed
context to throw TypeError. Reaching the literal S05 business outcome would require
changing that protected contract or bypassing complete validation.

Reproduced through physically installed @rpg/gameplay@0.10.3:

```js
const left = {definitionId:'d',categoryId:null,tagIds:[],rarityId:null,properties:{quality:1}};
const right = {...left,properties:{quality:2}};
const source = {instanceId:'s',definitionId:'d',properties:{}};
const destination = {instanceId:'t',definitionId:'d',properties:{}};
// assessItemStackCompatibility(left,source,right,destination,{stackable:true})
// => {compatible:false,reason:'definition_conflict'}
const context = {items:[left,right].map(definition =>
  ({definition,stackPolicy:{stackable:true},maxStackQuantity:20}))};
const state = {inventoryId:'bag',owner:null,entries:[
  {item:source,quantity:4},{item:destination,quantity:7}]};
// validateInventoryState(state,context) AND
// mergeInventoryEntries(state,context,'s','t',{eligible:true})
// => TypeError: Duplicate Inventory context definition
```

The final direct regression records exactly these distinct outcomes, also with false
admission. It does not claim to satisfy the unreachable Inventory business outcome.
No protected contract was changed. Recommended resolution: clarify S05 to require Item
conflict evidence plus Inventory structural rejection. Alternative: separately approve
a context/state contract redesign; outside this milestone. Question sent to Developer;
