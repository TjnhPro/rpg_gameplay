## Implementation and boundaries

Added runtime functions: createEncounterActivationPolicy,
createEncounterActivationObservation, evaluateEncounterActivationAdmission,
activateEncounter. Added types: EncounterParticipantActivationFact,
EncounterActivationObservation, EncounterActivationPolicy,
EncounterActivationRejectionReason, EncounterActivationAdmissionResult,
EncounterActivationTransitionResult. Central root runtime inventory139 exact
names. EN01–EN05 signatures/implementation and five-field EncounterState unchanged.
Only the existing import gains canonical Entity Life types (erased at runtime).

Policy requires all five fields, distinct explicit occupied-side requirements,
positive safe count minima, nonempty distinct canonical alive/dead statuses and
strict World boolean. No default sides, kind whitelist, PvE/alive-only setting.
Observation captures closed own-data facts, canonical Life ID/status and strict
boolean; duplicate/mismatched Life IDs fail. Factory cannot roster-check.

Every evaluation/transition first validates structural state/current canonical
collection, complete policy, complete observation, Encounter ID, foreign facts.
Malformed inputs throw TypeError before domain rejection, even at terminal status.
Domain priority is not_prepared → insufficient_participants →
insufficient_occupied_sides → required_side_unoccupied in policy order →
participant_fact_missing → participant_life_not_allowed →
participant_world_not_ready. Each participant stage uses roster order separately.
Seven reasons and exact side/Entity/null diagnostics have literal oracles.

activateEncounter revalidates original inputs, never trusts an admission token.
Rejected results expose state:null; success changes only status to active in a
deeply frozen detached candidate. Caller input remains mutable/unchanged. Two
calls on one prepared input yield equivalent independent candidates; no exactly-once
or commit promise. Active/resolved/closed/cancelled cannot restart.

Canonical ownership is preserved: encounter → entity only; Entity owns Life and
collections, L3 supplies policy, L4 owns actual spawning, Life/World truth and
freshness, CAS/commit, events and execution. No spawn/Join/Combat/Skill/AI/Effect
call, World/turn scheduler, hidden provider, new Core calculation or global store.
No change to Core/pin/registry/dependencies/CI/architecture/other production owners.
