## Implementation and API

SK11 adds readonly SkillResourceCost, SkillResourceCostBounds,
SkillResourceCostRequest, SkillResourceCostStatus,
SkillResourceCostRejectionReason, SkillResourceCostAssessment and
SkillResourceCostApplicationResult. Runtime additions are
evaluateSkillResourceCosts(admission, resources, request) and
applySkillResourceCosts(admission, resources, request).

SK12/SK13 use getEntityResourceCurrent for canonical full-state validation and
presence checks. Each positive cost delegates to transitionEntityResource with
decrease, caller minimum/maximum/currentAboveMaximum and fixed
allowIncreaseFromMinimum:false. Full payment compares canonical applied exactly
to requested amount. No resource subtraction, clamping, rounding or epsilon.
Core above-max140->100 for cost20 preserves applied20 despite delta40.
Entity/Core exceptions propagate without catch/fallback.

SK14 shares one private resolver. All cost/bounds entries validate before any
ordinary rejection: dense own-data arrays; closed records; finite nonnegative
amounts (fractions valid); exact nonblank opaque IDs; unique one-to-one bounds;
finite ordered bounds and explicit policy. Rejected admission/entity mismatch
is TypeError. First ordinary failure follows original cost order. Failure has
state:null/transitions:[]; no provisional state or receipts escape.

Success returns exactly one final EntityResourceState and readonly canonical
EntityResourceTransitionResult['transition'][] diagnostics, avoiding redundant
interim states and an unnecessary new receipt type. Zero cost still requires
resource presence; zero/free never call numerical transition/normalize. Free
requests still undergo canonical full-state validation through a lookup-only
probe. Already validated data is copied including nonenumerable resource keys.
Every returned object/list is frozen/detached; caller data stays unfrozen.
Evaluation exposes only assessment, creates no reservation; application resolves
again against current supplied state.

SK15 adds installed runtime and strict external NodeNext evidence. Root-only
surface now70 functions/110 types (prior68/103 +2/7). No helper/any/deep export;
no Skill identity/admission schema changes. Package/version lock only0.5.2.
