## B. Implementation

GF04 validates configuration before graph processing, requires every nonoptional
module, and rejects unknown/disabled selected dependencies with both IDs. It
scans remaining nodes in registration order after each removal, selecting the
first currently ready node. On a stalled graph an iterative private helper
reports an actual cycle, excluding downstream prefixes. Only selected nodes
participate. No inputs are modified, no dependencies are activated, no state is
cached, and no partial result is exposed on failure.

GF05 calls the canonical GF04 function directly, then maps the returned IDs to
validated frozen registry definitions. Only data is returned; there is no runtime.
The composition object and both arrays are frozen. Safe immutable definition
sharing avoids a redundant copy/validation layer.

Public additions: `resolveModuleDependencies`, `composeModules`, and readonly
`ModuleComposition { moduleIds, definitions }`. The seven existing functions and
four types remain unchanged, making nine functions/five types at the root only.
The canonical owner remains `src/foundation/modules/index.ts`. No Core numerical
operation, ownership change or external dependency was needed.
